You are given an array `prices` where `prices[i]` is the price of a given stock on the `i^th` day.

You want to maximize your profit by choosing a **single day** to buy one stock and choosing a **different day in the future** to sell that stock.

Return _the maximum profit you can achieve from this transaction_. If you cannot achieve any profit, return `0`.

**Example 1:**

```
Input: prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.
Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.
```

**Example 2:**

```
Input: prices = [7,6,4,3,1]
Output: 0
Explanation: In this case, no transactions are done and the max profit = 0.
```

**Constraints:**

- `1 <= prices.length <= 10^5`

- `0 <= prices[i] <= 10^4`

## Java Solution

```java
package array;

public class BestTimeToBuyAndSellStock {
    public int maxProfit(int[] prices) {
        int maxProfit = 0;
        int minPrice = Integer.MAX_VALUE;
        for (int price : prices) {
            if (price < minPrice) {
                minPrice = price;
            } else {
                maxProfit = Math.max(maxProfit, price - minPrice);
            }
        }
        return maxProfit;
    }
}
```

## Explanation

### Problem Analysis

This problem asks for the best profit from exactly one buy and one later sell.

That creates two important rules:
- the buy day must come before the sell day
- if prices never go up after a buy, the answer must be `0`

A brute-force solution would try every buy/sell pair, but that would be too slow for large inputs.

### Approach

The solution makes one pass through the array while keeping track of:
- the cheapest price seen so far
- the best profit seen so far

At each price, the algorithm decides whether this price is:
- a better day to buy, or
- a good day to sell using the lowest earlier price

### Pattern Used

This solution uses a **greedy one-pass scan**.

It is also closely related to the idea behind a sliding window, because we continuously maintain the best buying point seen before the current day, but the main idea here is greedy state tracking rather than a formal expanding/shrinking window.

### Key Insight

For any day used as the selling day, the best possible buy is simply the **minimum price seen before that day**.

So instead of checking all earlier days, we only need one value: `minPrice`.

That lets us compute the best profit ending at the current day in constant time.

### Code Walkthrough

```java
public int maxProfit(int[] prices) {
    int maxProfit = 0;
    int minPrice = Integer.MAX_VALUE;
    for (int price : prices) {
        if (price < minPrice) {
            minPrice = price;
        } else {
            maxProfit = Math.max(maxProfit, price - minPrice);
        }
    }
    return maxProfit;
}
```

How the method works:

1. `maxProfit` starts at `0` because making no transaction is always allowed.
2. `minPrice` starts at `Integer.MAX_VALUE` so the first real price will replace it.
3. For each `price`:
   - if `price < minPrice`, we found a better buying opportunity
   - otherwise, we treat this day as a potential sell day and compute `price - minPrice`
4. `Math.max(maxProfit, price - minPrice)` keeps the best profit seen so far.
5. After the loop, `maxProfit` is the answer.

### Example Walkthrough

For `prices = [7,1,5,3,6,4]`:

| Day | Price | `minPrice` after update | Profit if sold today | `maxProfit` |
|-----|-------|-------------------------|----------------------|--------------|
| 0 | 7 | 7 | — | 0 |
| 1 | 1 | 1 | — | 0 |
| 2 | 5 | 1 | 4 | 4 |
| 3 | 3 | 1 | 2 | 4 |
| 4 | 6 | 1 | 5 | 5 |
| 5 | 4 | 1 | 3 | 5 |

Best result:
- buy at `1`
- sell at `6`
- profit = `5`

### Key Variables Explained

- **`minPrice`**: the lowest price seen so far. It represents the best buying opportunity available before the current day.
- **`maxProfit`**: the highest profit found so far.
- **`price`**: the current day's price while scanning the array.

### Why This Works

The algorithm is correct because every valid transaction has a sell day, and for that sell day the only buy day that matters is the cheapest earlier day.

By updating `minPrice` as we move left to right, we always know the best buy candidate available for the current day.

So when we compute `price - minPrice`, we are computing the best profit for transactions that sell today. Taking the maximum over all days gives the global best answer.

### Trick Used

The trick is that we do **not** store all buy/sell pairs.

We only keep two numbers:
- the best buy seen so far
- the best profit seen so far

That collapses an `O(n^2)` search into a single linear scan.

### Edge Cases Handled

1. **Strictly decreasing prices** like `[7,6,4,3,1]`
   - `minPrice` keeps decreasing
   - no positive profit is ever found
   - answer stays `0`

2. **Single day** like `[5]`
   - there is no future day to sell
   - answer is `0`

3. **Immediate profit** like `[1,5]`
   - `minPrice` becomes `1`
   - next day gives profit `4`

### Complexity Analysis

- **Time Complexity: `O(n)`** — the array is scanned once, and each iteration does constant work.
- **Space Complexity: `O(1)`** — only two tracking variables are used.
