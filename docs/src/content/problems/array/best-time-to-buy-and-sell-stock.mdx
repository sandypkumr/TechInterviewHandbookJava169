You are given an array `prices` where `prices[i]` is the price of a given stock on the `i^th` day.

You want to maximize your profit by choosing a **single day** to buy one stock and choosing a **different day in the future** to sell that stock.

Return _the maximum profit you can achieve from this transaction_. If you cannot achieve any profit, return `0`.

**Example 1:**

```
Input: prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.
Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.
```

**Example 2:**

```
Input: prices = [7,6,4,3,1]
Output: 0
Explanation: In this case, no transactions are done and the max profit = 0.
```

**Constraints:**

- `1 <= prices.length <= 10^5`

- `0 <= prices[i] <= 10^4`

## Java Solution

```java
package array;

public class BestTimeToBuyAndSellStock {
    public int maxProfit(int[] prices) {
        int maxProfit = 0;
        int minPrice = Integer.MAX_VALUE;
        for (int price : prices) {
            if (price < minPrice) {
                minPrice = price;
            } else {
                maxProfit = Math.max(maxProfit, price - minPrice);
            }
        }
        return maxProfit;
    }
}
```

## Explanation

### Problem Analysis
This problem asks for the maximum profit from exactly one buy followed by one later sell. The main constraint is time order: the selling day must come after the buying day.

It is a staple interview problem because it tests whether you can maintain the right running information in one pass instead of comparing all day pairs.

### Approach
The code scans `prices` once while keeping track of the cheapest price seen so far in `minPrice`. At each new price, it asks: if I sold today, how much profit would that produce against the best buy day seen earlier?

This is much better than brute force:
- brute force compares every buy/sell pair in `O(n^2)` time
- this solution keeps only the best earlier buy price and computes the answer in one pass

### Pattern Used
Greedy

### Key Insight
At any day, the best possible sale today must use the smallest price seen on some earlier day, so keeping a running minimum is enough.

### Code Walkthrough
The method begins with:
- `int maxProfit = 0;`
- `int minPrice = Integer.MAX_VALUE;`

`maxProfit` stores the best profit found so far. `minPrice` starts very large so the first real price becomes the initial buying candidate.

The loop `for (int price : prices)` processes each day in order.

Inside the loop:
- if `price < minPrice`, the code updates `minPrice = price`
- otherwise, it computes the profit from selling today after buying at `minPrice`
- `maxProfit = Math.max(maxProfit, price - minPrice)` keeps the best answer seen so far

The `else` branch matters because once `price` is not a new minimum, it can be treated as a potential selling day.

After the loop, `return maxProfit;` gives `0` if no profitable sale ever existed.

### Example Walkthrough
Use Example 1: `prices = [7,1,5,3,6,4]`.

Start:
- `maxProfit = 0`
- `minPrice = Integer.MAX_VALUE`

Read `7`:
- `7 < minPrice`, so `minPrice = 7`

Read `1`:
- `1 < 7`, so `minPrice = 1`

Read `5`:
- not smaller than `minPrice`
- profit today = `5 - 1 = 4`
- `maxProfit = 4`

Read `3`:
- profit today = `3 - 1 = 2`
- `maxProfit` stays `4`

Read `6`:
- profit today = `6 - 1 = 5`
- `maxProfit = 5`

Read `4`:
- profit today = `4 - 1 = 3`
- `maxProfit` stays `5`

The final answer is `5`, which matches buying at `1` and selling at `6`.

### Key Variables Explained
- `maxProfit`: best profit found anywhere in the scan
- `minPrice`: lowest stock price seen before the current day
- `price`: current day's price from the enhanced `for` loop

### Why This Works
The algorithm maintains a simple invariant:
- before processing each `price`, `minPrice` is the cheapest earlier day
- `maxProfit` is the best profit obtainable from all days processed so far

Because every selling day is evaluated against the best possible earlier buy day, no better one-transaction answer can be missed. Taking the maximum across all days therefore gives the global optimum.

### Trick Used
Running minimum tracking with immediate profit calculation on each later day

### Edge Cases Handled
- Strictly decreasing prices, like Example 2: `minPrice` keeps dropping and `maxProfit` correctly stays `0`
- Single-element array: the loop runs once, no sale is possible, and the method returns `0`
- Best buy day appearing early: `minPrice` preserves it until a better buy appears

### Complexity Analysis
- **Time Complexity: `O(n)`** — the enhanced `for` loop visits each element of `prices` exactly once.
- **Space Complexity: `O(1)`** — only `maxProfit`, `minPrice`, and the loop variable are used.
