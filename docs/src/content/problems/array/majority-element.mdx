Given an array `nums` of size `n`, return _the majority element_.

The majority element is the element that appears more than `&lfloor;n / 2&rfloor;` times. You may assume that the majority element always exists in the array.

**Example 1:**

```
Input: nums = [3,2,3]
Output: 3
```

**Example 2:**

```
Input: nums = [2,2,1,1,1,2,2]
Output: 2
```

**Constraints:**

- `n == nums.length`

- `1 <= n <= 5 * 10^4`

- `-10^9 <= nums[i] <= 10^9`

- The input is generated such that a majority element will exist in the array.

**Follow-up:** Could you solve the problem in linear time and in `O(1)` space?

## Java Solution

```java
package array;

public class MajorityElement {
    public int majorityElement(int[] nums) {
        int count = 0;
        int candidate = 0;
        for (int num : nums) {
            if (count == 0) {
                candidate = num;
            }
            count += (num == candidate) ? 1 : -1;
        }
        return candidate;
    }
}
```

## Explanation

### Problem Analysis

The problem guarantees that one value appears more than half the time.

That guarantee is what makes this solution possible. If one number appears more than `n / 2` times, then even if you pair it against all other numbers, it still cannot be fully canceled out.

### Approach

The code uses the Boyer-Moore Voting Algorithm.

It scans the array once while maintaining:
- a current candidate for majority element
- a counter representing how strongly that candidate is currently ahead

Whenever the counter drops to zero, the algorithm chooses the current number as the new candidate.

### Pattern Used

This is a **greedy candidate-cancellation** pattern.

The algorithm greedily keeps one active candidate and cancels its influence against different values as it scans the array.

### Key Insight

If we cancel one occurrence of the majority element with one occurrence of a non-majority element, the true majority element still remains the majority among the remaining elements.

So repeated cancellation never destroys the final answer.

### Code Walkthrough

```java
public int majorityElement(int[] nums) {
    int count = 0;
    int candidate = 0;
    for (int num : nums) {
        if (count == 0) {
            candidate = num;
        }
        count += (num == candidate) ? 1 : -1;
    }
    return candidate;
}
```

How the method works:

1. `count` starts at `0`, meaning there is no active winner yet.
2. `candidate` stores the current value we are treating as the likely majority element.
3. For each `num`:
   - if `count == 0`, we reset the candidate to `num`
   - if `num == candidate`, add `1` to `count`
   - otherwise, subtract `1` from `count`
4. When the scan ends, `candidate` is the majority element.

### Example Walkthrough

For `nums = [2,2,1,1,1,2,2]`:

| Index | Number | Candidate before | Count before | Action | Candidate after | Count after |
|------:|--------|------------------|--------------|--------|-----------------|-------------|
| 0 | 2 | — | 0 | pick new candidate | 2 | 1 |
| 1 | 2 | 2 | 1 | same as candidate | 2 | 2 |
| 2 | 1 | 2 | 2 | different, cancel one vote | 2 | 1 |
| 3 | 1 | 2 | 1 | different, cancel one vote | 2 | 0 |
| 4 | 1 | 2 | 0 | pick new candidate | 1 | 1 |
| 5 | 2 | 1 | 1 | different, cancel one vote | 1 | 0 |
| 6 | 2 | 1 | 0 | pick new candidate | 2 | 1 |

Final answer: `2`

Even though the candidate changes during the scan, the true majority survives every cancellation round.

### Key Variables Explained

- **`candidate`**: the current value being treated as the majority contender.
- **`count`**: the current vote balance for that candidate.
- **`num`**: the current array element being processed.

### Why This Works

Every time the code sees a value different from the current candidate, it cancels out one vote for that candidate.

If the current candidate is not the real majority, those cancellations eventually drive its `count` to zero and remove it from contention.

If a value truly appears more than half the time, it cannot be completely canceled by the remaining values, so it must be the final candidate left standing.

### Trick Used

The trick is to simulate pair cancellation without actually storing pairs or counts for every number.

Instead of a hash map, the algorithm stores only:
- one candidate
- one running balance

That gives the optimal `O(1)` extra space solution required by the follow-up.

### Edge Cases Handled

1. **Single element** like `[5]`
   - `5` immediately becomes the candidate
   - answer is `5`

2. **Majority clustered at the front** like `[3,3,3,1,2]`
   - the candidate quickly builds a positive count
   - answer remains `3`

3. **Majority mixed with many different values** like `[2,1,2,3,2,4,2]`
   - cancellations happen repeatedly
   - the true majority still survives

4. **Negative values** like `[-1,-1,-1,2,3]`
   - comparisons work the same way
   - answer is `-1`

### Complexity Analysis

- **Time Complexity: `O(n)`** — the array is scanned once.
- **Space Complexity: `O(1)`** — only `candidate` and `count` are stored.
