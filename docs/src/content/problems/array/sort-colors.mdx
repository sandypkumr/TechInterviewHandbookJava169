Given an array `nums` with `n` objects colored red, white, or blue, sort them **in-place **so that objects of the same color are adjacent, with the colors in the order red, white, and blue.

We will use the integers `0`, `1`, and `2` to represent the color red, white, and blue, respectively.

You must solve this problem without using the library's sort function.

**Example 1:**

```
Input: nums = [2,0,2,1,1,0]
Output: [0,0,1,1,2,2]
```

**Example 2:**

```
Input: nums = [2,0,1]
Output: [0,1,2]
```

**Constraints:**

- `n == nums.length`

- `1 <= n <= 300`

- `nums[i]` is either `0`, `1`, or `2`.

**Follow up:** Could you come up with a one-pass algorithm using only constant extra space?

## Java Solution

```java
package array;

public class SortColors {
    public void sortColors(int[] nums) {
        int low = 0, mid = 0, high = nums.length - 1;

        while (mid <= high) {
            if (nums[mid] == 0) {
                swap(nums, low, mid);
                low++;
                mid++;
            } else if (nums[mid] == 1) {
                mid++;
            } else {
                swap(nums, mid, high);
                high--;
            }
        }
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
```

## Explanation

### Problem Analysis
This problem asks us to sort an array containing only `0`, `1`, and `2` in-place, without calling a built-in sort. Because the values are limited to three categories, the goal is to exploit that structure rather than perform a general-purpose sort.

It is a standard interview problem because it checks whether you recognize partitioning logic and can manage multiple regions of an array in one pass.

### Approach
Instead of counting first or sorting normally, this solution uses three pointers to maintain boundaries for the three color groups while scanning once through the array.

At any moment:
- positions before `low` are confirmed `0`s,
- positions after `high` are confirmed `2`s,
- positions between `low` and `mid - 1` are confirmed `1`s,
- positions from `mid` to `high` are still unprocessed.

When `nums[mid]` is inspected, the code immediately knows which region it belongs to and swaps only when needed.

### Pattern Used
Three Pointers, also known as the Dutch National Flag pattern.

### Key Insight
Because there are only three possible values, we can partition the array into finished regions and grow those regions in one pass instead of fully sorting arbitrary numbers.

### Code Walkthrough
The method `sortColors(int[] nums)` starts by initializing:
- `int low = 0, mid = 0, high = nums.length - 1;`

These pointers define the current boundaries of the three regions.

The loop `while (mid <= high)` keeps processing the unknown region.

Inside the loop:
- If `nums[mid] == 0`:
  - `swap(nums, low, mid);`
  - `low++;`
  - `mid++;`
  
  A `0` belongs at the front, so it is swapped into the `low` region. Both pointers move because the value brought into `mid` is already safe when `low == mid`, or it came from the known `1` region.

- Else if `nums[mid] == 1`:
  - `mid++;`
  
  A `1` is already in the correct middle region, so no swap is needed.

- Else:
  - `swap(nums, mid, high);`
  - `high--;`
  
  This handles `2`. It belongs at the end, so it is swapped with the `high` position. Notice that `mid` does **not** move here, because the incoming value from the end has not been examined yet.

The helper `swap(int[] nums, int i, int j)` performs a standard swap using `temp`.

### Example Walkthrough
Use Example 1: `nums = [2,0,2,1,1,0]`.

Start: `low = 0`, `mid = 0`, `high = 5`

- `nums[mid] = 2`
  - swap indices `0` and `5`
  - array becomes `[0,0,2,1,1,2]`
  - `high = 4`, `mid` stays `0`
- `nums[mid] = 0`
  - swap indices `0` and `0`
  - array stays `[0,0,2,1,1,2]`
  - `low = 1`, `mid = 1`
- `nums[mid] = 0`
  - swap indices `1` and `1`
  - `low = 2`, `mid = 2`
- `nums[mid] = 2`
  - swap indices `2` and `4`
  - array becomes `[0,0,1,1,2,2]`
  - `high = 3`, `mid` stays `2`
- `nums[mid] = 1`
  - `mid = 3`
- `nums[mid] = 1`
  - `mid = 4`

Now `mid > high`, so the loop stops. Output is `[0,0,1,1,2,2]`.

### Key Variables Explained
- `low`: next position where a `0` should be placed.
- `mid`: current index being inspected.
- `high`: next position where a `2` should be placed.
- `swap(...)`: helper used to move values into the correct region.
- `temp`: temporary variable inside `swap`.

### Why This Works
The algorithm maintains a partition invariant throughout execution:
- `[0, low - 1]` contains only `0`s,
- `[low, mid - 1]` contains only `1`s,
- `[mid, high]` is unknown,
- `[high + 1, end]` contains only `2`s.

Each branch shrinks the unknown region while preserving those boundaries. Since the unknown region eventually becomes empty, the entire array is correctly partitioned into sorted order.

### Trick Used
Do not increment `mid` after swapping `nums[mid]` with `nums[high]`, because the new value at `mid` still needs to be classified.

### Edge Cases Handled
- Array of length `1`: the loop runs at most once and exits safely.
- All values already equal: pointer logic still finishes correctly.
- Arrays containing only `0`s and `1`s or only `1`s and `2`s: the unused branch simply never executes.
- Values swapped with themselves, such as `swap(nums, low, mid)` when `low == mid`, remain safe.

### Complexity Analysis
- **Time Complexity: `O(n)`** — `mid` moves across the array once, and `high` only moves left, so each element is processed a constant number of times.
- **Space Complexity: `O(1)`** — sorting is done in place using only `low`, `mid`, `high`, and the `temp` variable in `swap`.
