Given an integer array `nums`, move all `0`'s to the end of it while maintaining the relative order of the non-zero elements.

**Note** that you must do this in-place without making a copy of the array.

**Example 1:**

```
Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]
```
**Example 2:**

```
Input: nums = [0]
Output: [0]
```

**Constraints:**

- `1 <= nums.length <= 10^4`

- `-2^31 <= nums[i] <= 2^31 - 1`

**Follow up:** Could you minimize the total number of operations done?

## Java Solution

```java
package array;

public class MoveZeroes {
    public void moveZeroes(int[] nums) {
        int zeroIndex = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != 0) {
                int temp = nums[zeroIndex];
                nums[zeroIndex++] = nums[i];
                nums[i] = temp;
            }
        }
    }
}
```

## Explanation

### Problem Analysis

The task is to move every zero to the end of the array while preserving the relative order of all non-zero values. Because the change must be in-place, the algorithm cannot build a separate output array and copy everything over.

This is a common interview problem because it looks simple, but it tests whether you can maintain stable ordering and minimize unnecessary writes with a pointer-based strategy.

### Approach

The idea is to maintain the next position where a non-zero value should go. As the loop scans from left to right, every non-zero number is swapped into that earliest available position.

Why this works well:

- non-zero values are compacted toward the front in their original order
- zeros naturally get pushed toward the back through the swaps
- the algorithm uses one pass and constant extra space

This is more efficient than repeatedly shifting elements whenever a zero is found.

### Pattern Used

This solution uses the **Two Pointers** pattern with in-place stable compaction.

### Key Insight

If `zeroIndex` always points to the first position that should contain the next non-zero value, then each non-zero element can be placed correctly the moment it is seen.

### Code Walkthrough

The method `moveZeroes(int[] nums)` starts with:

- `int zeroIndex = 0;`

This variable marks where the next non-zero value should be written.

Then the loop

- `for (int i = 0; i < nums.length; i++)`

scans every element exactly once.

Inside the loop, the important condition is:

- `if (nums[i] != 0)`

When the current value is non-zero, the code swaps `nums[i]` with `nums[zeroIndex]`:

- `int temp = nums[zeroIndex];`
- `nums[zeroIndex++] = nums[i];`
- `nums[i] = temp;`

That does two things at once:

- places the current non-zero value into the next correct front position
- leaves a zero behind whenever `zeroIndex` was pointing at an earlier zero

If `i == zeroIndex`, the swap is effectively with itself, which is harmless.

### Example Walkthrough

Using Example 1:

- `nums = [0,1,0,3,12]`

Start:

- `zeroIndex = 0`

Step by step:

- `i = 0`, `nums[0] = 0`
  - condition fails
  - array stays `[0,1,0,3,12]`
  - `zeroIndex = 0`

- `i = 1`, `nums[1] = 1`
  - swap `nums[1]` with `nums[0]`
  - array becomes `[1,0,0,3,12]`
  - `zeroIndex = 1`

- `i = 2`, `nums[2] = 0`
  - condition fails
  - array stays `[1,0,0,3,12]`

- `i = 3`, `nums[3] = 3`
  - swap `nums[3]` with `nums[1]`
  - array becomes `[1,3,0,0,12]`
  - `zeroIndex = 2`

- `i = 4`, `nums[4] = 12`
  - swap `nums[4]` with `nums[2]`
  - array becomes `[1,3,12,0,0]`
  - `zeroIndex = 3`

Final output:

- `[1,3,12,0,0]`

### Key Variables Explained

- `nums`: the array being modified in place
- `zeroIndex`: the leftmost position where the next non-zero element should be placed
- `i`: current scan index through the array
- `temp`: temporary variable used to swap values safely

### Why This Works

Before each iteration, all positions before `zeroIndex` already contain the non-zero elements seen so far in their original order. Everything from `zeroIndex` onward is the unprocessed or partially processed suffix.

When a non-zero value appears at `i`, swapping it into `zeroIndex` extends that correct prefix by one. Because elements are processed left to right, the non-zero values are inserted in the same order they originally appeared, which preserves stability.

### Trick Used

The trick is that the code does not explicitly search for zeros to move; it only places non-zero values forward, and the zeros end up at the back automatically.

### Edge Cases Handled

- All zeros: the `if (nums[i] != 0)` block never runs, so the array remains valid
- No zeros: swaps are all self-swaps as `i` matches `zeroIndex`, so the order is unchanged
- Single-element array like `[0]`: handled naturally by the one-pass loop
- Zeros between non-zero values: handled by swapping each later non-zero into the next front slot

### Complexity Analysis

- **Time Complexity: `O(n)`** because the single `for` loop visits each index once
- **Space Complexity: `O(1)`** because only `zeroIndex`, `i`, and `temp` are used beyond the input array
