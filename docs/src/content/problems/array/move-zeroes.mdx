Given an integer array `nums`, move all `0`'s to the end of it while maintaining the relative order of the non-zero elements.

**Note** that you must do this in-place without making a copy of the array.

**Example 1:**

```
Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]
```
**Example 2:**

```
Input: nums = [0]
Output: [0]
```

**Constraints:**

- `1 <= nums.length <= 10^4`

- `-2^31 <= nums[i] <= 2^31 - 1`

**Follow up:** Could you minimize the total number of operations done?

## Java Solution

```java
package array;

public class MoveZeroes {
    public void moveZeroes(int[] nums) {
        int zeroIndex = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != 0) {
                int temp = nums[zeroIndex];
                nums[zeroIndex++] = nums[i];
                nums[i] = temp;
            }
        }
    }
}
```

## Explanation

### Problem Analysis

The problem requires moving all zeros to the end of the array while maintaining the relative order of non-zero elements, **in-place**.

Key constraints:
- must modify the array in-place (no copy allowed)
- relative order of non-zeros must be preserved
- relative order of zeros does not matter

### Approach

The solution uses a two-pointer technique where:
- one pointer (`zeroIndex`) tracks where the next non-zero element should be placed
- another pointer (`i`) scans through the entire array

When a non-zero element is found, it is swapped with the element at `zeroIndex`, then `zeroIndex` is advanced.

This gradually compresses all non-zeros to the front, automatically leaving zeros at the end.

### Pattern Used

This is a **two-pointer in-place swap** pattern.

One pointer marks a boundary (where zeros should start), and the other scans for elements to move.

### Key Insight

We only move (swap) when we find a non-zero element.

The key observation is that `zeroIndex` always points to either a zero or has just passed the last non-zero. So when we find a non-zero at position `i`, swapping it with `zeroIndex` is guaranteed to make progress toward the final arrangement.

### Code Walkthrough

```java
public void moveZeroes(int[] nums) {
    int zeroIndex = 0;
    for (int i = 0; i < nums.length; i++) {
        if (nums[i] != 0) {
            int temp = nums[zeroIndex];
            nums[zeroIndex++] = nums[i];
            nums[i] = temp;
        }
    }
}
```

How the method works:

1. `zeroIndex` starts at `0`, marking the position where the next non-zero should go.
2. Loop through the array with `i` from `0` to `nums.length - 1`.
3. When `nums[i] != 0` (we found a non-zero element):
   - save `nums[zeroIndex]` in `temp`
   - place `nums[i]` at `nums[zeroIndex]`
   - place `temp` at `nums[i]`
   - increment `zeroIndex` to move the boundary forward
4. If `nums[i] == 0`, skip it (do nothing).
5. After the loop, all non-zeros are in the front, all zeros are in the back.

### Example Walkthrough

For `nums = [0,1,0,3,12]`:

| i | nums[i] | zeroIndex before | Condition | Action | Array after | zeroIndex after |
|---|---------|------------------|-----------|--------|-------------|-----------------|
| 0 | 0 | 0 | == 0 | skip | [0,1,0,3,12] | 0 |
| 1 | 1 | 0 | != 0 | swap nums[0] & nums[1] | [1,0,0,3,12] | 1 |
| 2 | 0 | 1 | == 0 | skip | [1,0,0,3,12] | 1 |
| 3 | 3 | 1 | != 0 | swap nums[1] & nums[3] | [1,3,0,0,12] | 2 |
| 4 | 12 | 2 | != 0 | swap nums[2] & nums[4] | [1,3,12,0,0] | 3 |

Final result: `[1,3,12,0,0]` ✓

Notice that `zeroIndex` only advances when we encounter a non-zero, and the relative order of non-zeros (1, 3, 12) is preserved.

### Key Variables Explained

- **`zeroIndex`**: tracks the position where the next non-zero element should be placed. All positions before `zeroIndex` are already filled with non-zeros (or are about to be).
- **`i`**: the current position being scanned in the array.
- **`temp`**: temporarily holds the value at `zeroIndex` during the swap.

### Why This Works

At any point during the loop, `zeroIndex` represents the boundary: all elements before it (if any) are non-zero, and all elements from `zeroIndex` onward either are zeros or haven't been processed yet.

When we find a non-zero at position `i`, swapping it into `zeroIndex` maintains this invariant and moves the boundary forward. By the end of the loop, all non-zeros have migrated to the front and all zeros are left behind at the back.

### Trick Used

The key trick is recognizing that we do not need to explicitly track or count zeros.

We only need one marker (`zeroIndex`) for where non-zeros should go. By always placing non-zeros at that marker and incrementing it, we implicitly leave zeros behind.

### Edge Cases Handled

1. **All zeros** like `[0,0,0]`
   - `zeroIndex` never increments because no non-zero is found
   - array remains `[0,0,0]` ✓

2. **No zeros** like `[1,2,3]`
   - every element triggers a swap with itself (since `zeroIndex == i` the whole time)
   - array remains `[1,2,3]` ✓

3. **Single element zero** like `[0]`
   - loop runs but never swaps
   - result is `[0]` ✓

4. **Single element non-zero** like `[5]`
   - `i == 0`, `nums[0] = 5 != 0`
   - swap at position 0 (with itself)
   - result is `[5]` ✓

5. **Zeros at the end already** like `[1,2,0,0]`
   - non-zeros swap with themselves initially
   - zeros never move
   - result is `[1,2,0,0]` ✓

### Complexity Analysis

- **Time Complexity: `O(n)`** — the array is scanned once from start to end, and each swap is constant time.
- **Space Complexity: `O(1)`** — only two integer variables (`zeroIndex` and `temp`) are used; no extra data structures.
