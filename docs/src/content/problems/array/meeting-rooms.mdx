The "Meeting Rooms" problem is about determining if a person can attend all their meetings without overlap. Given an
array of intervals where each interval represents a meeting time [start, end], the goal is to check if any of these
intervals overlap. If there’s overlap, return False; otherwise, return True.

For example:


**Input: [[0, 30], [5, 10], [15, 20]]**

**Output: False (since the meetings overlap).**

**Patterns:** `merge-intervals`

## Java Solution

```java
package array;

import java.util.Arrays;
import java.util.Comparator;

/**
 * The "Meeting Rooms" problem is about determining if a person can attend all their meetings without overlap. Given an
 * array of intervals where each interval represents a meeting time [start, end], the goal is to check if any of these
 * intervals overlap. If there’s overlap, return False; otherwise, return True.
 *
 * For example:
 *
 * Input: [[0, 30], [5, 10], [15, 20]]
 * Output: False (since the meetings overlap).
 */
public class MeetingRooms {
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < intervals[i - 1][1]) {
                return false;
            }
        }
        return true;
    }
}
```

## Explanation

### Problem Analysis

The question is whether one person can attend every meeting.

That is only possible when no two meetings overlap in time. So the problem becomes an overlap-detection problem on intervals.

### Approach

The solution first sorts all meetings by start time, then checks neighboring meetings for overlap.

Once meetings are ordered chronologically, each meeting only needs to be compared with the one immediately before it.

### Pattern Used

This uses the **interval sorting / merge-intervals style scan**.

Even though the code does not actually merge intervals, it uses the same core idea: sort intervals first, then make one pass through them.

### Key Insight

After sorting by start time, any overlap must appear between adjacent meetings in the sorted order.

So instead of comparing every pair of meetings, we only check whether:

`currentStart < previousEnd`

If that is true, the person cannot attend both meetings.

### Code Walkthrough

```java
public boolean canAttendMeetings(int[][] intervals) {
    Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] < intervals[i - 1][1]) {
            return false;
        }
    }
    return true;
}
```

How the method works:

1. `Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]))` sorts meetings by start time.
2. The loop starts at index `1` because the first interval has no previous interval to compare with.
3. `intervals[i][0]` is the current meeting's start time.
4. `intervals[i - 1][1]` is the previous meeting's end time.
5. If `intervals[i][0] < intervals[i - 1][1]`, the two meetings overlap, so return `false`.
6. If the loop finishes, no overlap was found, so return `true`.

### Example Walkthrough

For `[[0, 30], [5, 10], [15, 20]]`:

1. Sort by start time → `[[0, 30], [5, 10], [15, 20]]`
2. Compare `[5, 10]` with `[0, 30]`
3. Since `5 < 30`, the meetings overlap
4. Return `false`

For `[[7, 10], [2, 4]]`:

1. Sort by start time → `[[2, 4], [7, 10]]`
2. Compare `[7, 10]` with `[2, 4]`
3. Since `7 < 4` is false, there is no overlap
4. Return `true`

### Key Variables Explained

- **`intervals`**: the input array of meeting ranges, where each meeting is `[start, end]`.
- **`i`**: the current index in the sorted list of meetings.
- **`intervals[i][0]`**: the current meeting's start time.
- **`intervals[i - 1][1]`**: the previous meeting's end time.

### Why This Works

Sorting ensures meetings are processed in chronological order of when they begin.

If a meeting overlaps with any earlier meeting, then after sorting it must conflict with the most recent earlier meeting that comes before it in order. That is why checking adjacent intervals is enough.

So one linear scan after sorting correctly detects whether any overlap exists.

### Trick Used

The trick is reducing the problem to a simple adjacent comparison after sorting.

Without sorting, overlap detection would require comparing many pairs. With sorting, one inequality per neighboring pair is enough.

### Edge Cases Handled

1. **No meetings** like `[]`
   - the loop never runs
   - answer is `true`

2. **One meeting** like `[[5, 10]]`
   - one meeting cannot overlap with anything else
   - answer is `true`

3. **Touching meetings** like `[[1, 2], [2, 3]]`
   - `2 < 2` is false
   - these do not overlap
   - answer is `true`

4. **Overlapping meetings** like `[[1, 5], [4, 6]]`
   - `4 < 5` is true
   - answer is `false`

### Complexity Analysis

- **Time Complexity: `O(n log n)`** — sorting dominates the runtime, and the final scan is linear.
- **Space Complexity: `O(1)`** — aside from the sort's internal behavior, the algorithm itself uses only a few variables.
