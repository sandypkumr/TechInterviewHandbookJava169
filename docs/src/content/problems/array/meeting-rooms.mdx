The "Meeting Rooms" problem is about determining if a person can attend all their meetings without overlap. Given an
array of intervals where each interval represents a meeting time [start, end], the goal is to check if any of these
intervals overlap. If there’s overlap, return False; otherwise, return True.

For example:


**Input: [[0, 30], [5, 10], [15, 20]]**

**Output: False (since the meetings overlap).**

**Patterns:** `merge-intervals`

## Java Solution

```java
package array;

import java.util.Arrays;
import java.util.Comparator;

/**
 * The "Meeting Rooms" problem is about determining if a person can attend all their meetings without overlap. Given an
 * array of intervals where each interval represents a meeting time [start, end], the goal is to check if any of these
 * intervals overlap. If there’s overlap, return False; otherwise, return True.
 *
 * For example:
 *
 * Input: [[0, 30], [5, 10], [15, 20]]
 * Output: False (since the meetings overlap).
 */
public class MeetingRooms {
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < intervals[i - 1][1]) {
                return false;
            }
        }
        return true;
    }
}
```

## Explanation

### Problem Analysis

The problem asks whether one person can attend every meeting in the given list. That is only possible if no interval starts before the previous scheduled meeting has finished.

This is a standard interview problem because it checks whether you can turn interval overlap detection into a clean sort-and-scan solution instead of doing wasteful pairwise comparisons.

### Approach

The simplest way to detect any conflict is to first sort meetings by start time. Once the meetings are in chronological order, an overlap can only happen between neighboring intervals in that sorted order.

That makes the problem much easier than brute force:

- brute force compares many unnecessary pairs
- sorting lets us scan once and fail immediately when we see a conflict

### Pattern Used

This solution uses the **Greedy** pattern with **interval sorting**.

### Key Insight

After sorting by start time, if any overlap exists anywhere, it must appear as `intervals[i][0] < intervals[i - 1][1]` for some adjacent pair.

### Code Walkthrough

The method `canAttendMeetings(int[][] intervals)` starts by sorting the input:

- `Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]))`

This arranges all meetings by their starting time so the scan can reason locally.

Then the loop

- `for (int i = 1; i < intervals.length; i++)`

checks each meeting against the one immediately before it.

The overlap condition is:

- `if (intervals[i][0] < intervals[i - 1][1])`

If that is true, the current meeting starts before the previous one ends, so attending both is impossible and the method returns `false` immediately.

If the loop finishes without triggering that return, every adjacent pair is compatible, so the method returns `true`.

### Example Walkthrough

The example in the file is:

- `intervals = [[0, 30], [5, 10], [15, 20]]`

After

- `Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]))`

the order stays:

- `[[0, 30], [5, 10], [15, 20]]`

Now the loop begins:

- `i = 1`: compare `intervals[1][0] = 5` with `intervals[0][1] = 30`
- since `5 < 30`, the meetings overlap

The method returns `false` right there, which matches the expected output.

### Key Variables Explained

- `intervals`: the input array, sorted in place by meeting start time
- `i`: scans from the second meeting onward
- `intervals[i][0]`: current meeting's start time
- `intervals[i - 1][1]`: previous meeting's end time after sorting

### Why This Works

Sorting by start time guarantees that for any meeting, the only earlier meeting that can directly create the first visible scheduling conflict is the one right before it in sorted order.

The method maintains the idea that all meetings from index `0` to `i - 1` have already been checked and found non-overlapping. If `intervals[i][0]` is still at least the previous end, then adding meeting `i` keeps that property true. If not, the schedule is impossible.

### Trick Used

The trick is reducing a global overlap question to adjacent comparisons by sorting the intervals once.

### Edge Cases Handled

- Empty input: the `for` loop never runs, so the method returns `true`
- Single meeting: also returns `true` because one meeting cannot conflict with anything
- Meetings that touch, like `[1,2]` and `[2,3]`: treated as non-overlapping because the code only rejects strict `<`
- Unsorted input: handled by the initial `Arrays.sort(...)`

### Complexity Analysis

- **Time Complexity: `O(n log n)`** because `Arrays.sort(...)` dominates, and the follow-up loop is only `O(n)`
- **Space Complexity: `O(log n)`** in Java because sorting an object-comparator-based array can use stack space during sorting, while the algorithm itself uses only constant explicit extra variables
