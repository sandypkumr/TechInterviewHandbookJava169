Given an array of intervals `intervals` where `intervals[i] = [starti, endi]`, return _the minimum number of intervals you need to remove to make the rest of the intervals non-overlapping_.

**Note** that intervals which only touch at a point are **non-overlapping**. For example, `[1, 2]` and `[2, 3]` are non-overlapping.

**Example 1:**

```
Input: intervals = [[1,2],[2,3],[3,4],[1,3]]
Output: 1
Explanation: [1,3] can be removed and the rest of the intervals are non-overlapping.
```

**Example 2:**

```
Input: intervals = [[1,2],[1,2],[1,2]]
Output: 2
Explanation: You need to remove two [1,2] to make the rest of the intervals non-overlapping.
```

**Example 3:**

```
Input: intervals = [[1,2],[2,3]]
Output: 0
Explanation: You don't need to remove any of the intervals since they're already non-overlapping.
```

**Constraints:**

- `1 <= intervals.length <= 10^5`

- `intervals[i].length == 2`

- `-5 * 10^4 <= starti < endi <= 5 * 10^4`

**Patterns:** `merge-intervals`

## Java Solution

```java
package array;

import java.util.Arrays;
import java.util.Comparator;

public class NonOverlappingIntervals {
    public int eraseOverlapIntervals(int[][] intervals) {
        if (intervals == null || intervals.length == 0) {
            return 0;
        }

        // Sort the intervals based on their end times
        Arrays.sort(intervals, Comparator.comparingInt(a -> a[1]));

        int count = 0;
        int end = intervals[0][1];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] < end) {
                count++; // Overlapping interval found
            } else {
                end = intervals[i][1]; // Update the end time
            }
        }

        return count;
    }
}
```

## Explanation

### Approach

**Non-overlapping Intervals** has a greedy property: at every decision point, the locally optimal choice leads to a globally optimal solution. Unlike DP, which considers all sub-problems, a greedy algorithm commits to one choice and never reconsiders.

The challenge with greedy is proving correctness (an exchange argument usually works: show that swapping any two elements in a non-greedy solution to match the greedy order never makes things worse). Once you accept the greedy choice is safe, the algorithm is typically simple and fast.

### Code Walkthrough

The solution is implemented in `eraseOverlapIntervals(int[][] intervals)`:

1. Identify the greedy criterion (sort by end time, sort by cost, always pick the max/min, etc.).
2. Sort or arrange the input according to this criterion.
3. Iterate and make the greedy decision at each step without revisiting previous choices.
4. Update state (current end, running sum, remaining capacity) after each decision.
5. Return the accumulated result.

> **Note:** This solution also uses the **sort intervals by start time, then merge overlapping ones in one pass** technique.

### Complexity Analysis

- **Time Complexity: `O(n log n)`** — dominated by sorting the input (O(n log n)); the subsequent linear scan is O(n).
- **Space Complexity: `O(1)`** — only a fixed number of extra variables are used; no data structures that scale with input.
