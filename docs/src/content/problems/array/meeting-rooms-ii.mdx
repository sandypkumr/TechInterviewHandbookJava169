## Java Solution

```java
package array;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class MeetingRooms2 {
    public int minMeetingRooms(List<Interval> intervals) {
        if (intervals == null || intervals.isEmpty()) {
            return 0;
        }

        List<Integer> startTimes = new ArrayList<>();
        List<Integer> endTimes = new ArrayList<>();

        for (Interval interval : intervals) {
            startTimes.add(interval.start);
            endTimes.add(interval.end);
        }

        Collections.sort(startTimes);
        Collections.sort(endTimes);

        int startPointer = 0;
        int endPointer = 0;
        int roomCount = 0;
        int maxRooms = 0;

        while (startPointer < intervals.size()) {
            if (startTimes.get(startPointer) < endTimes.get(endPointer)) {
                roomCount++;
                startPointer++;
            } else {
                roomCount--;
                endPointer++;
            }
            maxRooms = Math.max(maxRooms, roomCount);
        }

        return maxRooms;
    }
}
```

## Explanation

### Problem Analysis

This problem asks for the minimum number of rooms needed so that every meeting can be scheduled without overlap. In other words, we need the maximum number of meetings happening at the same time.

It is a common interview question because it tests interval reasoning, overlap detection, and the ability to convert a scheduling problem into an efficient sweep over sorted events.

### Approach

Instead of checking every meeting against every other meeting, this solution separates all start times and end times, sorts both lists, and then walks through them with two pointers.

That lets the code simulate the timeline of meetings:

- when the next meeting starts before the earliest current meeting ends, a new room is needed
- otherwise, one meeting has already ended, so that room can be reused

This is chosen over brute force because pairwise overlap checks would do unnecessary repeated work, while the sorted timeline view captures exactly when room usage changes.

### Pattern Used

This solution uses the **Two Pointers** pattern on top of sorted start and end times, which is also a form of **sweep line / interval processing**.

### Key Insight

The minimum number of rooms is exactly the largest number of active meetings at any moment, so tracking how `roomCount` changes while scanning sorted starts and ends gives the answer.

### Code Walkthrough

The method starts with a guard clause:

- `if (intervals == null || intervals.isEmpty())` returns `0` because no meetings means no rooms

Next, it builds two separate lists:

- `startTimes` stores every `interval.start`
- `endTimes` stores every `interval.end`

The `for (Interval interval : intervals)` loop extracts those values from the input intervals.

Then the code sorts both lists:

- `Collections.sort(startTimes)`
- `Collections.sort(endTimes)`

After sorting, the method initializes:

- `startPointer` to scan the next meeting start
- `endPointer` to scan the earliest meeting end
- `roomCount` for the number of rooms currently in use
- `maxRooms` for the best answer seen so far

The main work happens in:

- `while (startPointer < intervals.size())`

Inside that loop:

- if `startTimes.get(startPointer) < endTimes.get(endPointer)`, the next meeting begins before the earliest active one ends, so `roomCount++` and `startPointer++`
- otherwise, a meeting has already ended by the time this start is reached, so `roomCount--` and `endPointer++`

After either branch, `maxRooms = Math.max(maxRooms, roomCount)` records the highest simultaneous room usage seen so far.

Finally, the method returns `maxRooms`.

### Key Variables Explained

- `startTimes`: sorted list of when meetings begin
- `endTimes`: sorted list of when meetings finish
- `startPointer`: index of the next start event to process
- `endPointer`: index of the earliest end event not yet consumed
- `roomCount`: number of rooms currently occupied
- `maxRooms`: maximum value of `roomCount`, which becomes the final answer

### Why This Works

Once starts and ends are sorted independently, every comparison between `startTimes.get(startPointer)` and `endTimes.get(endPointer)` tells us which event happens next on the timeline.

The algorithm maintains this invariant:

- `roomCount` always equals the number of meetings that have started but not yet ended among the processed events

So:

- a start before the next end must increase active meetings by one
- an end at or before the next start means one room can be released first

Because `maxRooms` records the peak value of this invariant, it correctly captures the minimum number of rooms required.

### Trick Used

The key trick is splitting intervals into separately sorted `startTimes` and `endTimes` arrays so the code can count overlaps without explicitly storing active meetings in a heap.

### Edge Cases Handled

- `intervals == null`: returns `0`
- `intervals.isEmpty()`: returns `0`
- Meetings that end exactly when another starts: handled by the `else` branch, because equality does not require a new room
- Fully overlapping chains of meetings: `roomCount` keeps increasing and `maxRooms` captures the peak

### Complexity Analysis

- **Time Complexity: `O(n log n)`** because the method fills two lists in `O(n)`, sorts `startTimes` and `endTimes` in `O(n log n)`, and then advances `startPointer` through the meetings once in `O(n)`
- **Space Complexity: `O(n)`** because `startTimes` and `endTimes` each store `n` values outside the input
