Given an array of integers `nums` and an integer `target`, return _indices of the two numbers such that they add up to `target`_.

You may assume that each input would have **_exactly_ one solution**, and you may not use the _same_ element twice.

You can return the answer in any order.

**Example 1:**

```
Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: Because nums[0] + nums[1] == 9, we return [0, 1].
```

**Example 2:**

```
Input: nums = [3,2,4], target = 6
Output: [1,2]
```

**Example 3:**

```
Input: nums = [3,3], target = 6
Output: [0,1]
```

**Constraints:**

- `2  time complexity?

## Java Solution

```java
package array;

import java.util.HashMap;
import java.util.Map;

public class TwoSum {
    public int[] twoSum(int[] nums, int target) {
        int[] result = new int[2];
        Map<Integer, Integer> numMap = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int diff = target - nums[i];
            if (numMap.containsKey(diff)) {
                result[0] = numMap.get(diff);
                result[1] = i;
                return result;
            }
            numMap.put(nums[i], i);
        }
        return null;
    }
}
```

## Explanation

### Problem Analysis
This problem asks for the indices of two numbers whose values add up to `target`. The important detail is that the answer must use two different positions, and the problem guarantees exactly one valid pair.

It is one of the most common interview warm-up questions because it checks whether you can reduce a nested-loop search to constant-time lookups with a hash map.

### Approach
The brute-force solution checks every pair and costs `O(n^2)`. This implementation scans the array once and remembers previously seen numbers in a map.

For each `nums[i]`, the code computes the needed complement `diff = target - nums[i]`.
- If `diff` is already in `numMap`, the answer has been found.
- Otherwise, the current value and index are stored for later elements.

This works because any valid pair can be detected the moment the second number is reached.

### Pattern Used
Hash Map.

### Key Insight
Instead of searching the rest of the array for a complement, store earlier values in `numMap` so each complement check becomes an `O(1)` lookup.

### Code Walkthrough
Inside `twoSum(int[] nums, int target)`:

- `int[] result = new int[2];` prepares the answer array.
- `Map<Integer, Integer> numMap = new HashMap<>();` stores `value -> index` for numbers already processed.

Then the loop `for (int i = 0; i < nums.length; i++)` examines each number.

For each index:
- `int diff = target - nums[i];` computes the matching value needed.
- `if (numMap.containsKey(diff))` checks whether that complement appeared earlier.
- If it did:
  - `result[0] = numMap.get(diff);`
  - `result[1] = i;`
  - `return result;`

If not found yet:
- `numMap.put(nums[i], i);` records the current number and its index.

If the loop somehow finishes without finding a pair, the method returns `null`. In normal problem constraints, that fallback should never be used because one solution is guaranteed.

### Example Walkthrough
Use Example 1: `nums = [2,7,11,15]`, `target = 9`.

Initial state:
- `numMap = {}`

- `i = 0`, `nums[0] = 2`
  - `diff = 9 - 2 = 7`
  - `7` is not in `numMap`
  - store `2 -> 0`
  - `numMap = {2=0}`

- `i = 1`, `nums[1] = 7`
  - `diff = 9 - 7 = 2`
  - `2` is in `numMap` at index `0`
  - set `result[0] = 0`, `result[1] = 1`
  - return `[0,1]`

That matches the expected output.

For Example 3, `nums = [3,3]`, the first `3` is stored, and the second `3` finds it as the complement, so duplicate values are handled correctly.

### Key Variables Explained
- `result`: array of size `2` that stores the answer indices.
- `numMap`: maps a number already seen to its index.
- `i`: current index in the loop.
- `diff`: complement needed so that `nums[i] + diff == target`.
- `target`: required sum given by the problem.

### Why This Works
Before processing index `i`, `numMap` contains exactly the numbers from earlier positions. If the correct partner for `nums[i]` appears earlier, `numMap.containsKey(diff)` finds it immediately.

Checking the map before inserting `nums[i]` is also important: it prevents the same element from being matched with itself. Because the problem guarantees exactly one solution, returning as soon as the complement is found is correct.

### Trick Used
Check `numMap` before calling `numMap.put(nums[i], i)` so the same array element is never reused.

### Edge Cases Handled
- Duplicate values, such as `[3,3]`: the first index is stored and the second finds it.
- Solution appearing early: the method returns immediately once the pair is found.
- Negative numbers or zero: handled naturally because the complement formula still works.
- No-solution fallback: `return null` covers inputs outside the stated guarantee.

### Complexity Analysis
- **Time Complexity: `O(n)`** — the loop runs once over `nums`, and each map lookup or insertion is `O(1)` amortized.
- **Space Complexity: `O(n)`** — in the worst case, `numMap` stores nearly every element before the answer is found.
