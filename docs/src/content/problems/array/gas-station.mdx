There are `n` gas stations along a circular route, where the amount of gas at the `i^th` station is `gas[i]`.

You have a car with an unlimited gas tank and it costs `cost[i]` of gas to travel from the `i^th` station to its next `(i + 1)^th` station. You begin the journey with an empty tank at one of the gas stations.

Given two integer arrays `gas` and `cost`, return _the starting gas station's index if you can travel around the circuit once in the clockwise direction, otherwise return_ `-1`. If there exists a solution, it is **guaranteed** to be **unique**.

**Example 1:**

```
Input: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
Output: 3
Explanation:
Start at station 3 (index 3) and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 4. Your tank = 4 - 1 + 5 = 8
Travel to station 0. Your tank = 8 - 2 + 1 = 7
Travel to station 1. Your tank = 7 - 3 + 2 = 6
Travel to station 2. Your tank = 6 - 4 + 3 = 5
Travel to station 3. The cost is 5. Your gas is just enough to travel back to station 3.
Therefore, return 3 as the starting index.
```

**Example 2:**

```
Input: gas = [2,3,4], cost = [3,4,3]
Output: -1
Explanation:
You can't start at station 0 or 1, as there is not enough gas to travel to the next station.
Let's start at station 2 and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 0. Your tank = 4 - 3 + 2 = 3
Travel to station 1. Your tank = 3 - 3 + 3 = 3
You cannot travel back to station 2, as it requires 4 unit of gas but you only have 3.
Therefore, you can't travel around the circuit once no matter where you start.
```

**Constraints:**

- `n == gas.length == cost.length`

- `1 <= n <= 10^5`

- `0 <= gas[i], cost[i] <= 10^4`

- The input is generated such that the answer is unique.

## Java Solution

```java
package array;

public class GasStation {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int totalGas = 0;
        int totalCost = 0;
        int currentGas = 0;
        int startStation = 0;

        for (int i = 0; i < gas.length; i++) {
            totalGas += gas[i];
            totalCost += cost[i];
            currentGas += gas[i] - cost[i];

            // If current gas is negative, reset the starting station
            if (currentGas < 0) {
                startStation = i + 1;
                currentGas = 0;
            }
        }

        // If total gas is less than total cost, return -1
        return totalGas < totalCost ? -1 : startStation;
    }
}
```

## Explanation

### Problem Analysis

We need to find a starting station from which the car can complete one full circular trip without the tank ever going negative.

Two facts define the problem:
- the car must survive every leg of the trip in order
- the total gas across all stations must be at least the total travel cost

A brute-force solution would try every starting index and simulate the whole loop each time. This code avoids that by eliminating impossible starts during a single pass.

### Approach

The solution scans the arrays once while maintaining four values:
- `totalGas`: the sum of all gas values
- `totalCost`: the sum of all travel costs
- `currentGas`: the running fuel balance for the current candidate start
- `startStation`: the current candidate starting index

At each station `i`, the code adds the net gain `gas[i] - cost[i]` to `currentGas`.

If `currentGas` becomes negative, then the current candidate cannot reach station `i + 1`. At that point, the code discards that entire segment, sets `startStation = i + 1`, and resets `currentGas` to `0`.

After the loop:
- if `totalGas < totalCost`, no starting point can complete the circuit, so return `-1`
- otherwise, return `startStation`

### Pattern Used

This is a **greedy one-pass traversal**.

The solution mainly relies on direct traversal and greedy elimination of bad starting positions. It does not use sorting, a queue, or any extra data structure.

### Key Insight

If starting from `startStation` causes the running balance to become negative at station `i`, then **none of the stations from `startStation` through `i` can be a valid answer**.

Why?

Because every station inside that failed segment would begin with no more fuel advantage than the original candidate had before reaching the failure point. So if the first candidate already fails by the time it reaches `i + 1`, every station before that point also fails.

That is why the code can safely skip all those stations and jump directly to `i + 1`.

### Code Walkthrough

```java

```

How the method works:

1. `totalGas` and `totalCost` track the full amount of fuel available and required across the whole route.
2. `currentGas` tracks the running balance if we start from the current `startStation`.
3. `currentGas += gas[i] - cost[i]` applies the net fuel effect at station `i`.
4. If `currentGas < 0`, the current candidate start has failed:
   - `startStation = i + 1`
   - `currentGas = 0`
5. After the loop, the ternary return checks whether the entire route is possible at all.
6. If enough total gas exists, the final `startStation` is returned.

### Example Walkthrough

For `gas = [1,2,3,4,5]` and `cost = [3,4,5,1,2]`:

| Index | `gas[i]` | `cost[i]` | Net `gas[i] - cost[i]` | `currentGas` after update | Action | `startStation` |
|------:|----------|-----------|-------------------------|---------------------------|--------|----------------|
| 0 | 1 | 3 | -2 | -2 | negative, reset | 1 |
| 1 | 2 | 4 | -2 | -2 | negative, reset | 2 |
| 2 | 3 | 5 | -2 | -2 | negative, reset | 3 |
| 3 | 4 | 1 | 3 | 3 | continue | 3 |
| 4 | 5 | 2 | 3 | 6 | continue | 3 |

Meanwhile:
- `totalGas = 15`
- `totalCost = 15`

So the trip is possible overall, and the final answer is `3`.

Starting at station `3` works because the surplus from stations `3` and `4` is enough to cover the earlier deficits after the route wraps around.

### Key Variables Explained

- **`totalGas`**: total fuel available across the whole circle.
- **`totalCost`**: total fuel required to drive the whole circle.
- **`currentGas`**: current running tank balance for the active candidate start.
- **`startStation`**: the current candidate answer.
- **`i`**: the station index being processed in the loop.

### Why This Works

The correctness comes from combining a global check with a local greedy rule.

First, if `totalGas < totalCost`, then even the best possible starting point cannot succeed, because the entire circle does not contain enough fuel.

Second, when `currentGas` becomes negative at station `i`, the code proves that the current candidate start and every station before `i + 1` in that segment are impossible. So moving `startStation` to `i + 1` never throws away a valid answer.

By the end of the scan:
- all impossible starting segments have been discarded
- the remaining candidate is the only index that can complete the loop if a solution exists

That matches the problem's guarantee that the valid answer is unique.

### Trick Used

The main trick is separating the problem into two simple checks:
- a **global feasibility test** using `totalGas` and `totalCost`
- a **local greedy reset rule** using `currentGas`

There is no fancy data-structure trick here. The important observation is that one negative running balance eliminates an entire block of starting positions at once.

### Edge Cases Handled

1. **Impossible overall case** like `gas = [2,3,4]`, `cost = [3,4,3]`
   - total gas is less than total cost
   - the method returns `-1`

2. **Several failed starts before the real answer**
   - the code may reset `startStation` multiple times
   - it still lands on the correct final candidate

3. **Exactly enough total gas**
   - `totalGas == totalCost` is still valid
   - the method can return a working start

4. **Single station**
   - if `gas[0] >= cost[0]`, the answer is `0`
   - otherwise, the answer is `-1`

### Complexity Analysis

- **Time Complexity: `O(n)`** — the arrays are scanned once, and each station does constant work.
- **Space Complexity: `O(1)`** — only a fixed number of integer variables are used.
