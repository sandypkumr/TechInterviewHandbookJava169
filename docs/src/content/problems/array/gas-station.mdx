There are `n` gas stations along a circular route, where the amount of gas at the `i^th` station is `gas[i]`.

You have a car with an unlimited gas tank and it costs `cost[i]` of gas to travel from the `i^th` station to its next `(i + 1)^th` station. You begin the journey with an empty tank at one of the gas stations.

Given two integer arrays `gas` and `cost`, return _the starting gas station's index if you can travel around the circuit once in the clockwise direction, otherwise return_ `-1`. If there exists a solution, it is **guaranteed** to be **unique**.

**Example 1:**

```
Input: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
Output: 3
Explanation:
Start at station 3 (index 3) and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 4. Your tank = 4 - 1 + 5 = 8
Travel to station 0. Your tank = 8 - 2 + 1 = 7
Travel to station 1. Your tank = 7 - 3 + 2 = 6
Travel to station 2. Your tank = 6 - 4 + 3 = 5
Travel to station 3. The cost is 5. Your gas is just enough to travel back to station 3.
Therefore, return 3 as the starting index.
```

**Example 2:**

```
Input: gas = [2,3,4], cost = [3,4,3]
Output: -1
Explanation:
You can't start at station 0 or 1, as there is not enough gas to travel to the next station.
Let's start at station 2 and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 0. Your tank = 4 - 3 + 2 = 3
Travel to station 1. Your tank = 3 - 3 + 3 = 3
You cannot travel back to station 2, as it requires 4 unit of gas but you only have 3.
Therefore, you can't travel around the circuit once no matter where you start.
```

**Constraints:**

- `n == gas.length == cost.length`

- `1 <= n <= 10^5`

- `0 <= gas[i], cost[i] <= 10^4`

- The input is generated such that the answer is unique.

## Java Solution

```java
package array;

public class GasStation {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int totalGas = 0;
        int totalCost = 0;
        int currentGas = 0;
        int startStation = 0;

        for (int i = 0; i < gas.length; i++) {
            totalGas += gas[i];
            totalCost += cost[i];
            currentGas += gas[i] - cost[i];

            // If current gas is negative, reset the starting station
            if (currentGas < 0) {
                startStation = i + 1;
                currentGas = 0;
            }
        }

        // If total gas is less than total cost, return -1
        return totalGas < totalCost ? -1 : startStation;
    }
}
```

## Explanation

### Problem Analysis
We need to decide whether there is a station from which a full circular trip is possible, and if so return that starting index. The challenge is that a starting point can fail partway through the route, so we need a rule for discarding bad starts efficiently.

This is a classic greedy interview problem because the brute-force solution checks every station, but the correct linear-time solution depends on proving when an entire prefix of candidates can be eliminated at once.

### Approach
Trying every starting station would take `O(n^2)` in the worst case. Instead, this code makes one pass while tracking both global feasibility and the current candidate start.

The idea is:

- `totalGas` and `totalCost` determine whether any solution exists at all.
- `currentGas` tracks whether the current candidate `startStation` can reach the current index.
- If `currentGas` becomes negative at station `i`, then none of the stations from the current `startStation` through `i` can be valid starts, so the next candidate must be `i + 1`.

### Pattern Used
This solution uses the **Greedy** pattern.

### Key Insight
If starting from `startStation` leaves `currentGas < 0` at index `i`, every station between `startStation` and `i` also fails, so we can skip all of them and jump directly to `i + 1`.

### Code Walkthrough
The method `canCompleteCircuit(int[] gas, int[] cost)` initializes four variables:

- `totalGas` accumulates all gas available on the route.
- `totalCost` accumulates the total cost to travel the whole route.
- `currentGas` tracks the tank balance for the current candidate start.
- `startStation` stores the current candidate answer.

The `for` loop iterates from `0` to `gas.length - 1`.

Inside the loop:

- `totalGas += gas[i]`
- `totalCost += cost[i]`
- `currentGas += gas[i] - cost[i]`

So each station contributes both to the global feasibility check and to the local running balance.

Then the code checks:

- `if (currentGas < 0)`

When that happens, the current candidate cannot reach station `i + 1`.

The code responds by:

- setting `startStation = i + 1`
- resetting `currentGas = 0`

This means the next station becomes the new candidate starting point, and we restart the local balance from there.

After the loop, the final line is:

- `return totalGas < totalCost ? -1 : startStation;`

If the total gas is less than the total cost, completing the circuit is impossible from any start. Otherwise, the greedy candidate `startStation` is returned.

### Example Walkthrough
Use **Example 1**:

- `gas = [1,2,3,4,5]`
- `cost = [3,4,5,1,2]`

Scan step by step:

- `i = 0`: `totalGas = 1`, `totalCost = 3`, `currentGas = -2` -> negative, so set `startStation = 1`, reset `currentGas = 0`.
- `i = 1`: `totalGas = 3`, `totalCost = 7`, `currentGas = -2` -> negative, so set `startStation = 2`, reset `currentGas = 0`.
- `i = 2`: `totalGas = 6`, `totalCost = 12`, `currentGas = -2` -> negative, so set `startStation = 3`, reset `currentGas = 0`.
- `i = 3`: `totalGas = 10`, `totalCost = 13`, `currentGas = 3` -> keep going.
- `i = 4`: `totalGas = 15`, `totalCost = 15`, `currentGas = 6` -> keep going.

Now `totalGas` is not less than `totalCost`, so a solution exists, and the code returns `startStation = 3`.

That matches the expected output.

### Key Variables Explained
- `totalGas`: total fuel available across all stations.
- `totalCost`: total fuel required to complete the circuit.
- `currentGas`: running tank balance from the current candidate start.
- `startStation`: current station being considered as the answer.
- `i`: index of the station currently being processed.

### Why This Works
The global condition `totalGas >= totalCost` is necessary and sufficient for some valid start to exist. The greedy reset rule is also safe: when the balance becomes negative at `i`, the cumulative gas from `startStation` to `i` is insufficient, so any start inside that failed segment would begin with even less leftover gas by the time it reaches `i + 1`.

Because the code discards whole impossible segments at once and only keeps the next viable candidate, the final `startStation` is the unique valid answer whenever a solution exists.

### Trick Used
The trick is combining a global feasibility check (`totalGas` vs `totalCost`) with a local reset rule (`currentGas < 0`) so the answer is found in one pass.

### Edge Cases Handled
- Impossible route: if `totalGas < totalCost`, the method returns `-1`.
- Candidate start fails early: handled by resetting `currentGas` and moving `startStation` to `i + 1`.
- Single valid answer guaranteed by the problem: the code returns the one surviving greedy candidate.

### Complexity Analysis
- **Time Complexity: `O(n)`** — the loop processes each station once, doing only constant-time updates per index.
- **Space Complexity: `O(1)`** — only four integer variables are used regardless of input size.
