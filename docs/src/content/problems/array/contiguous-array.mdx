Given a binary array `nums`, return _the maximum length of a contiguous subarray with an equal number of _`0`_ and _`1`.

**Example 1:**

```
Input: nums = [0,1]
Output: 2
Explanation: [0, 1] is the longest contiguous subarray with an equal number of 0 and 1.
```

**Example 2:**

```
Input: nums = [0,1,0]
Output: 2
Explanation: [0, 1] (or [1, 0]) is a longest contiguous subarray with equal number of 0 and 1.
```

**Example 3:**

```
Input: nums = [0,1,1,1,1,1,0,0,0]
Output: 6
Explanation: [1,1,1,0,0,0] is the longest contiguous subarray with equal number of 0 and 1.
```

**Constraints:**

- `1 <= nums.length <= 10^5`

- `nums[i]` is either `0` or `1`.

## Java Solution

```java
package array;

import java.util.HashMap;

public class ContiguousArray {
    public int findMaxLength(int[] nums) {
        int maxLength = 0;
        int count = 0;
        HashMap<Integer, Integer> map = new HashMap<>();
        map.put(0, -1); // Handle the case when the entire array is valid

        for (int i = 0; i < nums.length; i++) {
            count += (nums[i] == 1) ? 1 : -1; // Increment for 1, decrement for 0

            if (map.containsKey(count)) {
                maxLength = Math.max(maxLength, i - map.get(count));
            } else {
                map.put(count, i);
            }
        }

        return maxLength;
    }
}
```

## Explanation

### Problem Analysis
This problem asks for the longest contiguous subarray where the number of `0`s and `1`s is exactly the same. Because the subarray must be contiguous, we cannot just count totals globally; we need to detect balanced ranges while scanning in order.

This is a classic interview problem because it looks like a counting question at first, but the efficient solution comes from recognizing a prefix-sum relationship and storing the earliest time each balance appears.

### Approach
The brute-force idea is to try every subarray and count zeros and ones inside it, but that takes `O(n^2)` or worse. The code avoids that by turning the problem into a running balance question.

Treat each `1` as `+1` and each `0` as `-1`. If the same running `count` appears at two different indices, the elements between those indices must sum to zero, which means they contain an equal number of `0`s and `1`s.

### Pattern Used
This solution uses the **Prefix Sum + Hash Map** pattern.

### Key Insight
If two prefixes have the same running `count`, the subarray between them is balanced because the net contribution between those indices is zero.

### Code Walkthrough
The method starts by creating `maxLength`, `count`, and `map`.

- `maxLength` stores the best answer found so far.
- `count` is the running balance where `1` adds `1` and `0` subtracts `1`.
- `map` stores the first index where each `count` value appeared.

`map.put(0, -1)` is an important initialization.

- It means a balance of zero exists before the array starts.
- This lets the code correctly count a valid subarray that begins at index `0`.

The `for` loop scans `nums` once.

- If `nums[i] == 1`, the code does `count += 1`.
- Otherwise, it does `count += -1`.

Then the code checks `if (map.containsKey(count))`.

- If this balance was seen before, the subarray from `map.get(count) + 1` to `i` is balanced.
- Its length is `i - map.get(count)`.
- `maxLength` is updated with `Math.max(maxLength, i - map.get(count))`.

If the balance has not been seen before, the code stores it with `map.put(count, i)`.

- Only the first index is saved.
- That is important because the earliest occurrence gives the longest possible subarray for that same balance later.

Finally, the method returns `maxLength`.

### Example Walkthrough
Use **Example 3**: `nums = [0,1,1,1,1,1,0,0,0]`.

Start with:

- `count = 0`
- `maxLength = 0`
- `map = {0: -1}`

Step through the array:

- `i = 0`, value `0` -> `count = -1`. Not in `map`, so store `-1 -> 0`.
- `i = 1`, value `1` -> `count = 0`. Seen before at `-1`, so length is `1 - (-1) = 2`. `maxLength = 2`.
- `i = 2`, value `1` -> `count = 1`. Store `1 -> 2`.
- `i = 3`, value `1` -> `count = 2`. Store `2 -> 3`.
- `i = 4`, value `1` -> `count = 3`. Store `3 -> 4`.
- `i = 5`, value `1` -> `count = 4`. Store `4 -> 5`.
- `i = 6`, value `0` -> `count = 3`. Seen at `4`, length is `6 - 4 = 2`.
- `i = 7`, value `0` -> `count = 2`. Seen at `3`, length is `7 - 3 = 4`.
- `i = 8`, value `0` -> `count = 1`. Seen at `2`, length is `8 - 2 = 6`. `maxLength = 6`.

The longest balanced subarray length is `6`, which matches the output.

### Key Variables Explained
- `maxLength`: longest balanced subarray found so far.
- `count`: running balance of ones versus zeros.
- `map`: maps a balance value to the earliest index where it appeared.
- `i`: current index during the single pass.
- `nums[i]`: current bit that changes the running balance.

### Why This Works
The algorithm maintains an invariant: after processing index `i`, `count` represents the difference between the number of `1`s and `0`s in `nums[0..i]`. When the same `count` appears again, the difference between those two prefixes is zero, so the subarray between them must contain equal numbers of `0`s and `1`s.

Storing the first occurrence of each `count` guarantees that when the same balance appears later, the computed distance is as large as possible.

### Trick Used
Using `map.put(0, -1)` is the key trick. It acts like a virtual prefix before the array begins, so subarrays starting at index `0` are handled without special-case code.

### Edge Cases Handled
- A balanced subarray starting at index `0`: handled by `map.put(0, -1)`.
- Multiple repeated balances: handled by keeping the earliest index in `map` and reusing it for longer lengths.
- Arrays with no balanced subarray beyond length `0`: `maxLength` stays `0` and is returned.

### Complexity Analysis
- **Time Complexity: `O(n)`** — the `for` loop visits each element once, and each `HashMap` lookup or insert is `O(1)` on average.
- **Space Complexity: `O(n)`** — in the worst case, `map` stores a different `count` value for many indices.
