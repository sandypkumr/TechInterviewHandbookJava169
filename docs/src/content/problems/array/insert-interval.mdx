You are given an array of non-overlapping intervals `intervals` where `intervals[i] = [starti, endi]` represent the start and the end of the `i^th` interval and `intervals` is sorted in ascending order by `starti`. You are also given an interval `newInterval = [start, end]` that represents the start and end of another interval.

Insert `newInterval` into `intervals` such that `intervals` is still sorted in ascending order by `starti` and `intervals` still does not have any overlapping intervals (merge overlapping intervals if necessary).

Return `intervals`_ after the insertion_.

**Note** that you don't need to modify `intervals` in-place. You can make a new array and return it.

**Example 1:**

```
Input: intervals = [[1,3],[6,9]], newInterval = [2,5]
Output: [[1,5],[6,9]]
```

**Example 2:**

```
Input: intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
Output: [[1,2],[3,10],[12,16]]
Explanation: Because the new interval [4,8] overlaps with [3,5],[6,7],[8,10].
```

**Constraints:**

- `0 <= intervals.length <= 10^4`

- `intervals[i].length == 2`

- `0 <= starti <= endi <= 10^5`

- `intervals` is sorted by `starti` in **ascending** order.

- `newInterval.length == 2`

- `0 <= start <= end <= 10^5`

**Patterns:** `merge-intervals`

## Java Solution

```java
package array;

public class InsertInterval {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        int n = intervals.length;
        int[][] result = new int[n + 1][2];
        int index = 0;
        int i = 0;
        while (i < n && intervals[i][1] < newInterval[0]) {
            result[index++] = intervals[i++];
        }
        while (i < n && intervals[i][0] <= newInterval[1]) {
            newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
            newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
            i++;
        }
        result[index++] = newInterval;
        while (i < n) {
            result[index++] = intervals[i++];
        }
        int[][] finalResult = new int[index][2];
        System.arraycopy(result, 0, finalResult, 0, index);
        return finalResult;
    }
}
```

## Explanation

### Problem Analysis
We need to insert one new interval into an already sorted list of non-overlapping intervals, then return the updated list while preserving order and non-overlap. The only real complication is that the new interval may overlap with zero, one, or many existing intervals.

This is a standard interview problem because it checks whether you can reason about interval relationships in one pass instead of falling back to sorting everything again.

### Approach
A brute-force approach could append `newInterval`, sort all intervals, and then run a merge pass. That works, but it does unnecessary extra work because the input intervals are already sorted and non-overlapping.

This code uses that structure directly in three phases:

- copy all intervals that end before `newInterval` starts,
- merge every interval that overlaps `newInterval`,
- copy the remaining intervals unchanged.

### Pattern Used
This solution uses the **Merge Intervals** pattern with a single linear scan.

### Key Insight
Because `intervals` is already sorted and non-overlapping, all intervals before the overlap zone, inside the overlap zone, and after the overlap zone appear in three contiguous blocks.

### Code Walkthrough
The method `insert(int[][] intervals, int[] newInterval)` begins with:

- `int n = intervals.length;`
- `int[][] result = new int[n + 1][2];`
- `int index = 0;`
- `int i = 0;`

`result` is created with size `n + 1` because, in the worst case, no merge happens and the answer contains one more interval than the input.

The first `while` loop is:

- `while (i < n && intervals[i][1] < newInterval[0])`

These intervals end before `newInterval` begins, so they cannot overlap. The code copies them directly into `result` with `result[index++] = intervals[i++]`.

The second `while` loop is:

- `while (i < n && intervals[i][0] <= newInterval[1])`

These intervals overlap `newInterval`. Instead of storing each one, the code expands `newInterval` itself:

- `newInterval[0] = Math.min(newInterval[0], intervals[i][0]);`
- `newInterval[1] = Math.max(newInterval[1], intervals[i][1]);`

After all overlapping intervals are absorbed, the merged `newInterval` is added once with:

- `result[index++] = newInterval;`

The final `while (i < n)` copies all remaining intervals, since they start after the merged interval ends.

At the end, `result` may contain unused rows, so the code creates:

- `int[][] finalResult = new int[index][2];`

Then it copies only the filled portion using `System.arraycopy(result, 0, finalResult, 0, index)` and returns `finalResult`.

### Example Walkthrough
Use **Example 2**:

- `intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]`
- `newInterval = [4,8]`

Step through the code:

- First loop: `[1,2]` ends before `4`, so copy it. Now `result = [[1,2], ...]`, `index = 1`, `i = 1`.
- Second loop begins with `[3,5]` because `3 <= 8`. Merge into `newInterval` -> `newInterval = [3,8]`.
- Next `[6,7]` also overlaps because `6 <= 8`. Merge keeps `newInterval = [3,8]`.
- Next `[8,10]` overlaps because `8 <= 8`. Merge updates `newInterval = [3,10]`.
- `[12,16]` no longer overlaps, so exit the merge loop.
- Add merged `newInterval`, so result now has `[[1,2],[3,10]]`.
- Copy the remaining `[12,16]`.

The final answer is `[[1,2],[3,10],[12,16]]`, which matches the example.

### Key Variables Explained
- `n`: number of existing intervals.
- `result`: temporary array that stores copied and merged intervals.
- `index`: next free position in `result`.
- `i`: current position in `intervals`.
- `newInterval`: interval being inserted; it is expanded in place while overlaps are merged.
- `finalResult`: trimmed array containing only the valid rows from `result`.

### Why This Works
Since the input is sorted and already non-overlapping, once an interval ends before `newInterval` starts, it is permanently safe to copy. Similarly, once an interval starts after `newInterval` ends, no later interval can overlap either, because starts are nondecreasing.

That means the only work is to merge the single contiguous block of overlapping intervals into `newInterval`. The code does exactly that and outputs intervals in sorted order.

### Trick Used
The main trick is merging directly into `newInterval` instead of building a separate current interval object.

### Edge Cases Handled
- Empty input: if `n == 0`, both loops are skipped and `newInterval` becomes the only result.
- No overlap at all: `newInterval` is inserted between the copied left and right parts.
- Overlap with multiple intervals: the second `while` loop keeps expanding `newInterval` until the entire overlap block is merged.
- Insertion at the beginning or end: handled naturally by the first and last copy loops.

### Complexity Analysis
- **Time Complexity: `O(n)`** — each interval is processed at most once across the three `while` loops.
- **Space Complexity: `O(n)`** — the code allocates `result` and then `finalResult`, both proportional to the number of intervals.
