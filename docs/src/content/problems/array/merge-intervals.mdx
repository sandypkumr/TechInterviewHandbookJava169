The problem gives us a list of intervals and asks us to combine any intervals that overlap.

The final output must satisfy two conditions:
- the intervals are sorted by start time
- no two intervals in the output overlap

The Java solution solves this by first sorting the intervals and then scanning from left to right, merging only when the current interval touches or overlaps the interval we are already building.

The implementation follows a simple two-step process:
1. Sort all intervals by their starting point.
2. Walk through the sorted list and keep one `currentInterval` as the active merged range.

If the next interval starts before or at the end of `currentInterval`, the two intervals overlap and can be merged by extending the end boundary. If they do not overlap, the current merged interval is finished and added to the result list.

### Pattern Used

This is a **merge intervals** solution that uses **sorting and direct traversal**.

The code does not use a stack, heap, or recursion. It relies on the fact that once the intervals are sorted by start time, the overlap relationship can be decided with a single left-to-right pass.

### Key Insight

After sorting, any interval that can overlap with the current merged interval must appear immediately after it.

That means we only need to compare the next interval with the interval we are currently extending. If the next interval starts at or before `currentInterval[1]`, the merged range should expand. Otherwise, the current merged range is complete and can be stored.

### Code Walkthrough

The method `merge(int[][] intervals)` works as follows:

1. It first checks `if (intervals.length == 0)` and returns an empty `int[][]` when there is nothing to merge.
2. `Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]))` sorts the intervals by start value.
3. `merged` stores the finished non-overlapping intervals.
4. `currentInterval` starts as `intervals[0]`, which becomes the first active merged interval.
5. The `for` loop scans the remaining intervals one by one.
6. If `intervals[i][0] <= currentInterval[1]`, the intervals overlap, so `currentInterval[1]` is extended with `Math.max(currentInterval[1], intervals[i][1])`.
7. Otherwise, the current merged interval is complete, so it is added to `merged`, and `currentInterval` is moved to the new interval.
8. After the loop finishes, the last `currentInterval` is added to `merged` because it has not been written out yet.
9. Finally, `merged.toArray(new int[merged.size()][])` converts the list back into the required 2D array format.

### Example Walkthrough

For `intervals = [[1,3],[2,6],[8,10],[15,18]]`:

1. The intervals are already sorted, so the scan begins with `currentInterval = [1,3]`.
2. `[2,6]` starts before `currentInterval[1] = 3`, so they overlap.
   - `currentInterval[1] = max(3, 6) = 6`
   - `currentInterval` becomes `[1,6]`
3. `[8,10]` starts after `6`, so `[1,6]` is finished and added to `merged`.
   - `currentInterval` becomes `[8,10]`
4. `[15,18]` starts after `10`, so `[8,10]` is also finished and added.
   - `currentInterval` becomes `[15,18]`
5. After the loop, `[15,18]` is added as the last merged interval.

Final output: `[[1,6],[8,10],[15,18]]`.

### Key Variables Explained

- **`intervals`**: the input array of intervals, sorted in place by start value.
- **`merged`**: the list that stores completed non-overlapping intervals.
- **`currentInterval`**: the interval currently being expanded or finalized.
- **`i`**: the loop index used to scan each interval after the first one.

### Why This Works

The solution works because sorting puts every potentially overlapping interval next to the interval it can merge with.

At each step, `currentInterval` represents the full merged range for all intervals seen so far that overlap with it. When the next interval overlaps, extending the end with `Math.max` preserves every value covered by either interval. When the next interval does not overlap, no later interval can merge with the old one anymore, so it is safe to commit it to `merged` and start a new range.

This guarantees that every interval is placed in exactly one output range, and the output remains sorted and non-overlapping.

### Trick Used

There is no hidden trick here.

The key implementation detail is reusing `currentInterval` as the active merged interval and expanding its end in place instead of creating a new interval for every overlap.

### Edge Cases Handled

1. **Empty input** like `[]`
   - the method returns `new int[0][0]` immediately

2. **Touching intervals** like `[[1,4],[4,5]]`
   - the condition `intervals[i][0] <= currentInterval[1]` treats boundary-touching intervals as overlapping, so they merge into `[1,5]`

3. **One interval fully inside another** like `[[1,10],[2,3]]`
   - the inner interval does not change the merged range because `Math.max` keeps the larger end value

4. **Multiple separate groups** like `[[1,2],[3,4],[6,7]]`
   - each gap causes the current merged interval to be written to `merged` before the next group starts

### Complexity Analysis

- **Time Complexity: `O(n log n)`** — sorting dominates the runtime, and the single scan afterward is `O(n)`.
- **Space Complexity: `O(n)`** — the `merged` list stores the final intervals, so the output grows linearly with the input size.
