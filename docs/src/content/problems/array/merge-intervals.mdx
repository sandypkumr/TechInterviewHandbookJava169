Given an array of `intervals` where `intervals[i] = [starti, endi]`, merge all overlapping intervals, and return _an array of the non-overlapping intervals that cover all the intervals in the input_.

**Example 1:**

```
Input: intervals = [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
Explanation: Since intervals [1,3] and [2,6] overlap, merge them into [1,6].
```

**Example 2:**

```
Input: intervals = [[1,4],[4,5]]
Output: [[1,5]]
Explanation: Intervals [1,4] and [4,5] are considered overlapping.
```

**Example 3:**

```
Input: intervals = [[4,7],[1,4]]
Output: [[1,7]]
Explanation: Intervals [1,4] and [4,7] are considered overlapping.
```

**Constraints:**

- `1 <= intervals.length <= 10^4`

- `intervals[i].length == 2`

- `0 <= starti <= endi <= 10^4`

**Patterns:** `merge-intervals`

## Java Solution

```java
package array;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.List;

public class MergeIntervals {
    public int[][] merge(int[][] intervals) {
        if (intervals.length == 0) {
            return new int[0][0];
        }

        // Sort the intervals based on the start time
        Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));

        List<int[]> merged = new ArrayList<>();
        int[] currentInterval = intervals[0];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= currentInterval[1]) {
                // Overlapping intervals, merge them
                currentInterval[1] = Math.max(currentInterval[1], intervals[i][1]);
            } else {
                // No overlap, add the current interval to the list
                merged.add(currentInterval);
                currentInterval = intervals[i];
            }
        }

        // Add the last interval
        merged.add(currentInterval);

        return merged.toArray(new int[merged.size()][]);
    }
}
```

## Explanation

### Problem Analysis

The problem asks us to combine all intervals that overlap and return the smallest set of disjoint intervals covering the same ranges. Two intervals belong together if the next one starts before or exactly when the current merged interval ends.

This is a classic interview topic because it tests whether you recognize that sorting turns a messy global overlap problem into a simple one-pass merge process.

### Approach

The code first sorts intervals by start time. After that, it keeps one active interval in `currentInterval` and decides whether each new interval extends it or starts a brand-new merged block.

This is much better than comparing each interval with every other interval:

- brute force would repeatedly revisit the same overlap relationships
- sorting ensures that once an interval does not overlap with `currentInterval`, it cannot overlap with any earlier merged interval either

### Pattern Used

This solution uses the **Merge Intervals** pattern with a **Greedy** left-to-right scan.

### Key Insight

After sorting by start time, all intervals that should merge will appear consecutively, so maintaining one running merged interval is enough.

### Code Walkthrough

The method starts with:

- `if (intervals.length == 0) { return new int[0][0]; }`

That handles the empty-input case immediately.

Next, it sorts by start time:

- `Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]))`

The result container is:

- `List<int[]> merged = new ArrayList<>();`

Then:

- `int[] currentInterval = intervals[0];`

This means the first interval becomes the active interval we are currently building.

The loop

- `for (int i = 1; i < intervals.length; i++)`

processes every remaining interval.

Inside the loop:

- if `intervals[i][0] <= currentInterval[1]`, the intervals overlap, so the code extends the current merged end with `currentInterval[1] = Math.max(currentInterval[1], intervals[i][1])`
- otherwise, the current merged interval is finished, so `merged.add(currentInterval)` stores it and `currentInterval = intervals[i]` starts a new one

After the loop, the last active interval has not yet been added, so:

- `merged.add(currentInterval);`

Finally, the list is converted back to the required array format with:

- `return merged.toArray(new int[merged.size()][]);`

### Example Walkthrough

Using Example 1:

- `intervals = [[1,3],[2,6],[8,10],[15,18]]`

After sorting, the order is unchanged.

Initialize:

- `currentInterval = [1,3]`
- `merged = []`

Now scan:

- `i = 1`, interval `[2,6]`
  - `2 <= 3`, so merge
  - `currentInterval[1] = Math.max(3, 6) = 6`
  - `currentInterval` becomes `[1,6]`

- `i = 2`, interval `[8,10]`
  - `8 <= 6` is false, so no overlap
  - add `[1,6]` to `merged`
  - set `currentInterval = [8,10]`

- `i = 3`, interval `[15,18]`
  - `15 <= 10` is false
  - add `[8,10]` to `merged`
  - set `currentInterval = [15,18]`

After the loop:

- add the final `currentInterval`, `[15,18]`

Result:

- `[[1,6],[8,10],[15,18]]`

### Key Variables Explained

- `intervals`: input array, sorted in place by start time
- `merged`: stores completed merged intervals
- `currentInterval`: the interval currently being expanded
- `i`: index used to scan the remaining intervals

### Why This Works

Sorting by start time ensures intervals are considered in the only order that matters for merging. At any moment, `currentInterval` represents the merged result of all consecutive intervals processed so far that overlap with it.

If the next interval starts before or at `currentInterval[1]`, they must belong to the same merged block, so extending the end is correct. If it starts after `currentInterval[1]`, there is a gap, so no later interval can reconnect them, which makes it safe to finalize the current interval.

### Trick Used

The trick is reusing `currentInterval` directly from the original `intervals` array and only updating its end instead of creating a fresh interval object for every merge.

### Edge Cases Handled

- Empty input: returns `new int[0][0]`
- Touching intervals like `[1,4]` and `[4,5]`: merged because the check is `<=`
- Input already sorted or unsorted: both work because of the initial sort
- A fully contained interval, like `[2,3]` inside `[1,6]`: handled by `Math.max(...)`, which keeps the larger end

### Complexity Analysis

- **Time Complexity: `O(n log n)`** because sorting with `Arrays.sort(...)` dominates, and the merge loop is linear
- **Space Complexity: `O(n)`** because `merged` may store all intervals in the no-overlap case, excluding the output array conversion which represents the returned result
