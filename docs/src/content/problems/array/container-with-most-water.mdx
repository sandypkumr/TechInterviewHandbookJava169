You are given an integer array `height` of length `n`. There are `n` vertical lines drawn such that the two endpoints of the `i^th` line are `(i, 0)` and `(i, height[i])`.
Find two lines that together with the x-axis form a container, such that the container contains the most water.
Return _the maximum amount of water a container can store_.
**Notice** that you may not slant the container.
**Example 1:**
```
Input: height = [1,8,6,2,5,4,8,3,7]
Output: 49
Explanation: The above vertical lines are represented by array [1,8,6,2,5,4,8,3,7]. In this case, the max area of water (blue section) the container can contain is 49.
```
**Example 2:**
```
Input: height = [1,1]
Output: 1
```
**Constraints:**
- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`
**Patterns:** `two-pointers`
## Java Solution
```java
package array;
public class ContainerWithMostWater {
    public int maxArea(int[] height) {
        int maxArea = 0;
        int left = 0;
        int right = height.length - 1;
        while (left < right) {
            int width = right - left;
            int minHeight = Math.min(height[left], height[right]);
            maxArea = Math.max(maxArea, width * minHeight);
            // Move the pointer pointing to the shorter line
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return maxArea;
    }
}
```
## Explanation
### Problem Analysis
We need to choose two lines that form the largest possible container.
For any pair of indices `i` and `j`, the amount of water stored is:
`(j - i) * min(height[i], height[j])`
So every container is determined by:
- **width**: the distance between the two indices
- **height limit**: the shorter of the two lines
A brute-force solution would test every pair of lines and compute this area each time, but that would take `O(n^2)` time. The Java solution avoids that by shrinking the search space intelligently.
### Approach
The code starts with the widest possible container by placing:
- `left` at the beginning of the array
- `right` at the end of the array
For each pair, it computes the current area and updates `maxArea`.
Then it moves only **one** pointer inward:
- if the left line is shorter, move `left++`
- otherwise, move `right--`
This is the core idea of the solution. Since the shorter line limits the current container, keeping it and moving the taller line inward would only reduce the width without removing the bottleneck.
### Pattern Used
This solution uses the classic **two-pointers from both ends** pattern.
There is no sorting and no formal sliding window here. The solution mainly relies on direct two-pointer elimination based on which side currently limits the area.
### Key Insight
The shorter of the two boundary lines is the only height that matters for the current container.
If `height[left] < height[right]`, then any future container that still uses this same `left` line will have:
- a smaller width
- a height limit no larger than `height[left]`
So none of those containers can beat the current area for this `left` boundary. That means `left` can be safely discarded.
The same reasoning applies symmetrically when the right line is shorter.
### Code Walkthrough
```java
public int maxArea(int[] height) {
    int maxArea = 0;
    int left = 0;
    int right = height.length - 1;
    while (left < right) {
        int width = right - left;
        int minHeight = Math.min(height[left], height[right]);
        maxArea = Math.max(maxArea, width * minHeight);
        if (height[left] < height[right]) {
            left++;
        } else {
            right--;
        }
    }
    return maxArea;
}
```
How the method works:
1. `maxArea` starts at `0` because no container has been evaluated yet.
2. `left = 0` and `right = height.length - 1` create the maximum initial width.
3. On each loop iteration:
   - `width = right - left`
   - `minHeight = Math.min(height[left], height[right])`
   - `width * minHeight` gives the current container area
4. `Math.max(maxArea, width * minHeight)` keeps the best result seen so far.
5. The code then moves the pointer at the shorter line.
6. The loop stops when `left` and `right` meet, because no valid pair remains.
One exact detail from this implementation: when `height[left] == height[right]`, the `else` branch executes, so the code moves `right--`. That is still correct because in a tie either side can be moved safely.
### Example Walkthrough
For `height = [1,8,6,2,5,4,8,3,7]`:
| `left` | `right` | Heights | Width | `minHeight` | Area | `maxArea` | Move |
|-------:|--------:|---------|------:|------------:|-----:|----------:|------|
| 0 | 8 | `1, 7` | 8 | 1 | 8 | 8 | move `left` |
| 1 | 8 | `8, 7` | 7 | 7 | 49 | 49 | move `right` |
| 1 | 7 | `8, 3` | 6 | 3 | 18 | 49 | move `right` |
| 1 | 6 | `8, 8` | 5 | 8 | 40 | 49 | move `right` |
| 1 | 5 | `8, 4` | 4 | 4 | 16 | 49 | move `right` |
| 1 | 4 | `8, 5` | 3 | 5 | 15 | 49 | move `right` |
| 1 | 3 | `8, 2` | 2 | 2 | 4 | 49 | move `right` |
| 1 | 2 | `8, 6` | 1 | 6 | 6 | 49 | move `right` |
The best area is `49`, produced by the lines at indices `1` and `8`.
### Key Variables Explained
- **`left`**: the left boundary of the current container.
- **`right`**: the right boundary of the current container.
- **`width`**: the horizontal distance between `left` and `right`.
- **`minHeight`**: the shorter of the two selected line heights.
- **`maxArea`**: the largest area found so far.
### Why This Works
After evaluating a pair `(left, right)`, the algorithm throws away one boundary that cannot lead to a better answer.
If the left line is shorter, then keeping that same left line while moving the right side inward always reduces width, and the height limit still cannot exceed the left height. So every such future area is bounded by the current one.
That proves the left boundary is no longer useful, so moving `left` is safe. The same argument works when the right side is shorter.
Because each move discards only impossible-to-improve choices, the algorithm never skips the optimal answer. The largest value stored in `maxArea` is therefore the true maximum container area.
### Trick Used
The main trick is the pointer-movement rule:
- **move the shorter line, not the taller one**
That is what converts the naive `O(n^2)` search into a linear-time solution.
There is no extra hidden trick beyond that.
### Edge Cases Handled
1. **Only two lines** like `[1,1]`
   - the loop runs once
   - the method returns `1`
2. **Equal heights at both ends** like `[5,1,5]`
   - the code moves `right` because of the `else` branch
   - this is still correct because either equal side can be discarded
3. **Zero-height lines** like `[0,2,0]`
   - `minHeight` can be `0`
   - the area formula still behaves correctly
4. **Best container not at the ends** like `[1,8,6,2,5,4,8,3,7]`
   - the algorithm still finds it while moving inward
   - it does not assume the widest container is the best one
### Complexity Analysis
- **Time Complexity: `O(n)`** — each iteration moves either `left` or `right`, so the array is processed in one pass.
- **Space Complexity: `O(1)`** — only a few integer variables are used.
