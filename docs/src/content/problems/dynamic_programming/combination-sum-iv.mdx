Given an array of **distinct** integers `nums` and a target integer `target`, return _the number of possible combinations that add up to_ `target`.

The test cases are generated so that the answer can fit in a **32-bit** integer.

**Example 1:**

```
Input: nums = [1,2,3], target = 4
Output: 7
Explanation:
The possible combination ways are:
(1, 1, 1, 1)
(1, 1, 2)
(1, 2, 1)
(1, 3)
(2, 1, 1)
(2, 2)
(3, 1)
Note that different sequences are counted as different combinations.
```

**Example 2:**

```
Input: nums = [9], target = 3
Output: 0
```

**Constraints:**

- `1 <= nums.length <= 200`

- `1 <= nums[i] <= 1000`

- All the elements of `nums` are **unique**.

- `1 <= target <= 1000`

**Follow up:** What if negative numbers are allowed in the given array? How does it change the problem? What limitation we need to add to the question to allow negative numbers?

**Patterns:** `backtracking`, `dynamic-programming`

## Java Solution

```java
package dynamic_programming;

public class CombinationSum4 {
    public int combinationSum4(int[] nums, int target) {
        int[] dp = new int[target + 1];
        dp[0] = 1;

        for (int i = 1; i <= target; i++) {
            for (int num : nums) {
                if (i - num >= 0) {
                    dp[i] += dp[i - num];
                }
            }
        }

        return dp[target];
    }
}
```

## Explanation

### Problem Analysis
This problem asks for the number of ordered sequences from `nums` that sum to `target`. Because order matters, `[1,3]` and `[3,1]` are counted separately.

It is a common interview variation of combination-count DP because candidates must notice that the loop order determines whether they count combinations or ordered sequences.

### Approach
The code computes the number of ways to form every total from `0` up to `target`. For each intermediate sum `i`, it tries every `num` as the last element of the sequence.

This beats brute-force backtracking because recursive exploration would revisit the same remaining targets many times. Bottom-up DP stores each sub-answer once in `dp`.

### Pattern Used
This solution uses **Dynamic Programming**, specifically bottom-up counting DP.

### Key Insight
If a sequence ends with `num`, then the number of ways to reach total `i` through that choice is exactly **`dp[i - num]`**.

### Code Walkthrough
`combinationSum4(int[] nums, int target)` starts by building the DP array:

- `int[] dp = new int[target + 1];`
  - `dp[i]` means the number of ordered sequences that sum to `i`.
- `dp[0] = 1;`
  - There is exactly one way to make total `0`: choose nothing.

Then the method fills the table from small sums to large sums:

- `for (int i = 1; i <= target; i++)`
  - compute the answer for each total `i`
- `for (int num : nums)`
  - try each value as the last number added
- `if (i - num >= 0)`
  - only valid if `num` does not overshoot the current sum
- `dp[i] += dp[i - num];`
  - append `num` to every sequence that already forms `i - num`

Finally:

- `return dp[target];`
  - the last cell contains the number of ordered combinations for the target

### Example Walkthrough
Use **Example 1**:

- `nums = [1,2,3]`
- `target = 4`

Initialization:

- `dp = [1,0,0,0,0]`

Build the table:

- `i = 1`
  - use `1`: `dp[1] += dp[0]`, so `dp[1] = 1`
  - `2` and `3` do not fit
- `i = 2`
  - use `1`: add `dp[1] = 1`
  - use `2`: add `dp[0] = 1`
  - `dp[2] = 2` for sequences `[1,1]`, `[2]`
- `i = 3`
  - use `1`: add `dp[2] = 2`
  - use `2`: add `dp[1] = 1`
  - use `3`: add `dp[0] = 1`
  - `dp[3] = 4`
- `i = 4`
  - use `1`: add `dp[3] = 4`
  - use `2`: add `dp[2] = 2`
  - use `3`: add `dp[1] = 1`
  - `dp[4] = 7`

So the method returns `7`, matching the listed sequences in the example.

### Key Variables Explained
- `nums`: the distinct values allowed in each sequence.
- `target`: the total we want to build.
- `dp`: DP array where `dp[i]` stores the number of ordered sequences summing to `i`.
- `i`: the current total being solved.
- `num`: the candidate last element for the current total.

### Why This Works
For every total `i`, the algorithm partitions all valid sequences by their last number. If the last number is `num`, the earlier part of the sequence must sum to `i - num`, and there are exactly `dp[i - num]` such sequences.

Summing over all possible `num` values counts every valid ordered sequence exactly once. Since the loop builds `dp` from smaller totals to larger totals, all needed subproblems are already solved when used.

### Trick Used
The trick is the **loop order**: iterating `i` in the outer loop and `num` in the inner loop makes order matter, so `[1,3]` and `[3,1]` are counted separately.

### Edge Cases Handled
- `target = 0`: `dp[0] = 1`, so the code correctly returns one empty way.
- Values larger than the current total are skipped by `if (i - num >= 0)`.
- Impossible targets, such as `nums = [9]` and `target = 3`, leave `dp[target] = 0`.

### Complexity Analysis
- **Time Complexity:** `O(target * nums.length)` because the nested loops evaluate every pair of current sum `i` and candidate `num` once.
- **Space Complexity:** `O(target)` because the only extra structure is the `dp` array of size `target + 1`.
