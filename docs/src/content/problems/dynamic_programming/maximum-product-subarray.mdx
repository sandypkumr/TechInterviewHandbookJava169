Given an integer array `nums`, find a subarray that has the largest product, and return _the product_.

The test cases are generated so that the answer will fit in a **32-bit** integer.

**Note** that the product of an array with a single element is the value of that element.

**Example 1:**

```
Input: nums = [2,3,-2,4]
Output: 6
Explanation: [2,3] has the largest product 6.
```

**Example 2:**

```
Input: nums = [-2,0,-1]
Output: 0
Explanation: The result cannot be 2, because [-2,-1] is not a subarray.
```

**Constraints:**

- `1 <= nums.length <= 2 * 10^4`

- `-10 <= nums[i] <= 10`

- The product of any subarray of `nums` is **guaranteed** to fit in a **32-bit** integer.

## Java Solution

```java
package dynamic_programming;

public class MaximumProductSubarray {
    public int maxProduct(int[] nums) {
        int maxProduct = nums[0];
        int minProduct = nums[0];
        int result = nums[0];

        for (int i = 1; i < nums.length; i++) {
            if (nums[i] < 0) {
                int temp = maxProduct;
                maxProduct = minProduct;
                minProduct = temp;
            }

            maxProduct = Math.max(nums[i], maxProduct * nums[i]);
            minProduct = Math.min(nums[i], minProduct * nums[i]);

            result = Math.max(result, maxProduct);
        }

        return result;
    }
}
```

## Explanation

### Approach

**Maximum Product Subarray** has optimal substructure: the answer to the full problem can be built from answers to smaller sub-problems. Without memoisation, a naive recursion solves the same sub-problem exponentially many times; DP stores each result once and reuses it in O(1).

Think of computing Fibonacci numbers: fib(5) needs fib(4) and fib(3), which both need fib(2) — without caching you'd compute fib(2) repeatedly. DP caches each sub-answer so every value is computed exactly once, reducing exponential work to polynomial.

### Code Walkthrough

The solution is implemented in `maxProduct(int[] nums)`:

1. Define the state: what does dp[i] (or dp[i][j]) represent?
2. Write the recurrence relation that builds dp[i] from previously computed states.
3. Identify and set the base cases (dp[0], dp[1], etc.).
4. Fill the table bottom-up (or top-down with memoisation) in the correct order.
5. Read off the final answer from dp[n] (or dp[m][n] for 2-D problems).

### Complexity Analysis

- **Time Complexity: `O(n)`** — the input is processed in a single linear pass.
- **Space Complexity: `O(1)`** — only a fixed number of extra variables are used; no data structures that scale with input.
