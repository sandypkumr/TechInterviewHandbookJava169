You are climbing a staircase. It takes `n` steps to reach the top.

Each time you can either climb `1` or `2` steps. In how many distinct ways can you climb to the top?

**Example 1:**

```
Input: n = 2
Output: 2
Explanation: There are two ways to climb to the top.
1. 1 step + 1 step
2. 2 steps
```

**Example 2:**

```
Input: n = 3
Output: 3
Explanation: There are three ways to climb to the top.
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step
```

**Constraints:**

- `1 <= n <= 45`

## Java Solution

```java
package dynamic_programming;

public class ClimbingStairs {
    public int climbStairs(int n) {
        if (n <= 2) {
            return n;
        }

        int first = 1;
        int second = 2;
        int current = 0;

        for (int i = 3; i <= n; i++) {
            current = first + second;
            first = second;
            second = current;
        }

        return current;
    }
}
```

## Explanation

### Approach

**Climbing Stairs** has optimal substructure: the answer to the full problem can be built from answers to smaller sub-problems. Without memoisation, a naive recursion solves the same sub-problem exponentially many times; DP stores each result once and reuses it in O(1).

Think of computing Fibonacci numbers: fib(5) needs fib(4) and fib(3), which both need fib(2) — without caching you'd compute fib(2) repeatedly. DP caches each sub-answer so every value is computed exactly once, reducing exponential work to polynomial.

### Code Walkthrough

The solution is implemented in `climbStairs(int n)`:

1. Define the state: what does dp[i] (or dp[i][j]) represent?
2. Write the recurrence relation that builds dp[i] from previously computed states.
3. Identify and set the base cases (dp[0], dp[1], etc.).
4. Fill the table bottom-up (or top-down with memoisation) in the correct order.
5. Read off the final answer from dp[n] (or dp[m][n] for 2-D problems).

### Complexity Analysis

- **Time Complexity: `O(n)`** — the input is processed in a single linear pass.
- **Space Complexity: `O(1)`** — only a fixed number of extra variables are used; no data structures that scale with input.
