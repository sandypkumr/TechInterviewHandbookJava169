Given a string `s`, return _the longest_ _palindromic_ _substring_ in `s`.

**Example 1:**

```
Input: s = "babad"
Output: "bab"
Explanation: "aba" is also a valid answer.
```

**Example 2:**

```
Input: s = "cbbd"
Output: "bb"
```

**Constraints:**

- `1 <= s.length <= 1000`

- `s` consist of only digits and English letters.

**Patterns:** `sliding-window`, `merge-intervals`

## Java Solution

```java
package string;

public class LongestPalindromicSubstring {
    public String longestPalindrome(String s) {
        int n = s.length();
        if (n < 2) {
            return s;
        }
        int start = 0, end = 0;
        for (int i = 0; i < n; i++) {
            int len1 = expandAroundCenter(s, i, i); // Odd length palindrome
            int len2 = expandAroundCenter(s, i, i + 1); // Even length palindrome
            int len = Math.max(len1, len2);
            if (len > end - start) {
                start = i - (len - 1) / 2;
                end = i + len / 2;
            }
        }
        return s.substring(start, end + 1);
    }

    private int expandAroundCenter(String s, int left, int right) {
        while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        return right - left - 1;
    }
}
```

## Explanation

### Problem Analysis
This problem asks for the longest contiguous substring that reads the same forward and backward.
The challenge is that checking every substring would be too slow, so interviews use this problem to test whether you can exploit palindrome structure instead of brute force enumeration.

### Approach
The code treats each index as a possible palindrome center and expands outward while the characters match.
That is far better than checking all substrings explicitly. A palindrome is defined by its center, so the solution checks two cases at every position: odd-length palindromes centered at `i`, and even-length palindromes centered between `i` and `i + 1`.

### Pattern Used
Two Pointers

### Key Insight
Every palindrome can be discovered by expanding from its center, so checking all centers covers all possible palindromic substrings without generating every substring first.

### Code Walkthrough
The method `longestPalindrome(String s)` begins with `int n = s.length();`.
- If `n < 2`, it returns `s` immediately because a string of length `0` or `1` is already its own longest palindrome.

The variables `start` and `end` store the best palindrome boundaries found so far.

The loop `for (int i = 0; i < n; i++)` tries every position as a center.
For each `i`, the code computes:
- `len1 = expandAroundCenter(s, i, i)` for odd-length palindromes
- `len2 = expandAroundCenter(s, i, i + 1)` for even-length palindromes

Then it keeps `len = Math.max(len1, len2)`.
- If `len > end - start`, the current palindrome is longer than the best one seen so far.
- The new boundaries are computed as:
  - `start = i - (len - 1) / 2`
  - `end = i + len / 2`

The helper `expandAroundCenter(String s, int left, int right)` does the real expansion work.
- While `left >= 0`, `right < s.length()`, and the two characters match, it keeps moving outward.
- Once the expansion stops, the palindrome length is `right - left - 1` because both pointers have already moved one step beyond the valid palindrome.

Finally, `s.substring(start, end + 1)` returns the longest palindromic substring.

### Example Walkthrough
Use Example 1: `s = "babad"`.

Start with `start = 0`, `end = 0`.

At `i = 0`:
- `len1` from `"b"` is `1`
- `len2` from positions `(0, 1)` is `0`
- Best remains `"b"`

At `i = 1`:
- `len1` expands around `'a'` and matches `b-a-b`, so length is `3`
- `len2` is `0`
- Update:
  - `start = 1 - (3 - 1) / 2 = 0`
  - `end = 1 + 3 / 2 = 2`
- Best substring is now `"bab"`

At `i = 2`:
- `len1` expands to `"aba"`, also length `3`
- Since `len > end - start` is still true for this code's comparison, boundaries can shift to `"aba"`
- Either `"bab"` or `"aba"` is valid

Later centers do not produce a longer palindrome.
The method returns one valid longest answer of length `3`.

### Key Variables Explained
- `n`: length of the input string
- `start`, `end`: inclusive boundaries of the best palindrome found so far
- `i`: current center being tested
- `len1`: palindrome length for odd center `(i, i)`
- `len2`: palindrome length for even center `(i, i + 1)`
- `len`: better of the two palindrome lengths at this center
- `left`, `right`: expansion pointers inside `expandAroundCenter`

### Why This Works
Every palindrome has a center.
- Odd-length palindromes have a single middle character
- Even-length palindromes have a middle gap between two characters

By checking both center types for every index, the code considers every possible palindrome. `expandAroundCenter` grows only while the substring remains palindromic, so the returned length is exact. The `start` and `end` updates convert that length back into real substring boundaries, ensuring the longest valid candidate is preserved.

### Trick Used
Checking both `(i, i)` and `(i, i + 1)` handles odd and even palindromes uniformly with the same helper method.

### Edge Cases Handled
- `n < 2`: immediately returns `s`, so empty or single-character strings work without extra logic
- Even-length palindromes like `"bb"`: covered by `expandAroundCenter(s, i, i + 1)`
- Odd-length palindromes like `"bab"`: covered by `expandAroundCenter(s, i, i)`
- Palindromes touching string boundaries: the while condition stops safely when `left < 0` or `right == s.length()`

### Complexity Analysis
- Time Complexity: `O(n^2)`
  - There are `n` centers
  - Each center expansion can scan outward up to `O(n)` characters in the worst case
- Space Complexity: `O(1)`
  - Only a few integer variables are used beyond the input string
