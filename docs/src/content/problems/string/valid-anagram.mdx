Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

**Example 1:**

**Input:** s = "anagram", t = "nagaram"

**Output:** true

**Example 2:**

**Input:** s = "rat", t = "car"

**Output:** false

**Constraints:**

- `1 <= s.length, t.length <= 5 * 10^4`

- `s` and `t` consist of lowercase English letters.

**Follow up:** What if the inputs contain Unicode characters? How would you adapt your solution to such a case?

## Java Solution

```java
package string;

public class ValidAnagram {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) {
            return false;
        }

        int[] charCount = new int[26]; // Assuming only lowercase letters a-z

        for (int i = 0; i < s.length(); i++) {
            charCount[s.charAt(i) - 'a']++;
            charCount[t.charAt(i) - 'a']--;
        }

        for (int count : charCount) {
            if (count != 0) {
                return false;
            }
        }

        return true;
    }
}
```

## Explanation

### Problem Analysis

Two strings are anagrams if they contain exactly the same characters with exactly the same frequencies, just in a different order. Since the input is restricted to lowercase English letters, we do not need sorting or a general-purpose hash map.

This is a classic interview question because it tests whether you can translate "same multiset of characters" into an efficient counting strategy.

### Approach

The solution uses one frequency array `charCount` of size 26. For every position `i`, it increments the count for `s.charAt(i)` and decrements the count for `t.charAt(i)`.

This is better than sorting because:

- it finishes in linear time,
- it avoids rearranging either string,
- it uses the lowercase-letter constraint to keep space fixed.

### Pattern Used

This solution primarily relies on **counting / frequency array**.

### Key Insight

If two same-length strings are anagrams, then after adding counts from `s` and subtracting counts from `t`, every entry in the 26-slot array must end at zero.

### Code Walkthrough

The method first checks `if (s.length() != t.length())`. If lengths differ, the strings cannot be anagrams, so it returns `false` immediately.

`int[] charCount = new int[26]` stores balance counts for letters `'a'` through `'z'`.

The loop `for (int i = 0; i < s.length(); i++)` processes both strings together:

- `charCount[s.charAt(i) - 'a']++` records one more occurrence from `s`,
- `charCount[t.charAt(i) - 'a']--` cancels one occurrence from `t`.

After that, the enhanced for-loop checks every `count` inside `charCount`. If any entry is not zero, one letter appeared a different number of times in the two strings, so the method returns `false`.

If all 26 entries are zero, the method returns `true`.

### Example Walkthrough

Take **Example 1**, `s = "anagram"` and `t = "nagaram"`.

- Lengths are both 7, so the method continues.
- As the loop runs:
  - `'a'` in `s` increments the `'a'` bucket, while `'n'` in `t` decrements the `'n'` bucket.
  - next, `'n'` increments the `'n'` bucket, while `'a'` decrements the `'a'` bucket.
  - this balancing continues for every position.
- By the end, each letter used in one string has been canceled by the same number of appearances in the other.
- The final scan sees only zeroes, so the method returns `true`.

For **Example 2**, `"rat"` vs `"car"`, the counts for `'t'` and `'c'` cannot cancel, so one of the entries remains non-zero and the method returns `false`.

### Key Variables Explained

- `charCount`: a 26-element balance array where positive values mean `s` has seen more of that letter so far, and negative values mean `t` has.
- `i`: the current index used to read both strings in lockstep.
- `count`: the current frequency balance being checked in the final validation loop.

### Why This Works

The loop maintains an invariant: after processing indices `0..i`, `charCount[x]` equals:

`(# of letter x seen in s so far) - (# of letter x seen in t so far)`.

If the strings are anagrams, every letter count must match, so all balances become zero after the full scan. If even one balance is non-zero, then at least one character frequency differs, which is exactly why the strings are not anagrams.

### Trick Used

Updating counts for both strings in the same loop cuts the work into one pass instead of building two separate frequency arrays.

### Edge Cases Handled

- Different lengths: immediately rejected by `if (s.length() != t.length())`.
- Repeated characters: handled naturally by incrementing and decrementing counts multiple times.
- Strings that are already identical: all counts still cancel to zero.
- Strings with the same letters except one mismatch: the final scan detects the non-zero bucket.

### Complexity Analysis

- **Time Complexity: `O(n)`** — one loop processes all `n` characters, and a second loop checks exactly 26 array entries, which is constant extra work.
- **Space Complexity: `O(1)`** — the `charCount` array always has fixed size 26, regardless of input length.
