A phrase is a **palindrome** if, after converting all uppercase letters into lowercase letters and removing all non-alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.

Given a string `s`, return `true`_ if it is a **palindrome**, or _`false`_ otherwise_.

**Example 1:**

```
Input: s = "A man, a plan, a canal: Panama"
Output: true
Explanation: "amanaplanacanalpanama" is a palindrome.
```

**Example 2:**

```
Input: s = "race a car"
Output: false
Explanation: "raceacar" is not a palindrome.
```

**Example 3:**

```
Input: s = " "
Output: true
Explanation: s is an empty string "" after removing non-alphanumeric characters.
Since an empty string reads the same forward and backward, it is a palindrome.
```

**Constraints:**

- `1 <= s.length <= 2 * 10^5`

- `s` consists only of printable ASCII characters.

**Patterns:** `sliding-window`, `two-pointers`

## Java Solution

```java
package string;

public class ValidPalindrome {
    public boolean isPalindrome(String s) {
        int left = 0;
        int right = s.length() - 1;

        while (left < right) {
            // Move left pointer to the next valid character
            while (left < right && !isValidChar(s.charAt(left))) {
                left++;
            }
            // Move right pointer to the previous valid character
            while (left < right && !isValidChar(s.charAt(right))) {
                right--;
            }
            // Compare characters
            if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right))) {
                return false;
            }
            left++;
            right--;
        }

        return true;
    }

    private boolean isValidChar(char c) {
        return Character.isLetterOrDigit(c);
    }
}
```

## Explanation

### Problem Analysis

We need to decide whether a string reads the same forward and backward after ignoring punctuation, spaces, and case differences. So the real task is not comparing the raw string, but comparing only its alphanumeric characters in normalized lowercase form.

This is a very common interview problem because it checks whether you can use pointers carefully while filtering input on the fly instead of building unnecessary extra strings.

### Approach

The solution uses two pointers, `left` and `right`, starting from both ends of the string. Before comparing characters, it skips over any character that is not alphanumeric by calling `isValidChar`.

This is better than constructing a cleaned string first because:

- it keeps extra space constant,
- it processes the string in one pass,
- it compares only the characters that actually matter.

### Pattern Used

This solution uses the **Two Pointers** pattern.

### Key Insight

If the string is a palindrome after filtering, then the next valid character from the left must always match the next valid character from the right, case-insensitively.

### Code Walkthrough

The method initializes `left = 0` and `right = s.length() - 1`.

The outer loop `while (left < right)` keeps shrinking the window being checked.

Inside that loop:

- `while (left < right && !isValidChar(s.charAt(left)))` moves `left` forward until it points at a letter or digit.
- `while (left < right && !isValidChar(s.charAt(right)))` moves `right` backward for the same reason.

Once both pointers are on valid characters, the code compares:

- `Character.toLowerCase(s.charAt(left))`
- `Character.toLowerCase(s.charAt(right))`

If they differ, the method immediately returns `false`.

If they match, both pointers move inward with `left++` and `right--`, and the process repeats.

`isValidChar(char c)` simply delegates to `Character.isLetterOrDigit(c)`, which is exactly the filtering rule required by the problem.

### Example Walkthrough

Take **Example 1**, `s = "A man, a plan, a canal: Panama"`.

- `left` starts at `'A'`, `right` starts at `'a'`. Lowercased, both are `'a'`, so they match.
- `left` advances over the space after `A`; `right` skips backward over punctuation and spaces near the end.
- The next meaningful pair becomes `'m'` and `'m'`, then `'a'` and `'a'`, then `'n'` and `'n'`.
- This continues as the pointers keep skipping commas, spaces, and the colon.
- Eventually the pointers cross without finding a mismatch, so the method returns `true`.

That matches the cleaned string `"amanaplanacanalpanama"`.

### Key Variables Explained

- `left`: scans from the beginning toward the center.
- `right`: scans from the end toward the center.
- `s`: original input string, read directly without creating a filtered copy.
- `isValidChar(...)`: helper that decides whether a character should participate in palindrome comparison.

### Why This Works

At every iteration, the code preserves this invariant: all valid characters outside the current `[left, right]` window have already been matched successfully with their mirrored partner.

Skipping invalid characters is safe because the problem explicitly says they should be ignored. Comparing lowercase versions is safe because case should not matter. Therefore, the first mismatch proves the string is not a palindrome, and if no mismatch appears before the pointers cross, every mirrored pair matches and the string is a palindrome.

### Trick Used

Filtering characters lazily with the inner `while` loops avoids building a separate normalized string.

### Edge Cases Handled

- String containing only spaces or punctuation, such as **Example 3**: the pointers skip invalid characters and the method returns `true`.
- Mixed uppercase and lowercase letters: handled by `Character.toLowerCase(...)`.
- Digits inside the string: allowed because `isValidChar` accepts letters and digits.
- Early mismatch, such as `"race a car"`: the first unequal valid pair triggers `false`.

### Complexity Analysis

- **Time Complexity: `O(n)`** — each character is visited at most a constant number of times as `left` and `right` only move inward.
- **Space Complexity: `O(1)`** — only the two pointers and a helper method are used.
