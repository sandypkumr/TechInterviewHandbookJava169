Given an integer array `nums` where the elements are sorted in **ascending order**, convert _it to a _**_height-balanced_** _binary search tree_.

**Example 1:**

```
Input: nums = [-10,-3,0,5,9]
Output: [0,-3,9,-10,null,5]
Explanation: [0,-10,5,null,-3,null,9] is also accepted:
```

**Example 2:**

```
Input: nums = [1,3]
Output: [3,1]
Explanation: [1,null,3] and [3,1] are both height-balanced BSTs.
```

**Constraints:**

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` is sorted in a **strictly increasing** order.

**Patterns:** `divide-and-conquer`, `recursion`

## Java Solution

```java
package binary_search_tree;

public class ConvertSortedArrayToBinarySearchTree {
    public TreeNode sortedArrayToBST(int[] nums) {
        return buildBST(nums, 0, nums.length - 1);
    }

    private TreeNode buildBST(int[] nums, int left, int right) {
        if (left > right) {
            return null;
        }
        int mid = left + (right - left) / 2;
        TreeNode node = new TreeNode(nums[mid]);
        node.left = buildBST(nums, left, mid - 1);
        node.right = buildBST(nums, mid + 1, right);
        return node;
    }
}
```

## Explanation

### Problem Analysis

The array is already sorted, and the output must be a **height-balanced BST**.

Those two requirements immediately tell us what each recursive root selection must achieve:
- values on the left side must remain in the left subtree
- values on the right side must remain in the right subtree
- the split should be as even as possible so the tree stays balanced

So this problem is really about choosing the correct root for each subarray.

### Approach

The solution builds the BST recursively from index ranges.

For any subarray `nums[left...right]`:
- choose the middle index `mid`
- create a node from `nums[mid]`
- recursively build the left subtree from `left` to `mid - 1`
- recursively build the right subtree from `mid + 1` to `right`

Because the array is sorted, all values before `mid` are smaller and all values after `mid` are larger. That gives the BST property automatically.

### Pattern Used

This solution mainly uses **divide-and-conquer with recursion**.

Each recursive call solves the same problem on a smaller sorted range until no elements remain.

### Key Insight

Picking the middle element as the root does two jobs at once:
- it preserves BST ordering because the array is sorted
- it keeps the tree height-balanced because the left and right halves are nearly equal in size

That single choice drives the whole solution.

### Code Walkthrough

```java
public TreeNode sortedArrayToBST(int[] nums) {
    return buildBST(nums, 0, nums.length - 1);
}

private TreeNode buildBST(int[] nums, int left, int right) {
    if (left > right) {
        return null;
    }
    int mid = left + (right - left) / 2;
    TreeNode node = new TreeNode(nums[mid]);
    node.left = buildBST(nums, left, mid - 1);
    node.right = buildBST(nums, mid + 1, right);
    return node;
}
```

How the method works:

1. `sortedArrayToBST` starts the recursion on the full array.
2. `buildBST(nums, left, right)` builds a balanced BST from the current subarray boundaries.
3. If `left > right`, the range is empty, so the method returns `null`.
4. `int mid = left + (right - left) / 2;` computes the middle index.
   - This is the standard overflow-safe midpoint formula in Java.
   - For even-sized ranges, this code chooses the left-middle element.
5. `new TreeNode(nums[mid])` creates the root node for the current range.
6. `buildBST(nums, left, mid - 1)` builds the left subtree from the smaller values.
7. `buildBST(nums, mid + 1, right)` builds the right subtree from the larger values.
8. The method returns the node after attaching both child pointers.

### Example Walkthrough

For `nums = [-10, -3, 0, 5, 9]`:

1. First call: `left = 0`, `right = 4`
   - `mid = 2`
   - root = `0`

2. Build the left subtree from `[-10, -3]`
   - `left = 0`, `right = 1`
   - `mid = 0`
   - node = `-10`
   - left side becomes `null`
   - right side becomes `-3`

3. Build the right subtree from `[5, 9]`
   - `left = 3`, `right = 4`
   - `mid = 3`
   - node = `5`
   - left side becomes `null`
   - right side becomes `9`

One tree produced by this exact code is:

```text
        0
      /   \
   -10     5
      \     \
      -3     9
```

This output is valid because:
- all left descendants are smaller than their parent
- all right descendants are larger than their parent
- each recursive split stays nearly even

### Key Variables Explained

- **`nums`**: the sorted input array.
- **`left`**: the starting index of the current subarray.
- **`right`**: the ending index of the current subarray.
- **`mid`**: the index chosen as the root for the current subtree.
- **`node`**: the `TreeNode` created from `nums[mid]`.

### Why This Works

At every recursive step, `buildBST(nums, left, right)` is responsible for building a BST from exactly the elements in `nums[left...right]`.

That works because:
- the middle element becomes the root
- everything left of `mid` is smaller, so it belongs in the left subtree
- everything right of `mid` is larger, so it belongs in the right subtree
- the same logic is applied recursively to both halves

The tree is height-balanced because each split divides the current range into two parts whose sizes differ by at most one.

### Trick Used

There is no hidden trick beyond the core idea: **always use the middle element of the current range as the subtree root**.

That one choice gives both properties we need:
- valid BST ordering
- balanced tree height

### Edge Cases Handled

1. **Single element** like `[7]`
   - `left == right`, so the method creates one node and returns it

2. **Two elements** like `[1, 3]`
   - this code picks index `0` first
   - root becomes `1`
   - `3` becomes the right child
   - the result is still height-balanced

3. **Empty subarray during recursion**
   - when `left > right`, the method returns `null`
   - this correctly ends branches with no child node

4. **Negative numbers** like `[-10, -3, 0]`
   - nothing special is needed
   - the sorted order is enough for the recursion to place them correctly

### Complexity Analysis

- **Time Complexity: `O(n)`** — each element is used once to create exactly one `TreeNode`.
- **Space Complexity: `O(log n)`** — the recursion depth matches the height of the balanced tree.
