Given an integer array `nums` where the elements are sorted in **ascending order**, convert _it to a _**_height-balanced_** _binary search tree_.

**Example 1:**

```
Input: nums = [-10,-3,0,5,9]
Output: [0,-3,9,-10,null,5]
Explanation: [0,-10,5,null,-3,null,9] is also accepted:
```

**Example 2:**

```
Input: nums = [1,3]
Output: [3,1]
Explanation: [1,null,3] and [3,1] are both height-balanced BSTs.
```

**Constraints:**

- `1 <= nums.length <= 10^4`

- `-10^4 <= nums[i] <= 10^4`

- `nums` is sorted in a **strictly increasing** order.

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_search_tree;

public class ConvertSortedArrayToBinarySearchTree {
    public TreeNode sortedArrayToBST(int[] nums) {
        return buildBST(nums, 0, nums.length - 1);
    }

    private TreeNode buildBST(int[] nums, int left, int right) {
        if (left > right) {
            return null;
        }
        int mid = left + (right - left) / 2;
        TreeNode node = new TreeNode(nums[mid]);
        node.left = buildBST(nums, left, mid - 1);
        node.right = buildBST(nums, mid + 1, right);
        return node;
    }
}
```

## Explanation

### Problem Analysis

We are given a sorted array and must build a height-balanced BST from it. A valid tree must preserve BST ordering, and "height-balanced" means the left and right subtrees should stay as even as possible.

This is a common interview problem because it tests whether you can connect sorted data, recursion, and balanced-tree construction in one clean solution.

### Approach

The code always picks the middle element of the current subarray as the root. Everything left of that middle value becomes the left subtree, and everything right of it becomes the right subtree.

This approach is chosen because:

- it automatically satisfies BST ordering
- it keeps the tree balanced by splitting the array into two nearly equal halves at every step

### Pattern Used

Divide and Conquer with recursive DFS tree construction.

### Key Insight

In a sorted array, the middle element is the only natural root choice that preserves order while keeping subtree heights close to each other.

### Code Walkthrough

The public method is:

```java
public TreeNode sortedArrayToBST(int[] nums) {
    return buildBST(nums, 0, nums.length - 1);
}
```

So the real work happens in `buildBST(int[] nums, int left, int right)`.

Base case:

```java
if (left > right) {
    return null;
}
```

If the current subarray is empty, there is no node to build.

Next, the code picks the middle index:

```java
int mid = left + (right - left) / 2;
```

Then it creates the current root:

```java
TreeNode node = new TreeNode(nums[mid]);
```

After that, it recursively builds:

- `node.left = buildBST(nums, left, mid - 1);`
- `node.right = buildBST(nums, mid + 1, right);`

Finally, it returns `node`, which is the completed subtree for that range.

### Example Walkthrough

Use Example 1:

```text
nums = [-10,-3,0,5,9]
```

Step by step:

1. `buildBST(nums, 0, 4)`
   - `mid = 2`
   - create `node = new TreeNode(0)`
2. Build left subtree with `buildBST(nums, 0, 1)`
   - `mid = 0`
   - create node `-10`
   - left side `buildBST(nums, 0, -1)` returns `null`
   - right side `buildBST(nums, 1, 1)` creates node `-3`
3. Build right subtree with `buildBST(nums, 3, 4)`
   - `mid = 3`
   - create node `5`
   - left side `buildBST(nums, 3, 2)` returns `null`
   - right side `buildBST(nums, 4, 4)` creates node `9`

One valid resulting tree is:

- root `0`
- left child `-10`
- right child `5`
- `-10` has right child `-3`
- `5` has right child `9`

That matches the problem statement's note that multiple balanced BST shapes are acceptable.

### Key Variables Explained

- `nums`: the sorted input array.
- `left`: starting index of the current subarray being converted.
- `right`: ending index of the current subarray.
- `mid`: chosen root index for the current subtree.
- `node`: the `TreeNode` created from `nums[mid]`.

### Why This Works

Every recursive call builds a subtree from a sorted subarray. Since all elements left of `mid` are smaller than `nums[mid]`, they belong in the left subtree. Since all elements right of `mid` are larger, they belong in the right subtree.

Choosing the middle index keeps the two recursive ranges as balanced as possible, so the height remains balanced throughout the construction.

### Trick Used

The key trick is always selecting `mid = left + (right - left) / 2`, which both avoids overflow and gives a naturally balanced split.

### Edge Cases Handled

- **Empty subarray during recursion**: `left > right` returns `null`.
- **Single-element subarray**: `left == right` creates exactly one leaf node.
- **Even-sized subarray**: integer division picks one of the two middle candidates, and the result is still height-balanced.

### Complexity Analysis

- **Time Complexity: `O(n)`** — each array element is turned into exactly one `TreeNode`, and each recursive call does constant extra work beyond its two children.
- **Space Complexity: `O(log n)`** — the recursion depth is the height of the balanced BST, which is logarithmic.
