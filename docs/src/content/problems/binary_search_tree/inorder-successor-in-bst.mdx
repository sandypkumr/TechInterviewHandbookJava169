Problem Statement:
    Given the root of a binary search tree and a node p in it, return the in-order successor of that node in the BST.
    If the given node has no in-order successor in the tree, return null.

    The successor of a node p is the node with the smallest key greater than p.val.

    Example 1:

    Input: root = [2,1,3], p = 1
    Output: 2

    Example 2:

    Input: root = [5,3,6,2,4,null,null,1], p = 6
    Output: null

    Constraints:

    The number of nodes in the tree is in the range [1, 104].
    -105 &lt;= Node.val &lt;= 105
    All Nodes will have unique values.

**Patterns:** `binary-search`

## Java Solution

```java
package binary_search_tree;

/**
 * Problem Statement:
 *     Given the root of a binary search tree and a node p in it, return the in-order successor of that node in the BST.
 *     If the given node has no in-order successor in the tree, return null.
 *
 *     The successor of a node p is the node with the smallest key greater than p.val.
 *
 *     Example 1:
 *
 *     Input: root = [2,1,3], p = 1
 *     Output: 2
 *
 *     Example 2:
 *
 *     Input: root = [5,3,6,2,4,null,null,1], p = 6
 *     Output: null
 *
 *     Constraints:
 *
 *     The number of nodes in the tree is in the range [1, 104].
 *     -105 <= Node.val <= 105
 *     All Nodes will have unique values.
 */
public class InorderSuccessorInBST {
    public TreeNode inorderSuccessor(TreeNode root, TreeNode p) {
        TreeNode successor = null;
        while (root != null) {
            if (p.val < root.val) {
                successor = root;
                root = root.left;
            } else {
                root = root.right;
            }
        }
        return successor;
    }
}
```

## Explanation

### Problem Analysis

This problem asks for the **next node in inorder order** after `p`, which means the node with the **smallest value greater than `p.val`**.

Since the input tree is a **binary search tree**, we can use its ordering directly:
- all values in the left subtree are smaller than the current node
- all values in the right subtree are larger than the current node

That means we do **not** need to build the full inorder traversal or scan every node. We only need to keep track of the best "just larger than `p`" candidate while walking down the tree.

### Approach

The solution starts at the root and moves downward like a BST search.

At each node:
- if `p.val < root.val`, the current node is a valid successor candidate
  - save it in `successor`
  - move left to see whether there is an even smaller valid candidate
- otherwise, move right
  - the current node cannot be the successor
  - its left subtree also cannot contain the successor because those values are even smaller

When the loop finishes, `successor` is either the smallest value greater than `p.val` or `null` if no such value exists.

### Pattern Used

This solution mainly uses **direct BST traversal with binary-search-style decisions**.

It is not a full DFS over the whole tree. The code follows only one search path from the root, using BST comparisons to discard entire subtrees.

### Key Insight

The successor must come from the set of nodes whose values are **greater than `p.val`**.

Among those nodes, we want the **smallest** one.

So whenever the code sees a node with `root.val > p.val`, it records that node as the current best answer and then moves left to try to improve it.

### Code Walkthrough

```java
public TreeNode inorderSuccessor(TreeNode root, TreeNode p) {
    TreeNode successor = null;
    while (root != null) {
        if (p.val < root.val) {
            successor = root;
            root = root.left;
        } else {
            root = root.right;
        }
    }
    return successor;
}
```

How the method works:

1. `successor` starts as `null` because the answer might not exist.
2. The loop uses `root` as a moving pointer through the BST.
3. If `p.val < root.val`:
   - `root` is bigger than `p`, so it is a possible successor
   - store it in `successor`
   - move to `root.left` to look for a smaller larger value
4. Otherwise, move to `root.right`.
   - if `root.val == p.val`, the successor must be somewhere to the right
   - if `root.val < p.val`, both `root` and its left subtree are too small
5. When `root` becomes `null`, the search path is done and the best saved candidate is returned.

### Example Walkthrough

Consider:

`root = [5,3,6,2,4,null,null,1]`, `p = 3`

We want the smallest value greater than `3`, so the answer should be `4`.

Step by step:

1. Start at `root = 5`
   - `3 < 5`, so `5` is a valid candidate
   - set `successor = 5`
   - move left to `3`

2. At `root = 3`
   - `3 < 3` is false
   - move right to `4`

3. At `root = 4`
   - `3 < 4`, so `4` is a better candidate than `5`
   - set `successor = 4`
   - move left to `null`

4. The loop ends, so return `successor = 4`

This matches the idea of always keeping the best larger candidate seen so far.

### Key Variables Explained

- **`root`**: reused as the current traversal pointer while moving down the BST.
- **`p`**: the target node whose inorder successor we need to find.
- **`successor`**: the best candidate found so far; it always stores a node value greater than `p.val` that could still be the smallest such value.

### Why This Works

The invariant is:

> At every step, `successor` is the smallest valid candidate seen so far.

If `root.val > p.val`, then `root` could be the answer, but a better answer might exist in the left subtree, so the code saves `root` and goes left.

If `root.val <= p.val`, then `root` cannot be the successor. Its left subtree also cannot contain the successor, because every value there is less than `root.val`. So moving right is the only useful choice.

By repeatedly discarding impossible subtrees and remembering the best larger node found on the path, the algorithm ends with exactly the inorder successor.

### Trick Used

There is no fancy trick here.

The practical trick is simply: **when you move left from a node larger than `p`, save that node as the current answer**.

That is enough to avoid building an inorder list or traversing the full tree.

### Edge Cases Handled

1. **`p` is the largest node in the BST**
   - no node has a larger value
   - `successor` stays `null`

2. **The successor is an ancestor of `p`**
   - this happens when `p` has no right subtree
   - the earlier saved candidate becomes the answer

3. **`p` has a right subtree**
   - the search moves right from `p`
   - then it keeps checking for the smallest larger node there

4. **Single-node tree**
   - the loop ends without finding a larger value
   - the method returns `null`

### Complexity Analysis

- **Time Complexity: `O(h)`** — the code only walks down one root-to-leaf path, where `h` is the tree height. This is `O(log n)` for a balanced BST and `O(n)` for a skewed tree.
- **Space Complexity: `O(1)`** — only a couple of pointers are used, with no recursion and no extra data structure.
