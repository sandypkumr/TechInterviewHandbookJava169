Given two binary strings `a` and `b`, return _their sum as a binary string_.

**Example 1:**

```
Input: a = "11", b = "1"
Output: "100"
```
**Example 2:**

```
Input: a = "1010", b = "1011"
Output: "10101"
```

**Constraints:**

- `1 <= a.length, b.length <= 10^4`

- `a` and `b` consist only of `'0'` or `'1'` characters.

- Each string does not contain leading zeros except for the zero itself.

## Java Solution

```java
package binary;

public class AddBinary {
    public String addBinary(String a, String b) {
        StringBuilder result = new StringBuilder();
        int i = a.length() - 1, j = b.length() - 1, carry = 0;

        while (i >= 0 || j >= 0 || carry != 0) {
            int sum = carry;
            if (i >= 0) sum += a.charAt(i--) - '0';
            if (j >= 0) sum += b.charAt(j--) - '0';
            result.append(sum % 2);
            carry = sum / 2;
        }

        return result.reverse().toString();
    }
}
```

## Explanation

### Problem Analysis

The problem is to add two binary numbers represented as strings and return their sum as a binary string.

This is a direct arithmetic problem: we treat the strings as base-2 numbers and perform column-by-column addition, just like you would add decimal numbers by hand.

The key observation is that strings might have different lengths, so we cannot simply zip them. We must handle positions where one or both strings end.

### Approach

The solution scans both strings from right to left (least significant digit to most significant), maintaining a carry variable.

For each position:
- extract the digit from each string (if it exists)
- add both digits and the carry
- record the result digit
- update the carry for the next position

The result digits are built in reverse order and then reversed at the end.

### Pattern Used

This uses the **two-pointer right-to-left scan** pattern.

We move two pointers backward simultaneously through each string, processing digits from least significant to most significant, which is the natural order for addition.

### Key Insight

Binary addition works column by column, just like decimal addition.

At each column, the result is either 0 or 1, determined by `(sum of digits + carry) % 2`. The carry for the next column is `(sum of digits + carry) / 2`.

By scanning right-to-left and carrying information forward, we can compute the entire sum in a single pass.

### Code Walkthrough

```java
public String addBinary(String a, String b) {
    StringBuilder result = new StringBuilder();
    int i = a.length() - 1, j = b.length() - 1, carry = 0;

    while (i >= 0 || j >= 0 || carry != 0) {
        int sum = carry;
        if (i >= 0) sum += a.charAt(i--) - '0';
        if (j >= 0) sum += b.charAt(j--) - '0';
        result.append(sum % 2);
        carry = sum / 2;
    }

    return result.reverse().toString();
}
```

How the method works:

1. Initialize `i` and `j` to the last indices of strings `a` and `b`, and `carry` to `0`.
2. Initialize an empty `StringBuilder` to accumulate result digits.
3. While there are still digits to process or a carry remains:
   - Start with `sum = carry`
   - If `i >= 0`, add the digit at `a.charAt(i)` (converted from character to integer via `- '0'`) and decrement `i`
   - If `j >= 0`, add the digit at `b.charAt(j)` (converted from character to integer via `- '0'`) and decrement `j`
   - Append `sum % 2` to the result (the current bit)
   - Update `carry = sum / 2` (the carry for the next position)
4. Reverse the `StringBuilder` and return as a string.

### Example Walkthrough

For `a = "1010"` and `b = "1011"`:

| Step | i | j | carry | a[i] | b[j] | sum | digit (sum%2) | new carry | result |
|-----:|---:|---:|:-----:|:----:|:----:|:---:|:------------:|:--------:|:--------:|
| 1 | 3 | 3 | 0 | 0 | 1 | 1 | 1 | 0 | "1" |
| 2 | 2 | 2 | 0 | 1 | 1 | 2 | 0 | 1 | "01" |
| 3 | 1 | 1 | 1 | 0 | 0 | 1 | 1 | 0 | "101" |
| 4 | 0 | 0 | 0 | 1 | 1 | 2 | 0 | 1 | "0101" |
| 5 | -1 | -1 | 1 | — | — | 1 | 1 | 0 | "10101" |

After building `"10101"` (in reverse order), we reverse it to get `"10101"`.

This equals `10 + 11 = 101` in binary (2 + 3 = 5 in decimal).

### Key Variables Explained

- **`i`**: pointer to the current position in string `a` (starting from the right).
- **`j`**: pointer to the current position in string `b` (starting from the right).
- **`carry`**: the carry bit from the previous column (0 or 1).
- **`sum`**: the sum of the current carry and up to two digits, ranges from 0 to 3.
- **`result`**: a `StringBuilder` that accumulates the result digits.

### Why This Works

At each step, we correctly compute the sum of two bits plus the carry.

In binary: `0 + 0 = 0`, `0 + 1 = 1`, `1 + 1 = 10` (result 0, carry 1), `1 + 1 + 1 = 11` (result 1, carry 1).

By extracting the result bit as `sum % 2` and the carry as `sum / 2`, we handle all cases.

We continue until all digits are processed and no carry remains, guaranteeing we capture the full result including any final carry bit.

### Trick Used

The main trick is using integer arithmetic (`% 2` and `/ 2`) to extract the result bit and carry from binary addition.

This avoids branching logic and works elegantly because binary addition is inherently a base-2 arithmetic operation.

### Edge Cases Handled

1. **Strings of different lengths** like `a = "11"` and `b = "1"`
   - the pointers become -1 at different times
   - we only add digits that exist
   - the shorter string is treated as if it had leading zeros

2. **Carry at the end** like `a = "1"` and `b = "1"`
   - after processing both digits, `carry = 1` remains
   - the while loop continues one more iteration
   - the final `"1"` is appended, giving `"10"`

3. **One string significantly longer** like `a = "1"` and `b = "1111"`
   - after `i` reaches -1, we continue with `j` and the carry
   - leading digits of the longer string are added correctly

4. **Strings of equal length with no final carry** like `a = "00"` and `b = "01"`
   - result is `"01"` (which is `"1"` in canonical binary, but the problem allows it)

### Complexity Analysis

- **Time Complexity: `O(max(m,n))`** — we process each digit once, where `m` and `n` are the lengths of `a` and `b`.
- **Space Complexity: `O(max(m,n))`** — the result string is proportional to the maximum input length (potentially one digit longer due to final carry).
