Given an integer `n`, return _an array _`ans`_ of length _`n + 1`_ such that for each _`i`_ _(`0  0
1 --> 1
2 --> 10
```

**Example 2:**

```
Input: n = 5
Output: [0,1,1,2,1,2]
Explanation:
0 --> 0
1 --> 1
2 --> 10
3 --> 11
4 --> 100
5 --> 101
```

**Constraints:**

- `0 <= n <= 10^5`

**Follow up:**

- It is very easy to come up with a solution with a runtime of `O(n log n)`. Can you do it in linear time `O(n)` and possibly in a single pass?

- Can you do it without using any built-in function (i.e., like `__builtin_popcount` in C++)?

## Java Solution

```java
package binary;

public class CountingBits {
    public int[] countBits(int n) {
        int[] result = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            result[i] = result[i >> 1] + (i & 1);
        }
        return result;
    }
}
```

## Explanation

### Approach

**Counting Bits** has optimal substructure: the answer to the full problem can be built from answers to smaller sub-problems. Without memoisation, a naive recursion solves the same sub-problem exponentially many times; DP stores each result once and reuses it in O(1).

Think of computing Fibonacci numbers: fib(5) needs fib(4) and fib(3), which both need fib(2) — without caching you'd compute fib(2) repeatedly. DP caches each sub-answer so every value is computed exactly once, reducing exponential work to polynomial.

### Code Walkthrough

The solution is implemented in `countBits(int n)`:

1. Define the state: what does dp[i] (or dp[i][j]) represent?
2. Write the recurrence relation that builds dp[i] from previously computed states.
3. Identify and set the base cases (dp[0], dp[1], etc.).
4. Fill the table bottom-up (or top-down with memoisation) in the correct order.
5. Read off the final answer from dp[n] (or dp[m][n] for 2-D problems).

### Complexity Analysis

- **Time Complexity: `O(n)`** — the input is processed in a single linear pass.
- **Space Complexity: `O(n)`** — the DP table has O(n) entries (or O(n²) for 2-D DP — see the dp array dimensions).
