Given an unsorted integer array `nums`. Return the _smallest positive integer_ that is _not present_ in `nums`.

You must implement an algorithm that runs in `O(n)` time and uses `O(1)` auxiliary space.

**Example 1:**

```
Input: nums = [1,2,0]
Output: 3
Explanation: The numbers in the range [1,2] are all in the array.
```

**Example 2:**

```
Input: nums = [3,4,-1,1]
Output: 2
Explanation: 1 is in the array but 2 is missing.
```

**Example 3:**

```
Input: nums = [7,8,9,11,12]
Output: 1
Explanation: The smallest positive integer 1 is missing.
```

**Constraints:**

- `1 <= nums.length <= 10^5`

- `-2^31 <= nums[i] <= 2^31 - 1`

## Java Solution

```java
package hash_table;

public class FirstMissingPositive {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;

        for (int i = 0; i < n; i++) {
            while (nums[i] > 0 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
                int correctIndex = nums[i] - 1;
                int temp = nums[i];
                nums[i] = nums[correctIndex];
                nums[correctIndex] = temp;
            }
        }

        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }

        return n + 1;
    }
}
```

## Explanation

### Problem Analysis

We need the smallest positive integer missing from an unsorted array, under the strict requirement of `O(n)` time and `O(1)` extra space. That rules out sorting with extra storage or using a hash set.

This is a classic interview problem because the difficulty is not finding the answer conceptually, but realizing that the input array itself can be reused as an indexing structure.

### Approach

The solution places each valid number `x` into its "correct" position `x - 1`. For example, `1` belongs at index `0`, `2` at index `1`, and so on. After that rearrangement, the first index where `nums[i] != i + 1` directly reveals the missing positive.

This is better than brute force because it uses in-place swaps to simulate a hash table without extra memory. Values that cannot affect the answer, such as negatives, zero, or numbers larger than `n`, are ignored.

### Pattern Used

**Cyclic Sort / In-place Hashing**

### Key Insight

For an array of length `n`, the first missing positive must lie in the range `1` to `n + 1`, so putting each valid value into index `value - 1` turns the array into a presence map.

### Code Walkthrough

The method begins with `int n = nums.length;`.

The first `for` loop tries to place numbers into their correct indices:

- `while (nums[i] > 0 && nums[i] <= n && nums[nums[i] - 1] != nums[i])`

This condition means:

- only positive values matter
- only values within `1...n` can occupy useful positions
- if the target slot already has the same number, do not swap again

Inside the loop:

- `int correctIndex = nums[i] - 1;`
- `int temp = nums[i];`
- swap `nums[i]` with `nums[correctIndex]`

The `while` loop is important because after one swap, the new `nums[i]` might also need to be moved to its own correct position.

After placement, the second `for` loop checks the array from left to right:

- if `nums[i] != i + 1`, return `i + 1`

If every index is correct, then all numbers `1...n` exist, so the missing value must be `n + 1`.

### Example Walkthrough

Use **Example 2**: `nums = [3,4,-1,1]`

Initial state:

- `n = 4`

`i = 0`:

- `nums[0] = 3`, valid and not in the right place
- swap index `0` with index `2`
- array becomes `[-1,4,3,1]`

`i = 0` again:

- `nums[0] = -1`, not positive, so stop the `while`

`i = 1`:

- `nums[1] = 4`, valid and misplaced
- swap index `1` with index `3`
- array becomes `[-1,1,3,4]`

`i = 1` again:

- `nums[1] = 1`, valid and misplaced
- swap index `1` with index `0`
- array becomes `[1,-1,3,4]`

`i = 1` again:

- `nums[1] = -1`, stop

`i = 2` and `i = 3` are already fine.

Now scan from left to right:

- index `0` has `1`, correct
- index `1` has `-1`, but it should have `2`

So the method returns `2`.

### Key Variables Explained

- `n`: array length, which also defines the only relevant value range `1...n`
- `i`: current index being fixed
- `correctIndex`: target position where `nums[i]` belongs
- `temp`: temporary variable used during swapping
- `nums`: reused in place as both input storage and presence map

### Why This Works

Whenever the `while` condition is true, a swap places at least one valid number into its final correct position. That means the algorithm keeps making real progress and cannot loop forever unless a duplicate is already sitting in its target slot, which is exactly why `nums[nums[i] - 1] != nums[i]` is checked.

After the first loop finishes, every value that could be placed correctly has been placed correctly. Therefore, the first index `i` where `nums[i] != i + 1` proves that `i + 1` never appeared in the proper slot and is the smallest missing positive.

### Trick Used

The array itself is used as an in-place hash table by mapping value `x` to index `x - 1`.

### Edge Cases Handled

- **Negative numbers and zero:** ignored by `nums[i] > 0`
- **Values larger than `n`:** ignored by `nums[i] <= n`
- **Duplicates:** prevented from infinite swapping by `nums[nums[i] - 1] != nums[i]`
- **All values `1...n` present:** the method returns `n + 1`

### Complexity Analysis

- **Time Complexity: `O(n)`** — although there is a `while` inside the `for`, each successful swap places a number into its correct position, so the total number of swaps across the entire array is linear.
- **Space Complexity: `O(1)`** — only a few variables (`n`, `i`, `correctIndex`, `temp`) are used beyond the input array.
