You are given an array of strings `tokens` that represents an arithmetic expression in a Reverse Polish Notation.

Evaluate the expression. Return _an integer that represents the value of the expression_.

**Note** that:

- The valid operators are `'+'`, `'-'`, `'*'`, and `'/'`.

- Each operand may be an integer or another expression.

- The division between two integers always **truncates toward zero**.

- There will not be any division by zero.

- The input represents a valid arithmetic expression in a reverse polish notation.

- The answer and all the intermediate calculations can be represented in a **32-bit** integer.

**Example 1:**

```
Input: tokens = ["2","1","+","3","*"]
Output: 9
Explanation: ((2 + 1) * 3) = 9
```

**Example 2:**

```
Input: tokens = ["4","13","5","/","+"]
Output: 6
Explanation: (4 + (13 / 5)) = 6
```

**Example 3:**

```
Input: tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
Output: 22
Explanation: ((10 * (6 / ((9 + 3) * -11))) + 17) + 5
= ((10 * (6 / (12 * -11))) + 17) + 5
= ((10 * (6 / -132)) + 17) + 5
= ((10 * 0) + 17) + 5
= (0 + 17) + 5
= 17 + 5
= 22
```

**Constraints:**

- `1 <= tokens.length <= 10^4`

- `tokens[i]` is either an operator: `"+"`, `"-"`, `"*"`, or `"/"`, or an integer in the range `[-200, 200]`.

## Java Solution

```java
package stack;

import java.util.Stack;

public class EvaluateReversePolishNotation {
    public int evalRPN(String[] tokens) {
        Stack<Integer> stack = new Stack<>();

        for (String token : tokens) {
            if (isOperator(token)) {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(applyOperator(a, b, token));
            } else {
                stack.push(Integer.parseInt(token));
            }
        }

        return stack.pop();
    }

    private boolean isOperator(String token) {
        return token.equals("+") || token.equals("-") || token.equals("*") || token.equals("/");
    }

    private int applyOperator(int a, int b, String operator) {
        return switch (operator) {
            case "+" -> a + b;
            case "-" -> a - b;
            case "*" -> a * b;
            case "/" -> a / b;
            default -> throw new IllegalArgumentException("Invalid operator: " + operator);
        };
    }
}
```

## Explanation

### Problem Analysis

Reverse Polish Notation places each operator after its operands, so parentheses are unnecessary. The task is to evaluate the expression in that order and return the final integer result.

This is a classic interview problem because it is a very direct test of stack usage and careful handling of operand order for non-commutative operations like subtraction and division.

### Approach

The code scans the `tokens` array from left to right:

- if the token is a number, push it onto the stack
- if the token is an operator, pop the top two numbers, apply the operator, and push the result back

This works because in Reverse Polish Notation, whenever an operator appears, the two most recent unresolved values are exactly its operands.

### Pattern Used

This solution uses the **stack evaluation** pattern.

### Key Insight

A stack naturally stores partially evaluated subexpressions, and every operator combines the two most recent ones into a new single value.

### Code Walkthrough

The method starts with:

- `Stack<Integer> stack = new Stack<>();`

Then it iterates:

```java
for (String token : tokens)
```

For each `token`, the code checks `isOperator(token)`.

If it is an operator:

- `int b = stack.pop();`
- `int a = stack.pop();`
- `stack.push(applyOperator(a, b, token));`

The order matters:

- `a - b` is not the same as `b - a`
- `a / b` is not the same as `b / a`

If it is not an operator:

- `stack.push(Integer.parseInt(token));`

After the loop, the only value left is the answer, so the method returns `stack.pop()`.

The helper method `isOperator(String token)` checks whether the token is one of:

- `"+"`
- `"-"`
- `"*"`
- `"/"`

The helper method `applyOperator(int a, int b, String operator)` uses a `switch` expression to perform the correct arithmetic operation.

### Example Walkthrough

Use **Example 1**:

```text
tokens = ["2","1","+","3","*"]
```

Step by step:

- read `"2"` -> push `2`; stack = `[2]`
- read `"1"` -> push `1`; stack = `[2, 1]`
- read `"+"` -> pop `b = 1`, pop `a = 2`, compute `2 + 1 = 3`, push `3`; stack = `[3]`
- read `"3"` -> push `3`; stack = `[3, 3]`
- read `"*"` -> pop `b = 3`, pop `a = 3`, compute `3 * 3 = 9`, push `9`; stack = `[9]`

Return `9`.

### Key Variables Explained

- `stack` — stores numbers and partial expression results
- `token` — current string from the input array
- `a` — left operand popped from the stack
- `b` — right operand popped from the stack
- `operator` — the arithmetic symbol passed into `applyOperator(...)`

### Why This Works

The stack invariant is that after processing any prefix of `tokens`, the stack contains the correct values of all unresolved subexpressions from that prefix.

When a number appears, it becomes a new unresolved value. When an operator appears, the two top stack values are exactly the completed operands for that operator, so combining them and pushing the result preserves the invariant.

By the time the loop ends, the entire expression has been reduced to one value, which must be the final answer.

### Trick Used

The trick is **separating operator detection into `isOperator(...)` and arithmetic execution into `applyOperator(...)`**, which keeps the main loop simple and makes operand order explicit.

### Edge Cases Handled

- **Negative operands** like `"-11"` — not mistaken for operators because `isOperator(...)` only matches the four exact operator strings
- **Single-number expressions** — the loop pushes one value and returns it
- **Subtraction and division order** — preserved by popping `b` first and `a` second
- **Integer truncation for division** — Java integer division already truncates toward zero

### Complexity Analysis

- **Time Complexity: `O(n)`** — each token is processed once, with constant-time stack work per token
- **Space Complexity: `O(n)`** — in the worst case, the stack can hold many operands before operators reduce them
