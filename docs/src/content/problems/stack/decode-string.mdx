Given an encoded string, return its decoded string.

The encoding rule is: `k[encoded_string]`, where the `encoded_string` inside the square brackets is being repeated exactly `k` times. Note that `k` is guaranteed to be a positive integer.

You may assume that the input string is always valid; there are no extra white spaces, square brackets are well-formed, etc. Furthermore, you may assume that the original data does not contain any digits and that digits are only for those repeat numbers, `k`. For example, there will not be input like `3a` or `2[4]`.

The test cases are generated so that the length of the output will never exceed `10^5`.

**Example 1:**

```
Input: s = "3[a]2[bc]"
Output: "aaabcbc"
```

**Example 2:**

```
Input: s = "3[a2[c]]"
Output: "accaccacc"
```

**Example 3:**

```
Input: s = "2[abc]3[cd]ef"
Output: "abcabccdcdcdef"
```

**Constraints:**

- `1 <= s.length <= 30`

- `s` consists of lowercase English letters, digits, and square brackets `'[]'`.

- `s` is guaranteed to be **a valid** input.

- All the integers in `s` are in the range `[1, 300]`.

## Java Solution

```java
package stack;

import java.util.Stack;

public class DecodeString {
    public String decodeString(String s) {
        Stack<Integer> countStack = new Stack<>();
        Stack<StringBuilder> stringStack = new Stack<>();
        StringBuilder current = new StringBuilder();
        int k = 0;
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                k = k * 10 + (c - '0');
            } else if (c == '[') {
                countStack.push(k);
                stringStack.push(current);
                current = new StringBuilder();
                k = 0;
            } else if (c == ']') {
                StringBuilder decodedString = stringStack.pop();
                int repeatCount = countStack.pop();
                decodedString.append(String.valueOf(current).repeat(repeatCount));
                current = decodedString;
            } else {
                current.append(c);
            }
        }
        return current.toString();
    }
}
```

## Explanation

### Problem Analysis

The input is an encoded string where segments like `k[encoded_string]` must be expanded exactly `k` times. The main difficulty is that brackets can be nested, so inner decoded pieces must be finished before outer ones.

This is a popular interview question because it tests stack-based parsing, nested state management, and handling multi-digit repeat counts.

### Approach

The code keeps track of two kinds of state:

- how many times the current bracketed substring should repeat
- what string had already been built before entering that bracket

Whenever `[` appears, the current repeat count and current partial string are saved onto stacks. Whenever `]` appears, the code decodes the current bracketed content and appends it back to the previous saved string.

This is much cleaner than trying to recursively slice substrings by index.

### Pattern Used

This solution uses the **stack-based parsing** pattern.

### Key Insight

Every `[` starts a brand-new local decoding context, so saving the old `current` string and repeat count is enough to rebuild the correct outer string when `]` is reached.

### Code Walkthrough

The method initializes:

- `Stack<Integer> countStack = new Stack<>();`
- `Stack<StringBuilder> stringStack = new Stack<>();`
- `StringBuilder current = new StringBuilder();`
- `int k = 0;`

Then it scans each character with:

```java
for (char c : s.toCharArray())
```

Case 1: digit

- `k = k * 10 + (c - '0')`

This allows counts like `12[...]`, not just single-digit counts.

Case 2: opening bracket `'['`

- `countStack.push(k);`
- `stringStack.push(current);`
- `current = new StringBuilder();`
- `k = 0;`

This stores the outer context and starts a fresh inner substring.

Case 3: closing bracket `']'`

- `StringBuilder decodedString = stringStack.pop();`
- `int repeatCount = countStack.pop();`
- `decodedString.append(String.valueOf(current).repeat(repeatCount));`
- `current = decodedString;`

So the just-decoded inner content is repeated and attached to the saved outer string.

Case 4: regular letter

- `current.append(c);`

After the loop, `current.toString()` is the final decoded string.

### Example Walkthrough

Use **Example 2**:

```text
s = "3[a2[c]]"
```

Step by step:

- read `'3'` -> `k = 3`
- read `'['` -> push `3` to `countStack`, push current `""` to `stringStack`, reset `current = ""`
- read `'a'` -> `current = "a"`
- read `'2'` -> `k = 2`
- read `'['` -> push `2`, push current `"a"`, reset `current = ""`
- read `'c'` -> `current = "c"`
- read `']'` -> pop repeat count `2`, pop previous string `"a"`, build `"a" + "c".repeat(2)` = `"acc"`, so `current = "acc"`
- read final `']'` -> pop repeat count `3`, pop previous string `""`, build `"" + "acc".repeat(3)` = `"accaccacc"`

Return:

```text
"accaccacc"
```

### Key Variables Explained

- `countStack` — stores repeat counts for unfinished bracket levels
- `stringStack` — stores the string built before each `[` appears
- `current` — the substring currently being decoded at the active nesting level
- `k` — the repeat count currently being built from digits
- `decodedString` — the restored outer string used when a `]` is processed

### Why This Works

At any moment, `current` represents the decoded content of the current bracket level only. The stacks store everything needed to return to the previous level:

- `countStack` remembers how many times to repeat the inner result
- `stringStack` remembers what had already been built outside the brackets

When `]` appears, the current inner result is complete, so repeating it and appending it to the saved outer prefix is exactly what the encoding rule requires.

### Trick Used

The trick is **using two synchronized stacks: one for repeat counts and one for the partial strings that existed before each `[`**.

### Edge Cases Handled

- **Nested encodings** like `"3[a2[c]]"` — each level gets its own saved context
- **Multi-digit repeat counts** — handled by `k = k * 10 + (c - '0')`
- **Plain letters outside brackets** — appended directly to `current`
- **Suffix text after encoded blocks** like `"2[abc]3[cd]ef"` — final letters continue appending normally

### Complexity Analysis

- **Time Complexity: `O(n + m)`** — the input of length `n` is scanned once, and producing the decoded output of length `m` requires materializing those characters
- **Space Complexity: `O(n + m)`** — the stacks hold nested state, and the decoded `StringBuilder` content can grow to the full output size
