Serialization is the process of converting a data structure or object into a sequence of bits so that it can be stored in a file or memory buffer, or transmitted across a network connection link to be reconstructed later in the same or another computer environment.

Design an algorithm to serialize and deserialize a binary tree. There is no restriction on how your serialization/deserialization algorithm should work. You just need to ensure that a binary tree can be serialized to a string and this string can be deserialized to the original tree structure.

**Clarification:** The input/output format is the same as how LeetCode serializes a binary tree. You do not necessarily need to follow this format, so please be creative and come up with different approaches yourself.

**Example 1:**

```
Input: root = [1,2,3,null,null,4,5]
Output: [1,2,3,null,null,4,5]
```

**Example 2:**

```
Input: root = []
Output: []
```

**Constraints:**

- The number of nodes in the tree is in the range `[0, 10^4]`.

- `-1000 <= Node.val <= 1000`

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_tree;

public class SerializeAndDeserializeBinaryTree {
    // Encodes a tree to a single string.
    public String serialize(TreeNode root) {
        StringBuilder sb = new StringBuilder();
        serializeHelper(root, sb);
        return sb.toString();
    }

    private void serializeHelper(TreeNode node, StringBuilder sb) {
        if (node == null) {
            sb.append("null,");
            return;
        }
        sb.append(node.val).append(",");
        serializeHelper(node.left, sb);
        serializeHelper(node.right, sb);
    }

    // Decodes your encoded data to tree.
    public TreeNode deserialize(String data) {
        String[] nodes = data.split(",");
        return deserializeHelper(nodes, new int[]{0});
    }

    private TreeNode deserializeHelper(String[] nodes, int[] index) {
        if (index[0] >= nodes.length || nodes[index[0]].equals("null")) {
            index[0]++;
            return null;
        }
        TreeNode node = new TreeNode(Integer.parseInt(nodes[index[0]++]));
        node.left = deserializeHelper(nodes, index);
        node.right = deserializeHelper(nodes, index);
        return node;
    }
}
```

## Explanation

### Problem Analysis
This problem asks us to convert a binary tree into a string and then rebuild the exact same tree from that string. The important requirement is not a specific format, but that the structure and values are preserved perfectly.

It is a favorite interview design problem because it tests whether you can choose a traversal order that captures both node values and missing children. Without recording nulls, many different trees could produce the same sequence.

### Approach
The code uses preorder DFS for both operations.

- During serialization, it writes the current node value first, then serializes the left subtree, then the right subtree.
- For missing children, it writes the marker `"null,"`.

That null marker is what makes deserialization possible. A brute-force idea that records only values would lose structure, but preorder plus null placeholders gives a one-to-one representation of the tree.

### Pattern Used
DFS recursion with preorder traversal.

### Key Insight
Preorder traversal combined with explicit `null` markers contains enough information to reconstruct the exact original tree.

### Code Walkthrough
In `serialize(TreeNode root)`:

- A `StringBuilder sb = new StringBuilder();` is created.
- `serializeHelper(root, sb);` fills it recursively.
- `sb.toString()` is returned as the encoded tree.

In `serializeHelper(TreeNode node, StringBuilder sb)`:

- `if (node == null) { sb.append("null,"); return; }`
  - Missing children are written explicitly.

- Otherwise:
  - `sb.append(node.val).append(",");`
  - `serializeHelper(node.left, sb);`
  - `serializeHelper(node.right, sb);`

This is preorder because the current node is written before its children.

In `deserialize(String data)`:

- `String[] nodes = data.split(",");`
  - The serialized string is broken into tokens.

- `return deserializeHelper(nodes, new int[]{0});`
  - The array `new int[]{0}` acts as a mutable index shared across recursive calls.

In `deserializeHelper(String[] nodes, int[] index)`:

- `if (index[0] >= nodes.length || nodes[index[0]].equals("null"))`
  - If the current token is `null`, this subtree is empty.
  - `index[0]++` moves to the next token, then `null` is returned.

- Otherwise:
  - `TreeNode node = new TreeNode(Integer.parseInt(nodes[index[0]++]));`
  - A real node is created from the current token.
  - `node.left = deserializeHelper(nodes, index);`
  - `node.right = deserializeHelper(nodes, index);`
  - The subtree is rebuilt in the same preorder order it was encoded.

### Example Walkthrough
Use Example 1: `root = [1,2,3,null,null,4,5]`.

Serialization proceeds in preorder:

- visit `1`  -> append `1,`
- visit `2`  -> append `2,`
- left of `2` is null  -> append `null,`
- right of `2` is null -> append `null,`
- visit `3`  -> append `3,`
- visit `4`  -> append `4,`
- left of `4` is null  -> append `null,`
- right of `4` is null -> append `null,`
- visit `5`  -> append `5,`
- left of `5` is null  -> append `null,`
- right of `5` is null -> append `null,`

The serialized form becomes:

- `1,2,null,null,3,4,null,null,5,null,null,`

Now deserialization reads that sequence in the same order:

- token `1` creates the root
- token `2` becomes `root.left`
- next two `null` tokens make `2` a leaf
- token `3` becomes `root.right`
- token `4` becomes `3.left`
- two `null` tokens finish node `4`
- token `5` becomes `3.right`
- two `null` tokens finish node `5`

The rebuilt tree matches the original structure exactly.

### Key Variables Explained
- `sb`: accumulates the serialized tree string efficiently.
- `node`: current tree node being serialized or reconstructed.
- `nodes`: tokenized serialized data used during deserialization.
- `index`: one-element array used as a mutable pointer into `nodes` across recursive calls.

### Why This Works
Serialization writes nodes in preorder and records every missing child explicitly. That means the output fully describes both value order and tree shape.

Deserialization consumes tokens in the exact same preorder sequence. Whenever it sees a real value, it creates a node and recursively builds its left and right children. Whenever it sees `null`, it knows that branch ends there. Because the reading order mirrors the writing order exactly, the reconstructed tree must be identical to the original.

### Trick Used
Using an `int[]` with one element as a mutable recursion index shared across deserialization calls.

### Edge Cases Handled
- Empty tree: serialization writes `null,`, and deserialization returns `null`.
- Leaf nodes: both children become `null` tokens, so structure is preserved.
- Negative values: `Integer.parseInt(...)` handles them correctly.
- Deeply nested trees: recursion still processes the structure correctly in preorder.

### Complexity Analysis
- **Time Complexity: `O(n)`**
  - Serialization visits each node once and also processes each null child marker a constant number of times.
  - Deserialization reads each token once.

- **Space Complexity: `O(n)`**
  - The serialized string stores the whole tree representation.
  - Deserialization uses the token array `nodes`, and recursion can use up to `O(h)` call stack space.
