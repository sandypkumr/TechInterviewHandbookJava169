Given the `root` of a binary tree, return _the length of the **diameter** of the tree_.

The **diameter** of a binary tree is the **length** of the longest path between any two nodes in a tree. This path may or may not pass through the `root`.

The **length** of a path between two nodes is represented by the number of edges between them.

**Example 1:**

```
Input: root = [1,2,3,4,5]
Output: 3
Explanation: 3 is the length of the path [4,2,1,3] or [5,2,1,3].
```

**Example 2:**

```
Input: root = [1,2]
Output: 1
```

**Constraints:**

- The number of nodes in the tree is in the range `[1, 10^4]`.

- `-100 <= Node.val <= 100`

## Java Solution

```java
package binary_tree;

public class DiameterOfBinaryTree {
    public int diameterOfBinaryTree(TreeNode root) {
        int[] diameter = new int[1]; // Use an array to store the diameter
        calculateHeight(root, diameter);
        return diameter[0];
    }

    private int calculateHeight(TreeNode node, int[] diameter) {
        if (node == null) {
            return 0;
        }

        int leftHeight = calculateHeight(node.left, diameter);
        int rightHeight = calculateHeight(node.right, diameter);

        // Update the diameter if the path through the current node is larger
        diameter[0] = Math.max(diameter[0], leftHeight + rightHeight);

        // Return the height of the current node
        return Math.max(leftHeight, rightHeight) + 1;
    }
}
```

## Explanation

### Problem Analysis
The diameter is the number of edges on the longest path between any two nodes in the tree. That path can pass through the root, but it does not have to, so checking only root-based paths is not enough.

This is a standard interview problem because it tests whether you can combine local subtree information into a global answer during DFS.

### Approach
The code computes the height of every subtree and, at the same time, updates the best diameter found so far. For each node, the longest path passing through that node is `leftHeight + rightHeight`.

This is better than recomputing heights separately for every node, which would repeat work and become inefficient.

### Pattern Used
Depth-First Search (DFS) with postorder recursion.

### Key Insight
If you know the heights of the left and right subtrees, then the longest path through the current node is simply their sum in edges.

### Code Walkthrough
`diameterOfBinaryTree(TreeNode root)` creates `int[] diameter = new int[1]` to hold the best answer across recursive calls.

It calls `calculateHeight(root, diameter)` and returns `diameter[0]` at the end.

In `calculateHeight(TreeNode node, int[] diameter)`, the base case `if (node == null) return 0;` defines the height of an empty subtree.

The recursive calls `calculateHeight(node.left, diameter)` and `calculateHeight(node.right, diameter)` compute `leftHeight` and `rightHeight` first.

Once both heights are known, `diameter[0] = Math.max(diameter[0], leftHeight + rightHeight);` checks whether the path going left -> node -> right is the longest one seen so far.

Finally, `return Math.max(leftHeight, rightHeight) + 1;` returns the height of the current subtree to the parent.

That makes this a postorder-style DFS: children are processed before the current node uses their results.

### Example Walkthrough
Use Example 1: `root = [1,2,3,4,5]`.

Start at the leaves:
- Node `4` returns height `1`
- Node `5` returns height `1`
- Node `3` returns height `1`

At node `2`:
- `leftHeight = 1` from node `4`
- `rightHeight = 1` from node `5`
- Candidate diameter through `2` is `2`
- Return height `2`

At node `1`:
- `leftHeight = 2` from node `2`
- `rightHeight = 1` from node `3`
- Candidate diameter through `1` is `3`
- Update `diameter[0]` to `3`
- Return height `3`

The final answer is `3`, matching the path `[4,2,1,3]` or `[5,2,1,3]`.

### Key Variables Explained
- `diameter`: single-element array storing the maximum diameter found so far.
- `node`: current tree node in the DFS.
- `leftHeight`: height returned from the left subtree.
- `rightHeight`: height returned from the right subtree.

### Why This Works
Every possible longest path has a highest turning point where it goes from one side of a subtree to the other. When DFS reaches that node, the code computes exactly that path length as `leftHeight + rightHeight`.

Because the recursion evaluates every node once and updates `diameter[0]` at each node, the global maximum path is guaranteed to be captured.

### Trick Used
The trick is using `int[] diameter = new int[1]` so recursive calls can update a shared answer without needing a wrapper object.

### Edge Cases Handled
- Single-node tree: both child heights are `0`, so the diameter remains `0`.
- Missing child on one side: the null child contributes height `0`, so the path length is still computed correctly.
- Diameter not passing through the root: updating `diameter[0]` at every node ensures such cases are included.

### Complexity Analysis
- Time Complexity: `O(n)` because `calculateHeight` visits each node exactly once and does constant work there.
- Space Complexity: `O(h)` for the recursion stack, where `h` is the tree height; in the worst-case skewed tree, this becomes `O(n)`.
