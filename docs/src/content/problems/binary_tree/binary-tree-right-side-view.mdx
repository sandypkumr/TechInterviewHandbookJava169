Given the `root` of a binary tree, imagine yourself standing on the **right side** of it, return _the values of the nodes you can see ordered from top to bottom_.

**Example 1:**

**Input:** root = [1,2,3,null,5,null,4]

**Output:** [1,3,4]

**Explanation:**

**Example 2:**

**Input:** root = [1,2,3,4,null,null,null,5]

**Output:** [1,3,4,5]

**Explanation:**

**Example 3:**

**Input:** root = [1,null,3]

**Output:** [1,3]

**Example 4:**

**Input:** root = []

**Output:** []

**Constraints:**

- The number of nodes in the tree is in the range `[0, 100]`.

- `-100 <= Node.val <= 100`

**Patterns:** `bfs`

## Java Solution

```java
package binary_tree;

import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;

public class BinaryTreeRightSideView {
    public List<Integer> rightSideView(TreeNode root) {
        List<Integer> result = new ArrayList<>();
        if (root == null) {
            return result;
        }
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size();
            for (int i = 0; i < size; i++) {
                TreeNode node = queue.poll();
                if (i == size - 1) {
                    result.add(node.val);
                }
                if (node.left != null) {
                    queue.offer(node.left);
                }
                if (node.right != null) {
                    queue.offer(node.right);
                }
            }
        }
        return result;
    }
}
```

## Explanation

### Problem Analysis
The task asks for the nodes visible when the tree is viewed from the right side, from top to bottom. That means for every depth, we only want the last node seen in that level-order sweep.

This is a common interview problem because it checks whether you can map a visual tree requirement into level-by-level traversal logic.

### Approach
The code uses Breadth-First Search so it can process one level at a time. Once a full level is isolated, the right-side answer for that level is simply the last node removed from the queue.

This is cleaner than a brute-force "simulate visibility" idea because BFS already groups nodes by depth naturally.

### Pattern Used
Breadth-First Search (BFS) / level-order traversal.

### Key Insight
If you process the tree level by level, the node at index `size - 1` for that level is exactly the node visible from the right side.

### Code Walkthrough
`rightSideView(TreeNode root)` starts by creating `result` to store the visible values.

If `root == null`, it immediately returns `result`, which correctly handles the empty tree case.

A `Queue<TreeNode> queue = new LinkedList<>()` is used for BFS, and `queue.offer(root)` seeds the traversal.

The outer `while (!queue.isEmpty())` loop processes one level per iteration.

At the start of each level, `int size = queue.size()` captures how many nodes belong to the current depth.

The `for (int i = 0; i < size; i++)` loop removes exactly those nodes.

Inside the loop, `TreeNode node = queue.poll()` takes the next node from the current level.

When `i == size - 1`, that node is the last one in this level, so `result.add(node.val)` records the right-side view.

Then the code enqueues `node.left` and `node.right` if they exist, preparing the next level in left-to-right order.

After all levels are processed, `result` is returned.

### Example Walkthrough
Use Example 1: `root = [1,2,3,null,5,null,4]`.

Start with `queue = [1]` and `result = []`.

Level 1:
- `size = 1`
- Poll `1`; since `i == 0 == size - 1`, add `1`
- Enqueue `2`, `3`
- `result = [1]`

Level 2:
- `queue = [2,3]`, `size = 2`
- Poll `2`; not the last node, so do not add it
- Enqueue `5`
- Poll `3`; this is the last node of the level, so add `3`
- Enqueue `4`
- `result = [1,3]`

Level 3:
- `queue = [5,4]`, `size = 2`
- Poll `5`; not the last node
- Poll `4`; last node, so add `4`
- `result = [1,3,4]`

The final answer is `[1,3,4]`.

### Key Variables Explained
- `result`: stores the rightmost value from each level.
- `queue`: holds nodes waiting to be processed in BFS order.
- `size`: number of nodes in the current level.
- `i`: loop index used to detect the last node of the level.
- `node`: the current node removed from the queue.

### Why This Works
BFS guarantees that nodes are processed depth by depth. Because `size` freezes the current level boundary before the loop starts, the node visited when `i == size - 1` must be the final node at that depth.

Since children are only enqueued for the next level, no node from another depth can interfere with that decision.

### Trick Used
The small trick is capturing `size = queue.size()` before the inner loop, which lets the code isolate one level and pick its last node.

### Edge Cases Handled
- Empty tree: `if (root == null)` returns an empty list.
- Single-node tree: that only node is also the last node of its level, so it is added.
- Missing children: `if (node.left != null)` and `if (node.right != null)` avoid null entries in the queue.

### Complexity Analysis
- Time Complexity: `O(n)` because every node is enqueued and dequeued exactly once.
- Space Complexity: `O(n)` in the worst case because the queue can hold an entire level of the tree, and `result` also stores up to one value per level.
