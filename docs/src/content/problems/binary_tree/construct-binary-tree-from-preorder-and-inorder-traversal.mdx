Given two integer arrays `preorder` and `inorder` where `preorder` is the preorder traversal of a binary tree and `inorder` is the inorder traversal of the same tree, construct and return _the binary tree_.

**Example 1:**

```
Input: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]
Output: [3,9,20,null,null,15,7]
```

**Example 2:**

```
Input: preorder = [-1], inorder = [-1]
Output: [-1]
```

**Constraints:**

- `1 <= preorder.length <= 3000`

- `inorder.length == preorder.length`

- `-3000 <= preorder[i], inorder[i] <= 3000`

- `preorder` and `inorder` consist of **unique** values.

- Each value of `inorder` also appears in `preorder`.

- `preorder` is **guaranteed** to be the preorder traversal of the tree.

- `inorder` is **guaranteed** to be the inorder traversal of the tree.

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_tree;

public class ConstructBinaryTreeFromPreorderAndInOrderTraversal {
    public TreeNode buildTree(int[] preorder, int[] inorder) {
        return buildTree(preorder, 0, preorder.length - 1,
                inorder, 0, inorder.length - 1);
    }

    private TreeNode buildTree(int[] preorder, int preStart, int preEnd,
                               int[] inorder, int inStart, int inEnd) {
        if (preStart > preEnd || inStart > inEnd) {
            return null;
        }
        TreeNode root = new TreeNode(preorder[preStart]);
        int rootIndex = findRootIndex(inorder, inStart, inEnd, root.val);
        int leftTreeSize = rootIndex - inStart;
        root.left = buildTree(preorder, preStart + 1, preStart + leftTreeSize,
                inorder, inStart, rootIndex - 1);
        root.right = buildTree(preorder, preStart + leftTreeSize + 1, preEnd,
                inorder, rootIndex + 1, inEnd);
        return root;
    }

    private int findRootIndex(int[] inorder, int start, int end, int value) {
        for (int i = start; i <= end; i++) {
            if (inorder[i] == value) {
                return i;
            }
        }
        return -1;
    }
}
```

## Explanation

### Problem Analysis
We are given preorder and inorder traversals of the same binary tree and need to rebuild the original tree. The challenge is to figure out where each subtree starts and ends without actually seeing the tree structure.

This is a classic interview problem because it tests recursive thinking, traversal properties, and careful index management.

### Approach
The solution uses recursion with index ranges instead of creating subarrays. In preorder, the first element of any range is the root; in inorder, that root splits the array into the left subtree and right subtree.

This is much better than trying all possible trees because the traversal rules uniquely determine the structure when values are unique.

### Pattern Used
Depth-First Search (DFS) with divide and conquer.

### Key Insight
The first value in the current preorder slice is always the root, and its position in the current inorder slice tells you exactly how many nodes belong to the left subtree.

### Code Walkthrough
`buildTree(int[] preorder, int[] inorder)` is the public entry point.

It immediately calls the helper `buildTree(preorder, 0, preorder.length - 1, inorder, 0, inorder.length - 1)` so the entire two arrays are treated as the initial ranges.

The helper method receives six boundaries: `preStart`, `preEnd`, `inStart`, and `inEnd` define the current subtree inside both traversals.

The base case is `if (preStart > preEnd || inStart > inEnd) return null;`. That means the current subtree has no nodes.

`TreeNode root = new TreeNode(preorder[preStart]);` creates the root from the first preorder value in the current range.

`int rootIndex = findRootIndex(inorder, inStart, inEnd, root.val);` searches for that root inside the current inorder segment.

`int leftTreeSize = rootIndex - inStart;` computes how many nodes belong to the left subtree.

The left subtree is built with `preStart + 1` through `preStart + leftTreeSize` in preorder and `inStart` through `rootIndex - 1` in inorder.

The right subtree is built with `preStart + leftTreeSize + 1` through `preEnd` in preorder and `rootIndex + 1` through `inEnd` in inorder.

Finally, the method returns `root` after attaching `root.left` and `root.right`.

`findRootIndex(...)` performs a linear scan over the relevant inorder range to locate the current root value.

### Example Walkthrough
Use Example 1: `preorder = [3,9,20,15,7]`, `inorder = [9,3,15,20,7]`.

First call:
- `preStart = 0`, so root is `3`
- In inorder, `3` is at index `1`
- `leftTreeSize = 1`
- Left subtree uses preorder `[9]` and inorder `[9]`
- Right subtree uses preorder `[20,15,7]` and inorder `[15,20,7]`

Left subtree call:
- Root is `9`
- Its inorder position matches the single-element segment
- Both recursive child calls hit the base case, so `9` becomes a leaf

Right subtree call:
- Root is `20`
- In inorder `[15,20,7]`, `20` is in the middle
- Left subtree becomes `[15]`
- Right subtree becomes `[7]`

Those recursive calls create leaf nodes `15` and `7`, so the final tree is `[3,9,20,null,null,15,7]`.

### Key Variables Explained
- `preStart`, `preEnd`: boundaries of the current subtree inside `preorder`.
- `inStart`, `inEnd`: boundaries of the current subtree inside `inorder`.
- `root`: node created from `preorder[preStart]`.
- `rootIndex`: position of `root.val` inside the current inorder segment.
- `leftTreeSize`: number of nodes in the left subtree, used to split the preorder range.

### Why This Works
Preorder always visits root before its subtrees, so `preorder[preStart]` must be the current root. Inorder always lists left subtree, then root, then right subtree, so `rootIndex` gives an exact partition of the subtree.

Because the code passes matching index ranges into recursive calls, every node is assigned to exactly one subtree, and the reconstructed structure is the only tree consistent with both traversals.

### Trick Used
The key trick is passing index boundaries (`preStart`, `preEnd`, `inStart`, `inEnd`) instead of creating new subarrays at each recursive step.

### Edge Cases Handled
- Empty subtree during recursion: the base case returns `null`.
- Single-node subtree: `preStart == preEnd` creates one node and both child calls return `null`.
- Fully skewed trees: the range math still works even when one side has size `0` repeatedly.

### Complexity Analysis
- Time Complexity: `O(n^2)` in the worst case because `findRootIndex(...)` may scan up to `O(n)` elements for each of the `n` recursive node constructions.
- Space Complexity: `O(h)` for recursion depth, where `h` is the tree height; in the worst-case skewed tree, that becomes `O(n)`.
