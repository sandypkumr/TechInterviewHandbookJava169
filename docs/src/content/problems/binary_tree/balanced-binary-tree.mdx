Given a binary tree, determine if it is **height-balanced**.

A height-balanced binary tree is a binary tree in which the depth of the two subtrees of every node never differs by more than one.

**Example 1:**

```
Input: root = [3,9,20,null,null,15,7]
Output: true
```

**Example 2:**

```
Input: root = [1,2,2,3,3,null,null,4,4]
Output: false
```

**Example 3:**

```
Input: root = []
Output: true
```

**Constraints:**

- The number of nodes in the tree is in the range `[0, 5000]`.

- `-10^4 <= Node.val <= 10^4`

## Java Solution

```java
package binary_tree;

public class BalancedBinaryTree {
    public boolean isBalanced(TreeNode root) {
        return checkBalance(root) != -1;
    }

    private int checkBalance(TreeNode node) {
        if (node == null) {
            return 0;
        }

        int leftHeight = checkBalance(node.left);
        if (leftHeight == -1) {
            return -1; // Left subtree is not balanced
        }

        int rightHeight = checkBalance(node.right);
        if (rightHeight == -1) {
            return -1; // Right subtree is not balanced
        }

        if (Math.abs(leftHeight - rightHeight) > 1) {
            return -1; // Current node is not balanced
        }

        return Math.max(leftHeight, rightHeight) + 1; // Return the height of the tree
    }
}
```

## Explanation

### Problem Analysis

A balanced binary tree requires that at every node, the heights of the left and right subtrees differ by at most 1.

A naive approach would check this condition at each node but recompute subtree heights repeatedly, leading to `O(n²)` time complexity.

The optimal approach computes heights once while checking balance, combining both operations into a single pass.

### Approach

The solution uses a helper function `checkBalance` that returns:
- The height of the subtree if it is balanced
- `-1` if the subtree is unbalanced (sentinel value)

For each node:
1. Recursively check if the left subtree is balanced (get its height or -1)
2. If left is unbalanced, propagate -1 immediately (no need to check right)
3. Recursively check if the right subtree is balanced
4. If right is unbalanced, propagate -1 immediately
5. Check if the current node is balanced: `|leftHeight - rightHeight| <= 1`
6. If balanced, return the height; otherwise return -1

### Pattern Used

This solution uses **recursive tree traversal with early termination**.

The key pattern is combining the balance check with height calculation, using a sentinel return value (-1) to propagate unbalance information up the tree without recomputing heights.

### Key Insight

The key insight is that checking balance and computing height are interdependent:
- To check if a tree is balanced, we need heights of left and right subtrees
- We can compute heights while checking balance in a single traversal
- Use -1 as a signal to stop checking once unbalance is detected

This avoids redundant traversals: a naive solution might check each node's balance after separately computing all heights.

### Code Walkthrough

**`isBalanced` (entry point):**

```java
public boolean isBalanced(TreeNode root) {
    return checkBalance(root) != -1;
}
```

Returns `true` if the result is not -1 (meaning the tree is balanced).

**`checkBalance` (core logic):**

```java
private int checkBalance(TreeNode node) {
    if (node == null) {
        return 0;  // Empty tree has height 0 and is balanced
    }

    int leftHeight = checkBalance(node.left);
    if (leftHeight == -1) {
        return -1;  // Left subtree is unbalanced, propagate immediately
    }

    int rightHeight = checkBalance(node.right);
    if (rightHeight == -1) {
        return -1;  // Right subtree is unbalanced, propagate immediately
    }

    if (Math.abs(leftHeight - rightHeight) > 1) {
        return -1;  // Height difference exceeds 1, so not balanced
    }

    return Math.max(leftHeight, rightHeight) + 1;  // Return height of this subtree
}
```

1. Base case: `null` nodes have height 0 and don't violate balance.

2. Recursively check left subtree and get its height (or -1).
   - If -1 is returned, the left subtree is unbalanced; stop checking and return -1.

3. Recursively check right subtree and get its height (or -1).
   - If -1 is returned, the right subtree is unbalanced; stop checking and return -1.

4. Check if the current node's left and right subtrees are balanced:
   - Compare absolute difference of heights
   - If difference > 1, return -1 (unbalanced)

5. If balanced, return the height: `max(leftHeight, rightHeight) + 1`.
   - The height of this subtree is one more than the taller child

### Example Walkthrough

For `root = [3,9,20,null,null,15,7]`:

```
       3
      / \
     9   20
        /  \
       15   7
```

**Call stack (depth-first):**

1. `checkBalance(3)`
   - `checkBalance(9)` → `checkBalance(null)` returns 0; `checkBalance(null)` returns 0
     - Height difference: |0-0| = 0 ≤ 1 ✓
     - Returns 0 + 1 = 1 (height of node 9)

   - `checkBalance(20)` → `checkBalance(15)` returns 1 (leaf); `checkBalance(7)` returns 1 (leaf)
     - Height difference: |1-1| = 0 ≤ 1 ✓
     - Returns 1 + 1 = 2 (height of node 20)

   - Back at 3: leftHeight = 1, rightHeight = 2
     - Height difference: |1-2| = 1 ≤ 1 ✓
     - Returns 2 + 1 = 3

2. `isBalanced` checks: 3 != -1 → **true**

For `root = [1,2,2,3,3,null,null,4,4]`:

```
       1
      / \
     2   2
    / \
   3   3
  / \
 4   4
```

1. `checkBalance(1)`
   - `checkBalance(2 left)`
     - `checkBalance(3 left)` → checkBalance(4) returns 1; checkBalance(4) returns 1; height diff = 0; returns 2
     - `checkBalance(3 right)` → checkBalance(4) returns 1; checkBalance(4) returns 1; height diff = 0; returns 2
     - Height difference: |2-2| = 0 ≤ 1 ✓; returns 3

   - `checkBalance(2 right)` → both children null
     - Returns 1

   - Back at 1: leftHeight = 3, rightHeight = 1
     - Height difference: |3-1| = 2 > 1 ✗
     - Returns -1

2. `isBalanced` checks: -1 != -1 → **false**

### Key Variables Explained

- **`leftHeight`**: height of the left subtree (or -1 if unbalanced)
- **`rightHeight`**: height of the right subtree (or -1 if unbalanced)
- **`-1`**: sentinel value indicating unbalance (allows early termination)
- **`Math.abs(leftHeight - rightHeight)`**: absolute difference between subtree heights
- **`Math.max(leftHeight, rightHeight) + 1`**: height of current subtree (one more than the taller child)

### Why This Works

The recursion is correct because:

1. **Base case**: A `null` node is balanced with height 0.

2. **Inductive step**: If both subtrees are balanced (neither returns -1), we check if the current node maintains balance. If both are balanced AND the height difference is ≤ 1, the entire subtree rooted at the current node is balanced.

3. **Early termination**: The -1 sentinel allows us to stop checking as soon as unbalance is detected, avoiding redundant traversals.

4. **Single pass**: Heights are computed exactly once during the traversal, without separate preprocessing.

### Trick Used

The main trick is using -1 as a sentinel value:

```java
if (leftHeight == -1) {
    return -1;  // Propagate unbalance immediately
}
```

This eliminates the need for a separate boolean flag or exception handling. The return type `int` carries both information: valid heights (≥0) and the unbalanced state (-1).

### Edge Cases Handled

1. **Empty tree**: Returns 0 (height 0, which is balanced).
2. **Single node**: Both children are null (height 0), difference is 0, returns 1.
3. **Left-skewed tree**: Unbalance is detected early and -1 is propagated.
4. **Right-skewed tree**: Similarly detected and propagated.
5. **Perfect binary tree**: All balance checks pass; height is computed correctly.

### Complexity Analysis

- **Time Complexity: `O(n)`** — Each node is visited exactly once during the recursive traversal.

- **Space Complexity: `O(h)`** — The recursion stack depth is proportional to the height `h` of the tree. In a balanced tree, `h = log n`; in a skewed tree, `h = n`.
