Given the `root` of a binary tree and an integer `targetSum`, return _all **root-to-leaf** paths where the sum of the node values in the path equals_ `targetSum`.

Each path should be returned as a list of the node **values**, not node references.

A **root-to-leaf** path is a path starting from the root and ending at any leaf node. A **leaf** is a node with no children.

**Example 1:**

```
Input: root = [5,4,8,11,null,13,4,7,2,null,1], targetSum = 22
Output: [[5,4,11,2],[5,8,4,5]]
```

**Example 2:**

```
Input: root = [1,2,3], targetSum = 5
Output: []
```

**Example 3:**

```
Input: root = [1,2], targetSum = 0
Output: []
```

**Constraints:**

- The number of nodes in the tree is in the range `[0, 5000]`.

- `-1000 <= Node.val <= 1000`

- `-1000 <= targetSum <= 1000`

## Java Solution

```java
package binary_tree;

import java.util.ArrayList;
import java.util.List;

public class PathSum2 {
    public List<List<Integer>> pathSum(TreeNode root, int targetSum) {
        List<List<Integer>> result = new ArrayList<>();
        findPaths(root, targetSum, new ArrayList<>(), result);
        return result;
    }

    private void findPaths(TreeNode node, int targetSum, List<Integer> currentPath,
                           List<List<Integer>> result) {
        if (node == null) {
            return;
        }
        currentPath.add(node.val);
        if (node.left == null && node.right == null && node.val == targetSum) {
            result.add(new ArrayList<>(currentPath));
        } else {
            findPaths(node.left, targetSum - node.val, currentPath, result);
            findPaths(node.right, targetSum - node.val, currentPath, result);
        }
        currentPath.removeLast();
    }
}
```

## Explanation

### Problem Analysis

Find all root-to-leaf paths that sum to a target. This requires exploring every root-to-leaf path while maintaining a running sum, then collecting paths where the total equals the target. The key distinction from other path problems is that we must reach a leaf node for a valid path.

### Approach

Use DFS with backtracking:
1. Traverse from root toward leaves
2. Add each node's value to the current path
3. Subtract node's value from remaining target
4. At a leaf node, if remaining target equals zero, add path copy to result
5. Backtrack (remove from path) after exploring children

### Pattern Used

**DFS with backtracking** for enumerating all root-to-leaf paths and filtering valid ones.

### Key Insight

The key insight is treating this as a path-building problem where we accumulate nodes while decrementing the target. At leaves, a simple check (`node.val == targetSum`) determines if the path is valid. Backtracking correctly manages state through multiple branches.

### Code Walkthrough

**Entry point:**
```java

    return result;

```

Initializes result and calls helper with empty path.

**Recursive helper:**
```java
private void findPaths(TreeNode node, int targetSum, List<Integer> currentPath,
                       List<List<Integer>> result) {
    if (node == null) {
        return;  // Base case: null node, stop exploring
    }

    currentPath.add(node.val);  // Add current node to path

    if (node.left == null && node.right == null && node.val == targetSum) {
        // Leaf node and sum matches: add path to result
        result.add(new ArrayList<>(currentPath));
    } else {
        // Not a leaf or sum doesn't match: explore children
        findPaths(node.left, targetSum - node.val, currentPath, result);
        findPaths(node.right, targetSum - node.val, currentPath, result);
    }

    currentPath.removeLast();  // Backtrack
}
```

1. **Base case**: If node is null, return (end of path)
2. **Add node**: Add value to currentPath
3. **Check leaf**: If it's a leaf AND value equals remaining targetSum, save path
4. **Explore children**: Otherwise, recurse with targetSum decremented
5. **Backtrack**: Remove node from path to restore state for sibling exploration

### Example Walkthrough

For `root = [5,4,8,11,null,13,4,7,2,null,1], targetSum = 22`:

```
       5
      / \
     4   8
    /   / \
  11   13  4
  / \       \
 7   2       1
```

Path 1: `5 → 4 → 11 → 2`
- Start: sum=22, path=[]
- At 5: path=[5], targetSum=17
- At 4: path=[5,4], targetSum=13
- At 11: path=[5,4,11], targetSum=2
- At 2 (leaf): path=[5,4,11,2], 2==2 ✓ → add to result
- Backtrack

Path 2: `5 → 8 → 4 → 5` (note: different 4 node, right child of 8)
- Start: sum=22, path=[]
- At 5: path=[5], targetSum=17
- At 8: path=[5,8], targetSum=9
- At 4 (right): path=[5,8,4], targetSum=5
- At 1 (right, leaf): path=[5,8,4,1]? No wait, the node value is 1, not 5...

Actually looking at tree again: At 8 right child is 4, and 4 has right child 1. So path would be [5,8,4,1] with sum 18, not [5,8,4,5].

Let me recalculate based on actual array: `[5,4,8,11,null,13,4,7,2,null,1]`
- Level 0: 5
- Level 1: 4 (left of 5), 8 (right of 5)
- Level 2: 11 (left of 4), null, 13 (left of 8), 4 (right of 8)
- Level 3: 7, 2 (children of 11), null, null, null, null, 1 (right of 4 at level 2)

So paths:
- 5→4→11→7 = 27 (no)
- 5→4→11→2 = 22 ✓
- 5→8→13 = 26 (no, not leaf)
- 5→8→4→1 = 18 (no)

Output should include [5,4,11,2]. The second path in expected output [5,8,4,5] doesn't match the given tree structure. This must be an example error in the problem. The algorithm would correctly identify all matching paths regardless.

### Key Variables Explained

- **`targetSum`**: Remaining sum needed to reach target (decrements as we traverse)
- **`currentPath`**: List accumulating node values from root to current node
- **`result`**: List of all valid root-to-leaf paths found
- **`node.left == null && node.right == null`**: Condition for leaf node

### Why This Works

The algorithm is correct because:

1. **Complete exploration**: DFS explores all root-to-leaf paths
2. **Correct validation**: Leaf check ensures we only count complete paths
3. **Sum tracking**: Decrementing targetSum correctly tracks progress
4. **Backtracking**: Path list is properly restored after each branch
5. **No duplicates**: Each path is explored exactly once

### Trick Used

The main trick is using `removeLast()` for efficient backtracking:

```java
currentPath.removeLast();
```

This is O(1) with ArrayList (removes last element). It ensures the path state is correct for exploring sibling nodes.

### Edge Cases Handled

1. **Empty tree**: Returns empty result
2. **No matching paths**: Returns empty result
3. **Negative node values**: Handled correctly by subtraction
4. **Single-node tree matching**: Adds it if value equals targetSum
5. **Skewed tree**: Correctly traverses regardless of shape

### Complexity Analysis

- **Time Complexity: `O(n·h)`** — Visit each of n nodes, and for each path found, copy it (h elements). Worst case: many paths of height h
- **Space Complexity: `O(h)`** — Recursion stack depth plus currentPath storage
