Given the `root` of a binary tree and an integer `targetSum`, return _all **root-to-leaf** paths where the sum of the node values in the path equals _`targetSum`_. Each path should be returned as a list of the node **values**, not node references_.

A **root-to-leaf** path is a path starting from the root and ending at any leaf node. A **leaf** is a node with no children.

**Example 1:**

```
Input: root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
Output: [[5,4,11,2],[5,8,4,5]]
Explanation: There are two paths whose sum equals targetSum:
5 + 4 + 11 + 2 = 22
5 + 8 + 4 + 5 = 22
```

**Example 2:**

```
Input: root = [1,2,3], targetSum = 5
Output: []
```

**Example 3:**

```
Input: root = [1,2], targetSum = 0
Output: []
```

**Constraints:**

- The number of nodes in the tree is in the range `[0, 5000]`.

- `-1000 <= Node.val <= 1000`

- `-1000 <= targetSum <= 1000`

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_tree;

import java.util.ArrayList;
import java.util.List;

public class PathSum2 {
    public List<List<Integer>> pathSum(TreeNode root, int targetSum) {
        List<List<Integer>> result = new ArrayList<>();
        findPaths(root, targetSum, new ArrayList<>(), result);
        return result;
    }

    private void findPaths(TreeNode node, int targetSum, List<Integer> currentPath,
                           List<List<Integer>> result) {
        if (node == null) {
            return;
        }
        currentPath.add(node.val);
        if (node.left == null && node.right == null && node.val == targetSum) {
            result.add(new ArrayList<>(currentPath));
        } else {
            findPaths(node.left, targetSum - node.val, currentPath, result);
            findPaths(node.right, targetSum - node.val, currentPath, result);
        }
        currentPath.removeLast();
    }
}
```

## Explanation

### Problem Analysis
This problem asks for every root-to-leaf path whose node values add up to `targetSum`. Unlike the simpler yes/no path-sum problem, here we must collect all valid paths, not just detect one.

This is a common interview topic because it combines tree DFS with backtracking. You need to explore paths incrementally, keep state for the current path, and undo that state correctly when recursion returns.

### Approach
The code performs DFS from the root while maintaining two pieces of path state:

- the remaining `targetSum` still needed
- the current path stored in `currentPath`

Whenever recursion reaches a leaf, the code checks whether that leaf finishes the required sum. If it does, it copies the current path into `result`. This is better than brute-forcing all root-to-leaf paths first and summing them later because the running subtraction keeps the validation local to each recursive call.

### Pattern Used
DFS + Backtracking.

### Key Insight
Instead of recomputing path sums from scratch, subtract each visited node value from `targetSum`, so at a leaf you only need to check whether `node.val == targetSum`.

### Code Walkthrough
The main method is `pathSum(TreeNode root, int targetSum)`.

- It creates `List<List<Integer>> result = new ArrayList<>();`
  - This stores every valid root-to-leaf path.

- It calls `findPaths(root, targetSum, new ArrayList<>(), result);`
  - The empty list represents the path being built during DFS.

- Finally, it returns `result`.

Inside `findPaths(TreeNode node, int targetSum, List<Integer> currentPath, List<List<Integer>> result)`:

- `if (node == null) { return; }`
  - A null node cannot extend a valid path.

- `currentPath.add(node.val);`
  - The current node is included in the active root-to-current path.

- `if (node.left == null && node.right == null && node.val == targetSum)`
  - This checks two things together:
    - the node is a leaf
    - the remaining sum is exactly satisfied here
  - If true, `result.add(new ArrayList<>(currentPath));` stores a copy.

- `else { ... }`
  - If not a valid ending leaf, recursion continues:
    - `findPaths(node.left, targetSum - node.val, currentPath, result);`
    - `findPaths(node.right, targetSum - node.val, currentPath, result);`
  - The sum passed down is reduced by the current node value.

- `currentPath.removeLast();`
  - This is the backtracking step.
  - After both recursive calls finish, the current node is removed so the parent call can continue with a clean path.

### Example Walkthrough
Use Example 1: `root = [5,4,8,11,null,13,4,7,2,null,null,5,1]`, `targetSum = 22`.

Start at node `5`:

- `currentPath = [5]`
- remaining sum for children becomes `22 - 5 = 17`

Go left to `4`:

- `currentPath = [5,4]`
- remaining sum becomes `17 - 4 = 13`

Go left to `11`:

- `currentPath = [5,4,11]`
- remaining sum becomes `13 - 11 = 2`

Visit leaf `7`:

- `currentPath = [5,4,11,7]`
- `7 != 2`, so this path is rejected
- backtrack to `[5,4,11]`

Visit leaf `2`:

- `currentPath = [5,4,11,2]`
- leaf and `2 == 2`, so add `[5,4,11,2]` to `result`
- backtrack

Now explore the right side from `5` to `8` to `4` to `5`:

- path becomes `[5,8,4,5]`
- remaining sum at the leaf is exactly satisfied
- add `[5,8,4,5]` to `result`

The final result is `[[5,4,11,2],[5,8,4,5]]`.

### Key Variables Explained
- `result`: stores all valid root-to-leaf paths found so far.
- `currentPath`: mutable list representing the path from the root to `node`.
- `targetSum`: in each recursive call, this is the remaining sum still needed from the current node downward.
- `node`: current tree node being explored.

### Why This Works
At every recursive call, `currentPath` exactly matches the nodes on the current root-to-node path, and `targetSum` represents the remaining amount needed before entering this node. That invariant is preserved because the method adds `node.val` to the path and subtracts `node.val` before recursing further.

When the code reaches a leaf, the only valid time to store a path is when that leaf's value equals the remaining sum. Backtracking with `currentPath.removeLast()` restores the path to its previous state, so sibling branches are explored without contamination from earlier choices.

### Trick Used
Using backtracking with one shared `currentPath` list and copying it only when a valid leaf is found.

### Edge Cases Handled
- Empty tree: the initial call reaches `node == null`, so the method returns an empty `result`.
- Leaf that does not finish the sum: it is rejected because `node.val == targetSum` fails.
- Valid path only at a leaf: the code correctly avoids accepting partial root-to-internal-node sums.
- Multiple valid paths: each one is copied separately into `result`.

### Complexity Analysis
- **Time Complexity: `O(n + total output size)`**
  - Every node is visited once by `findPaths`.
  - Each valid path added to `result` requires copying `currentPath`.
  - In the worst case, this can grow to `O(n^2)` when the total size of stored paths is quadratic.

- **Space Complexity: `O(h)` auxiliary, excluding output**
  - The recursion stack and `currentPath` both follow the current tree height `h`.
  - If the returned paths are counted, output space depends on how many valid paths exist.
