Given the `root` of a binary tree, return _its maximum depth_.

A binary tree's **maximum depth** is the number of nodes along the longest path from the root node down to the farthest leaf node.

**Example 1:**

```
Input: root = [3,9,20,null,null,15,7]
Output: 3
```

**Example 2:**

```
Input: root = [1,null,2]
Output: 2
```

**Constraints:**

- The number of nodes in the tree is in the range `[0, 10^4]`.

- `-100 <= Node.val <= 100`

## Java Solution

```java
package binary_tree;

public class MaximumDepthOfBinaryTree {
    public int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }
        return Math.max(maxDepth(root.left), maxDepth(root.right)) + 1;
    }
}
```

## Explanation

### Problem Analysis
The task is to return the length of the longest root-to-leaf path in a binary tree. In other words, we need the height of the tree measured in nodes, not edges.

This is a classic interview problem because it checks whether you naturally model a tree in terms of smaller subtrees. If you can express the answer for a node using the answers of its children, recursion becomes the most direct solution.

### Approach
The code uses recursive DFS. For every node, it asks: what is the maximum depth of my left subtree, and what is the maximum depth of my right subtree?

A brute-force mindset is not even necessary here because the recursive structure already gives the optimal solution. Once we know the deepest path on both sides, the current node contributes `1` more level, so the answer is `max(leftDepth, rightDepth) + 1`.

### Pattern Used
DFS recursion on a binary tree.

### Key Insight
The maximum depth at any node is exactly one plus the larger of the maximum depths of its left and right children.

### Code Walkthrough
The public method is `maxDepth(TreeNode root)`.

- The first check is `if (root == null) { return 0; }`.
  - An empty tree has depth `0`.
  - This is also the base case that stops recursion at missing children.

- For a real node, the method returns:
  - `Math.max(maxDepth(root.left), maxDepth(root.right)) + 1`
  - `maxDepth(root.left)` computes the deepest path in the left subtree.
  - `maxDepth(root.right)` computes the deepest path in the right subtree.
  - `Math.max(...)` keeps the longer branch.
  - `+ 1` counts the current `root` node itself.

There are no extra data structures, counters, or helper methods. The recursion alone carries the whole computation.

### Example Walkthrough
Use Example 1: `root = [3,9,20,null,null,15,7]`.

- Start at node `3`.
- Recurse left to node `9`.
  - `9.left` is `null`, so that call returns `0`.
  - `9.right` is `null`, so that call returns `0`.
  - Node `9` returns `Math.max(0, 0) + 1 = 1`.

- Recurse right to node `20`.
  - Go left to `15`.
    - Both children are `null`, so node `15` returns `1`.
  - Go right to `7`.
    - Both children are `null`, so node `7` returns `1`.
  - Node `20` returns `Math.max(1, 1) + 1 = 2`.

- Back at node `3`:
  - left depth = `1`
  - right depth = `2`
  - result = `Math.max(1, 2) + 1 = 3`

So the output is `3`.

### Key Variables Explained
- `root`: the current tree node whose subtree depth is being computed.
- `root.left`: starting point of the left subtree recursion.
- `root.right`: starting point of the right subtree recursion.
- `Math.max(...)`: chooses the deeper subtree.

### Why This Works
For every node, any root-to-leaf path must continue either through the left child or the right child. The deepest valid path from that node therefore must be the deeper of those two subtree depths, plus the current node.

The base case makes the recursion correct at the bottom of the tree: a missing child contributes depth `0`. Since each call returns the correct depth of its own subtree, the parent combines two correct results into its own correct result.

### Trick Used
No specific trick — the solution is direct and straightforward

### Edge Cases Handled
- Empty tree: `root == null` returns `0` immediately.
- Single-node tree: both recursive child calls return `0`, so the node returns `1`.
- Unbalanced tree: recursion naturally follows the longer side and still returns the correct maximum.

### Complexity Analysis
- **Time Complexity: `O(n)`**
  - Every node is visited exactly once by `maxDepth`.

- **Space Complexity: `O(h)`**
  - The only extra space is the recursion stack.
  - `h` is the tree height, which is `O(log n)` for a balanced tree and `O(n)` in the worst-case skewed tree.
