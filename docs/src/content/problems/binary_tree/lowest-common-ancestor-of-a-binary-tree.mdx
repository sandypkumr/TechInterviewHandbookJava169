Given a binary tree, find the lowest common ancestor (LCA) of two given nodes in the tree.

The lowest common ancestor is defined between two nodes `p` and `q` as the lowest node in the tree that has both `p` and `q` as descendants (where we allow **a node to be a descendant of itself**).

**Example 1:**

```
Input: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
Output: 3
```

**Example 2:**

```
Input: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
Output: 5
```

**Example 3:**

```
Input: root = [1,2], p = 1, q = 2
Output: 1
```

**Constraints:**

- The number of nodes in the tree is in the range `[2, 10^5]`.

- `-10^9 <= Node.val <= 10^9`

- All `Node.val` are **unique**.

- `p != q`

- Both `p` and `q` will exist in the tree.

## Java Solution

```java
package binary_tree;

public class LowestCommonAncestorOfABinaryTree {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        if (root == null || root == p || root == q) {
            return root;
        }
        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);
        if (left != null && right != null) {
            return root;
        }
        return left != null ? left : right;
    }
}
```

## Explanation

### Problem Analysis

The LCA is the *first node where search paths to p and q diverge*—or equivalently, the highest node having both p and q in its subtree. Finding this efficiently requires traversing to locate both nodes and recognizing where they diverge.

### Approach

Use post-order DFS:
1. Recursively search left and right subtrees for p and q
2. At each node, check:
   - If current node is p or q, return it (found one target)
   - If both left and right return non-null, current node is the LCA (both targets in different subtrees)
   - If only one returns non-null, LCA is in that subtree
3. Return non-null result (the LCA)

### Pattern Used

**Post-order recursive traversal with child-to-parent information propagation**.

### Key Insight

The key insight is recognizing that LCA can be found in three scenarios:
1. The LCA is the current node (it equals p or q, and the other is in one of its subtrees)
2. The LCA is in the left subtree (both p and q are there)
3. The LCA is in the right subtree (both p and q are there)

The algorithm returns non-null only when nodes are found, allowing results to bubble up from descendants to find the LCA.

### Code Walkthrough

```java
public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) {
        return root;
    }
    TreeNode left = lowestCommonAncestor(root.left, p, q);

```

1. **Base case**: If root is null or equals p or q, return it.
2. **Recursive search**: Check left and right subtrees.
3. **Decision logic**: If both subtrees return non-null, root is the LCA. Otherwise, return the non-null side.

### Example Walkthrough

**Example 1: `root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1` → 3**

```
          3
        /   \
       5     1
      / \   / \
     6   2 0   8
        / \
       7   4
```

1. `lowestCommonAncestor(3, 5, 1)`: 3 is not p or q
   - left = `lowestCommonAncestor(5, 5, 1)`: root==p → return 5
   - right = `lowestCommonAncestor(1, 5, 1)`: root==q → return 1
   - left and right both non-null → return 3 ✓

**Example 2: `root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4` → 5**

1. `lowestCommonAncestor(3, 5, 4)`: 3 not p or q
   - left = `lowestCommonAncestor(5, 5, 4)`: root==p → return 5
   - right = `lowestCommonAncestor(1, 5, 4)`: (not p or q, recurse deeper...) → eventually null
   - left=5, right=null → return 5 ✓

### Key Variables Explained

- **`root`**: Current node
- **`p`, `q`**: Target nodes
- **`left`, `right`**: Results from left and right subtrees

### Why This Works

1. **Base case**: When we reach p or q, we return it (found).
2. **Case 1 (both in different subtrees)**: Both left and right non-null → root divides them → root is LCA.
3. **Case 2 (both in same subtree)**: Only one side non-null → LCA is on that side.
4. **Propagation**: Results bubble up until LCA is found.

### Trick Used

**One function for two purposes**: Finding nodes AND finding their LCA in a single traversal using the base case and combination logic.

### Edge Cases Handled

1. **One node ancestor of other**: Returns the ancestor correctly
2. **Nodes at different depths**: Algorithm handles any configuration
3. **Skewed tree**: Works regardless of shape

### Complexity Analysis

- **Time Complexity: `O(n)`** — Worst case visits all nodes (e.g., if one node is deep in skewed tree).
- **Space Complexity: `O(h)`** — Recursion stack depth. Balanced: O(log n); skewed: O(n).
