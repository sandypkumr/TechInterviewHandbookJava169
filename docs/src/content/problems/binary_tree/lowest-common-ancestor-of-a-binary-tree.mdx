Given a binary tree, find the lowest common ancestor (LCA) of two given nodes in the tree.

According to the definition of LCA on Wikipedia: &ldquo;The lowest common ancestor is defined between two nodes `p` and `q` as the lowest node in `T` that has both `p` and `q` as descendants (where we allow **a node to be a descendant of itself**).&rdquo;

**Example 1:**

```
Input: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
Output: 3
Explanation: The LCA of nodes 5 and 1 is 3.
```

**Example 2:**

```
Input: root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
Output: 5
Explanation: The LCA of nodes 5 and 4 is 5, since a node can be a descendant of itself according to the LCA definition.
```

**Example 3:**

```
Input: root = [1,2], p = 1, q = 2
Output: 1
```

**Constraints:**

- The number of nodes in the tree is in the range `[2, 10^5]`.

- `-10^9 <= Node.val <= 10^9`

- All `Node.val` are **unique**.

- `p != q`

- `p` and `q` will exist in the tree.

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_tree;

public class LowestCommonAncestorOfABinaryTree {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        if (root == null || root == p || root == q) {
            return root;
        }
        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);
        if (left != null && right != null) {
            return root;
        }
        return left != null ? left : right;
    }
}
```

## Explanation

### Problem Analysis
We need the lowest node in the tree that has both `p` and `q` in its subtree, allowing a node to be its own descendant. Since the tree is not a BST, node values do not help with navigation, so the algorithm has to search both sides when needed.

This is a common interview problem because it tests recursive reasoning on trees and whether you can interpret what information a subtree should return.

### Approach
The solution does a DFS and lets each recursive call answer one question: does this subtree contain `p`, `q`, or their lowest common ancestor already? If the left subtree returns one target and the right subtree returns the other, the current `root` must be the LCA.

This is better than building parent maps here because the recursive structure already gives the needed information directly.

### Pattern Used
Depth-First Search (DFS) with recursion.

### Key Insight
A node is the LCA exactly when one target is found in its left subtree and the other is found in its right subtree, or when the current node itself is one of the targets.

### Code Walkthrough
`lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q)` is the recursive method.

The base case is `if (root == null || root == p || root == q) return root;`.

That line does three important things:
- Stops at empty subtrees
- Immediately reports when `p` is found
- Immediately reports when `q` is found

The recursive calls `TreeNode left = lowestCommonAncestor(root.left, p, q);` and `TreeNode right = lowestCommonAncestor(root.right, p, q);` ask both subtrees for their result.

If both `left` and `right` are non-null, it means one target came from each side, so `return root;` makes the current node the LCA.

Otherwise, the method returns `left != null ? left : right;`, which passes the found target or previously discovered ancestor upward.

### Example Walkthrough
Use Example 1: `root = [3,5,1,6,2,0,8,null,null,7,4]`, `p = 5`, `q = 1`.

At node `3`:
- Recurse left into subtree rooted at `5`
- Recurse right into subtree rooted at `1`

Left recursion:
- `root == p`, so it immediately returns node `5`

Right recursion:
- `root == q`, so it immediately returns node `1`

Back at node `3`:
- `left` is `5`
- `right` is `1`
- Both are non-null, so `3` is returned as the LCA

That matches the expected output `3`.

For Example 2, when searching for `p = 5` and `q = 4`, the left subtree rooted at `5` already contains both targets, so the recursion returns `5` upward without needing node `3` to become the answer.

### Key Variables Explained
- `root`: current node being evaluated.
- `p`, `q`: the two target nodes.
- `left`: result returned from the left subtree.
- `right`: result returned from the right subtree.

### Why This Works
Each recursive call returns one of three meaningful results: `null` if neither target exists in that subtree, one of the targets if exactly one has been found so far, or the LCA if it was already determined below.

When both `left` and `right` are non-null, the current node is the first place where the search paths from `p` and `q` meet, which is exactly the definition of the lowest common ancestor.

### Trick Used
The important trick is the early return `root == p || root == q`, which lets a target node bubble upward and also correctly handles the case where one target is an ancestor of the other.

### Edge Cases Handled
- Current subtree is empty: `root == null` returns `null`.
- One target is an ancestor of the other: the ancestor is returned by the base case and remains the final answer.
- Targets lie in different subtrees: `left != null && right != null` detects that split and returns the current node.

### Complexity Analysis
- Time Complexity: `O(n)` because in the worst case the recursion may visit every node once.
- Space Complexity: `O(h)` for the recursion stack, where `h` is the tree height; in the worst-case skewed tree, this becomes `O(n)`.
