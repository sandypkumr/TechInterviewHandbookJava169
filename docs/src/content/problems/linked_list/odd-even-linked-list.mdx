Given the `head` of a singly linked list, group all the nodes with odd indices together followed by the nodes with even indices, and return _the reordered list_.

The **first** node is considered **odd**, and the **second** node is **even**, and so on.

Note that the relative order inside both the even and odd groups should remain as it was in the input.

You must solve the problem in `O(1)` extra space complexity and `O(n)` time complexity.

**Example 1:**

```
Input: head = [1,2,3,4,5]
Output: [1,3,5,2,4]
```

**Example 2:**

```
Input: head = [2,1,3,5,6,4,7]
Output: [2,3,6,7,1,5,4]
```

**Constraints:**

- The number of nodes in the linked list is in the range `[0, 10^4]`.

- `-10^6 <= Node.val <= 10^6`

## Java Solution

```java
package linked_list;

public class OddEvenLinkedList {
    public ListNode oddEvenList(ListNode head) {
        if (head == null || head.next == null) {
            return head;
        }

        ListNode odd = head;
        ListNode even = head.next;
        ListNode evenHead = even;

        while (even != null && even.next != null) {
            odd.next = even.next;
            odd = odd.next;
            even.next = odd.next;
            even = even.next;
        }

        odd.next = evenHead;

        return head;
    }
}
```

## Explanation

### Approach

**Odd Even Linked List** exploits sorted order (or a structural property) to let two pointers converge from opposite ends of the array, eliminating the need for a nested loop. When the current pair doesn't satisfy the condition, we know exactly which pointer to advance — so each element is visited at most once, giving O(n) time.

Imagine squeezing a tube of toothpaste from both ends simultaneously — instead of trying every possible pair (both ends → O(n²)), you make an informed decision at each step about which end to squeeze next.

### Code Walkthrough

The solution is implemented in `oddEvenList(ListNode head)`:

1. Sort the array if it isn't already (or confirm the existing order guarantees correctness).
2. Place one pointer at the start (left = 0) and one at the end (right = n - 1).
3. Compute the result for the current pair.
4. If the result is too small, advance left to increase it; if too large, move right backward.
5. Stop when the pointers meet or cross.

### Complexity Analysis

- **Time Complexity: `O(n)`** — the two pointers together traverse the array at most once — every element is visited at most twice.
- **Space Complexity: `O(1)`** — only a fixed number of extra variables are used; no data structures that scale with input.
