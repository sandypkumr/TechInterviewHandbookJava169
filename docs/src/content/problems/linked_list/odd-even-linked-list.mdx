Given the `head` of a singly linked list, group all the nodes with odd indices together followed by the nodes with even indices, and return _the reordered list_.

The **first** node is considered **odd**, and the **second** node is **even**, and so on.

Note that the relative order inside both the even and odd groups should remain as it was in the input.

You must solve the problem in `O(1)` extra space complexity and `O(n)` time complexity.

**Example 1:**

```
Input: head = [1,2,3,4,5]
Output: [1,3,5,2,4]
```

**Example 2:**

```
Input: head = [2,1,3,5,6,4,7]
Output: [2,3,6,7,1,5,4]
```

**Constraints:**

- The number of nodes in the linked list is in the range `[0, 10^4]`.

- `-10^6 <= Node.val <= 10^6`

## Java Solution

```java
package linked_list;

public class OddEvenLinkedList {
    public ListNode oddEvenList(ListNode head) {
        if (head == null || head.next == null) {
            return head;
        }

        ListNode odd = head;
        ListNode even = head.next;
        ListNode evenHead = even;

        while (even != null && even.next != null) {
            odd.next = even.next;
            odd = odd.next;
            even.next = odd.next;
            even = even.next;
        }

        odd.next = evenHead;

        return head;
    }
}
```

## Explanation

### Problem Analysis
The problem asks us to reorder the list by node position, not by node value: nodes at odd indices must come first, followed by nodes at even indices, while preserving the original relative order inside each group. That means we are not sorting anything; we are carefully rewiring pointers.

This is a strong interview question because it checks whether you can manipulate linked-list structure in place without losing nodes.

### Approach
A brute-force idea would be to copy odd and even nodes into separate lists or arrays and then join them, but that uses extra space. This solution does the same logical grouping directly inside the existing list.

It keeps one chain for odd-indexed nodes and one chain for even-indexed nodes:
- `odd` builds the odd-position list
- `even` builds the even-position list
- `evenHead` remembers where the even list starts so it can be attached at the end

### Pattern Used
This solution primarily uses the **Two Pointers** pattern with in-place linked-list rewiring.

### Key Insight
If we repeatedly skip over alternating nodes, we can separate the original list into odd and even chains in one pass, then connect the odd chain to `evenHead`.

### Code Walkthrough
The method `oddEvenList(ListNode head)` first checks:
- `if (head == null || head.next == null)`

If the list has zero or one node, no reordering is needed, so it returns `head`.

Then it initializes:
- `ListNode odd = head;`
- `ListNode even = head.next;`
- `ListNode evenHead = even;`

Here:
- `odd` starts at position 1
- `even` starts at position 2
- `evenHead` stores the first even node so we do not lose that sublist

The main loop is:
- `while (even != null && even.next != null)`

Inside the loop:
1. `odd.next = even.next;`
   - link the current odd node to the next odd-position node
2. `odd = odd.next;`
   - advance `odd`
3. `even.next = odd.next;`
   - link the current even node to the next even-position node
4. `even = even.next;`
   - advance `even`

This gradually extracts two interleaved chains from the original list.

After the loop, `odd` points to the last node in the odd chain. The line
- `odd.next = evenHead;`
attaches the entire even chain after the odd chain.

Finally, the method returns `head`, which is still the start of the reordered list.

### Example Walkthrough
Use Example 1:
- `head = [1,2,3,4,5]`

Initial state:
- `odd = 1`
- `even = 2`
- `evenHead = 2`

Iteration 1:
- `odd.next = even.next` makes `1 -> 3`
- move `odd` to `3`
- `even.next = odd.next` makes `2 -> 4`
- move `even` to `4`

Current structure:
- odd chain: `1 -> 3 -> 4 -> 5` temporarily
- even chain: `2 -> 4 -> 5` temporarily

Iteration 2:
- `odd.next = even.next` makes `3 -> 5`
- move `odd` to `5`
- `even.next = odd.next` makes `4 -> null`
- move `even` to `null`

Loop stops.
- `odd.next = evenHead` connects `5 -> 2`
- final list becomes `[1,3,5,2,4]`

For Example 2, the same rewiring preserves the odd-order `2,3,6,7` and even-order `1,5,4`, producing `[2,3,6,7,1,5,4]`.

### Key Variables Explained
- `head`: remains the head of the final reordered list.
- `odd`: tail pointer of the odd-indexed chain as it is being built.
- `even`: tail pointer of the even-indexed chain as it is being built.
- `evenHead`: saved start of the even chain, needed for the final connection.

### Why This Works
Before each loop iteration, the nodes before `odd` already form the correct odd-order chain, and the nodes before `even` already form the correct even-order chain. The two pointer updates extend each chain by one valid node while preserving original relative order.

Because every node stays in exactly one of those two chains, and the final line connects the completed odd chain to the start of the even chain, the result contains all original nodes in the required order.

### Trick Used
Storing `evenHead` is the key pointer trick that lets the code reconnect the even chain after finishing the odd chain.

### Edge Cases Handled
- Empty list: `head == null` returns immediately.
- One-node list: `head.next == null` returns immediately.
- Even-length and odd-length lists: `while (even != null && even.next != null)` prevents invalid pointer access in both cases.
- Relative order preservation: nodes are relinked in traversal order, so each group keeps its original ordering.

### Complexity Analysis
- **Time Complexity:** `O(n)`, because the `while` loop moves through the list once, rewiring each node a constant number of times.
- **Space Complexity:** `O(1)`, because only a few pointer variables are used and no extra list or array is created.
