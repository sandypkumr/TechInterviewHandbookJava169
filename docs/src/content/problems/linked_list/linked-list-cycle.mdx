Given `head`, the head of a linked list, determine if the linked list has a cycle in it.

There is a cycle in a linked list if there is some node in the list that can be reached again by continuously following the `next` pointer. Internally, `pos` is used to denote the index of the node that tail's `next` pointer is connected to. **Note that `pos` is not passed as a parameter**.

Return `true`_ if there is a cycle in the linked list_. Otherwise, return `false`.

**Example 1:**

```
Input: head = [3,2,0,-4], pos = 1
Output: true
Explanation: There is a cycle in the linked list, where the tail connects to the 1st node (0-indexed).
```

**Example 2:**

```
Input: head = [1,2], pos = 0
Output: true
Explanation: There is a cycle in the linked list, where the tail connects to the 0th node.
```

**Example 3:**

```
Input: head = [1], pos = -1
Output: false
Explanation: There is no cycle in the linked list.
```

**Constraints:**

- The number of the nodes in the list is in the range `[0, 10^4]`.

- `-10^5 <= Node.val <= 10^5`

- `pos` is `-1` or a **valid index** in the linked-list.

**Follow up:** Can you solve it using `O(1)` (i.e. constant) memory?

**Patterns:** `two-pointers`, `fast-slow-pointers`

## Java Solution

```java
package linked_list;

public class LinkedListCycle {
    public boolean hasCycle(ListNode head) {
        if (head == null || head.next == null) {
            return false;
        }

        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;

            if (slow == fast) {
                return true; // Cycle detected
            }
        }

        return false; // No cycle
    }
}
```

## Explanation

### Problem Analysis
We need to determine whether following `next` pointers eventually revisits an earlier node. In other words, does the list terminate at `null`, or does it loop forever inside a cycle?

This is a staple interview problem because it tests pointer reasoning and whether you know Floyd's cycle detection technique, which solves the problem in constant extra space.

### Approach
The code uses two pointers that move at different speeds. `slow` advances one step at a time, while `fast` advances two steps at a time.

If there is no cycle, `fast` eventually reaches `null`. If there is a cycle, the faster pointer must eventually catch the slower pointer somewhere inside the loop.

### Pattern Used
Fast/Slow Pointers.

### Key Insight
Inside a cycle, a pointer moving two steps per turn gains one step on a pointer moving one step per turn, so the gap between them must eventually close to zero.

### Code Walkthrough
`hasCycle(ListNode head)` begins with a quick rejection:

- `if (head == null || head.next == null)` returns `false` because an empty list or a single node without a self-loop cannot contain a traversable cycle in this code path.

Then both pointers are initialized:

- `ListNode slow = head;`
- `ListNode fast = head;`

The main loop is:

- `while (fast != null && fast.next != null)`
- This guard ensures `fast.next.next` is safe before moving the fast pointer two steps.

Inside the loop:

- `slow = slow.next;` moves one node.
- `fast = fast.next.next;` moves two nodes.
- `if (slow == fast)` returns `true` immediately when both pointers meet.

If the loop exits naturally:

- `return false;`
- That means `fast` reached the end, so there is no cycle.

### Example Walkthrough
Use Example 1: `head = [3,2,0,-4]`, `pos = 1`.

The structure is:

- `3 -> 2 -> 0 -> -4`
- Then `-4.next` points back to the node with value `2`.

Pointer movement:

- Start: `slow = 3`, `fast = 3`
- Iteration 1: `slow = 2`, `fast = 0`
- Iteration 2: `slow = 0`, `fast = 2`
- Iteration 3: `slow = -4`, `fast = -4`

Now `slow == fast`, so the method returns `true`.

### Key Variables Explained
- `head`: starting node of the linked list.
- `slow`: moves one step per iteration and represents the tortoise pointer.
- `fast`: moves two steps per iteration and represents the hare pointer.
- `fast != null && fast.next != null`: safety condition that prevents invalid pointer jumps.

### Why This Works
If the list has no cycle, repeatedly moving `fast` by two steps must eventually hit `null`, so the loop ends and the method correctly returns `false`. If the list has a cycle, then after both pointers enter the cycle, `fast` gains one node per iteration relative to `slow`. Since the cycle length is finite, that relative gain guarantees they will meet.

That meeting can happen only when a cycle exists, so returning `true` on `slow == fast` is correct.

### Trick Used
The trick is Floyd's tortoise-and-hare method: detect a cycle without marking nodes or using a hash set.

### Edge Cases Handled
- `head == null`: immediately returns `false`.
- `head.next == null`: a single-node non-cyclic list returns `false`.
- Short non-cyclic lists: the `while (fast != null && fast.next != null)` guard exits safely.
- Cycles of any length, including a self-loop reachable from the loop: the pointers eventually meet.

### Complexity Analysis
- **Time Complexity:** `O(n)` because each pointer advances through the list a linear number of times before either meeting or reaching the end.
- **Space Complexity:** `O(1)` because only `slow`, `fast`, and a few constant-size checks are used.
