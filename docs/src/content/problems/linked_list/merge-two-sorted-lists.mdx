You are given the heads of two sorted linked lists `list1` and `list2`.

Merge the two lists into one **sorted** list. The list should be made by splicing together the nodes of the first two lists.

Return _the head of the merged linked list_.

**Example 1:**

```
Input: list1 = [1,2,4], list2 = [1,3,4]
Output: [1,1,2,3,4,4]
```

**Example 2:**

```
Input: list1 = [], list2 = []
Output: []
```

**Example 3:**

```
Input: list1 = [], list2 = [0]
Output: [0]
```

**Constraints:**

- The number of nodes in both lists is in the range `[0, 50]`.

- `-100 <= Node.val <= 100`

- Both `list1` and `list2` are sorted in **non-decreasing** order.

**Patterns:** `merge-intervals`

## Java Solution

```java
package linked_list;

public class MergeTwoSortedLists {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        if (list1 == null) {
            return list2;
        }
        if (list2 == null) {
            return list1;
        }

        ListNode mergedHead = new ListNode(0);
        ListNode current = mergedHead;

        while (list1 != null && list2 != null) {
            if (list1.val < list2.val) {
                current.next = list1;
                list1 = list1.next;
            } else {
                current.next = list2;
                list2 = list2.next;
            }
            current = current.next;
        }

        if (list1 != null) {
            current.next = list1;
        } else {
            current.next = list2;
        }

        return mergedHead.next;
    }
}
```

## Explanation

### Problem Analysis
The problem asks us to merge two already sorted linked lists into one sorted linked list by reusing the existing nodes. The important constraint is not just correctness, but doing it efficiently without creating unnecessary extra structures.

This is a common interview question because it checks whether you can exploit sorted order and manipulate pointers safely.

### Approach
Since both lists are already sorted, we never need to look far ahead. At each step, the smaller current node must be the next node in the answer.

So the algorithm keeps one pointer on each list and repeatedly links the smaller node to the merged result. This is much better than copying values into an array and sorting again, because it keeps the work strictly linear.

### Pattern Used
This solution uses the **Two Pointers** pattern on linked lists, together with a dummy head node.

### Key Insight
Because `list1` and `list2` are individually sorted, comparing only their current heads is enough to decide the next node in the merged list.

### Code Walkthrough
The method is `mergeTwoLists(ListNode list1, ListNode list2)`.

The first two checks handle empty-input cases immediately:
- if `list1 == null`, return `list2`
- if `list2 == null`, return `list1`

After that, the code creates:
- `ListNode mergedHead = new ListNode(0);`
- `ListNode current = mergedHead;`

`mergedHead` is a dummy starter node. `current` always points to the last node in the merged list built so far.

The main loop runs while both lists still have nodes:
- compare `list1.val` and `list2.val`
- if `list1.val < list2.val`, attach `list1` by `current.next = list1`, then advance `list1 = list1.next`
- otherwise attach `list2`, then advance `list2 = list2.next`
- finally move `current = current.next`

Notice that when the values are equal, the `else` branch chooses from `list2` first because the condition is strictly `<`.

Once one list finishes, the remaining nodes in the other list are already sorted, so the code simply appends them:
- if `list1 != null`, set `current.next = list1`
- else set `current.next = list2`

The final answer starts after the dummy node, so the method returns `mergedHead.next`.

### Example Walkthrough
Use Example 1:
- `list1 = [1,2,4]`
- `list2 = [1,3,4]`

Initial state:
- `mergedHead` is a dummy node
- `current = mergedHead`

Step 1:
- compare `list1.val = 1` and `list2.val = 1`
- `1 < 1` is false, so the code takes the node from `list2`
- merged list becomes `1`
- `list2` moves to `3`

Step 2:
- compare `1` and `3`
- take `list1`
- merged list becomes `1 -> 1`
- `list1` moves to `2`

Step 3:
- compare `2` and `3`
- take `list1`
- merged list becomes `1 -> 1 -> 2`
- `list1` moves to `4`

Step 4:
- compare `4` and `3`
- take `list2`
- merged list becomes `1 -> 1 -> 2 -> 3`
- `list2` moves to `4`

Step 5:
- compare `4` and `4`
- the `else` branch takes `list2`
- merged list becomes `1 -> 1 -> 2 -> 3 -> 4`
- `list2` becomes `null`

Loop ends because `list2 == null`.
- append the rest of `list1`, which is `4`
- final result is `[1,1,2,3,4,4]`

### Key Variables Explained
- `list1`: current node in the first sorted list.
- `list2`: current node in the second sorted list.
- `mergedHead`: dummy starting node that simplifies result construction.
- `current`: tail of the merged list; it advances after each attachment.

### Why This Works
At every iteration, the smallest remaining value among all unmerged nodes must be either `list1.val` or `list2.val`, because those are the first unprocessed nodes of two sorted lists. The code attaches exactly that smaller node, so the merged list stays sorted after each step.

When one list runs out, every node left in the other list is already greater than or equal to the nodes already placed before it, so appending the remainder preserves sorted order.

### Trick Used
Using a **dummy head node** avoids special handling for the first inserted node.

### Edge Cases Handled
- `list1 == null`: the method immediately returns `list2`.
- `list2 == null`: the method immediately returns `list1`.
- Different list lengths: once one list ends, the leftover nodes are attached in one step.
- Equal values: the `else` branch still produces a correct sorted merge.

### Complexity Analysis
- **Time Complexity:** `O(n + m)`, where `n` and `m` are the lengths of `list1` and `list2`, because each node is attached to the merged list exactly once.
- **Space Complexity:** `O(1)`, because the code reuses existing nodes and only keeps a few pointer variables.
