Given the `head` of a singly linked list, reverse the list, and return _the reversed list_.

**Example 1:**

```
Input: head = [1,2,3,4,5]
Output: [5,4,3,2,1]
```

**Example 2:**

```
Input: head = [1,2]
Output: [2,1]
```

**Example 3:**

```
Input: head = []
Output: []
```

**Constraints:**

- The number of nodes in the list is the range `[0, 5000]`.

- `-5000 <= Node.val <= 5000`

**Follow up:** A linked list can be reversed either iteratively or recursively. Could you implement both?

## Java Solution

```java
package linked_list;

public class ReverseLinkedList {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode current = head;

        while (current != null) {
            ListNode nextTemp = current.next; // Store next node
            current.next = prev; // Reverse the link
            prev = current; // Move prev to current
            current = nextTemp; // Move to the next node
        }

        return prev; // New head of the reversed list
    }
}
```

## Explanation

### Problem Analysis
This problem asks us to reverse the direction of every pointer in a singly linked list and return the new head. We are not changing node values; we are rewiring `next` references in place.

It is a classic interview problem because it tests pointer manipulation, in-place updates, and whether you can preserve access to the remaining list while modifying links.

### Approach
The code uses an iterative in-place reversal. As we scan the list from left to right, we detach the current node from its original next node and point it backward to the already-reversed portion.

This is better than copying values into another structure because it keeps extra space constant and directly exercises linked-list pointer handling.

### Pattern Used
Two Pointers / Iterative Pointer Reversal.

### Key Insight
At every step, keep `prev` as the head of the already-reversed part and `current` as the first node not processed yet.

### Code Walkthrough
The method `reverseList(ListNode head)` starts by setting `prev = null` and `current = head`.

- `prev` represents the reversed list built so far.
- `current` represents the node we are currently processing.

The loop `while (current != null)` processes one node at a time until the original list is exhausted.

Inside the loop:
- `ListNode nextTemp = current.next;` saves the original next node before we change anything.
- `current.next = prev;` flips the pointer so the current node points backward.
- `prev = current;` moves the reversed-list head forward by one node.
- `current = nextTemp;` advances into the unreversed remainder.

After the loop finishes, `current` is `null` and `prev` points to the new head of the fully reversed list.

The method returns `prev`.

### Example Walkthrough
Use Example 1: `head = [1,2,3,4,5]`.

Initial state:
- `prev = null`
- `current = 1`

Iteration 1:
- `nextTemp = 2`
- `current.next = prev` makes `1 -> null`
- `prev = 1`
- `current = 2`

Iteration 2:
- `nextTemp = 3`
- `current.next = prev` makes `2 -> 1`
- `prev = 2`
- `current = 3`

Iteration 3:
- Reverse `3` so the partial list becomes `3 -> 2 -> 1`

Iteration 4:
- Reverse `4` so the partial list becomes `4 -> 3 -> 2 -> 1`

Iteration 5:
- Reverse `5` so the partial list becomes `5 -> 4 -> 3 -> 2 -> 1`
- `current` becomes `null`

Return `prev`, which is the head of `[5,4,3,2,1]`.

### Key Variables Explained
- `prev`: head of the reversed portion built so far.
- `current`: node currently being reversed.
- `nextTemp`: saved pointer to the remainder of the original list so it is not lost after rewiring `current.next`.

### Why This Works
Before each loop iteration:
- the nodes before `current` have already been reversed correctly,
- `prev` points to the front of that reversed portion,
- and the nodes from `current` onward are still in original order.

The loop preserves this invariant by saving `current.next`, reversing one pointer, then advancing both tracking pointers. When the loop ends, there are no unprocessed nodes left, so `prev` must be the fully reversed list.

### Trick Used
No specific trick — the solution is direct and straightforward

### Edge Cases Handled
- Empty list: if `head` is `null`, the loop never runs and the method returns `null`.
- Single-node list: its `next` becomes `null`, which is already correct, and that node is returned.
- General list: every node is processed exactly once without losing the remainder because of `nextTemp`.

### Complexity Analysis
- **Time Complexity: `O(n)`** — the `while (current != null)` loop visits each node exactly once.
- **Space Complexity: `O(1)`** — only `prev`, `current`, and `nextTemp` are used regardless of list size.
