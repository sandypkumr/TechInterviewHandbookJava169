You are given an array of CPU `tasks`, each labeled with a letter from A to Z, and a number `n`. Each CPU interval can be idle or allow the completion of one task. Tasks can be completed in any order, but there's a constraint: there has to be a gap of **at least** `n` intervals between two tasks with the same label.

Return the **minimum** number of CPU intervals required to complete all tasks.

**Example 1:**

**Input:** tasks = ["A","A","A","B","B","B"], n = 2

**Output:** 8

**Explanation:** A possible sequence is: A -> B -> idle -> A -> B -> idle -> A -> B.

After completing task A, you must wait two intervals before doing A again. The same applies to task B. In the 3^rd interval, neither A nor B can be done, so you idle. By the 4^th interval, you can do A again as 2 intervals have passed.

**Example 2:**

**Input:** tasks = ["A","C","A","B","D","B"], n = 1

**Output:** 6

**Explanation:** A possible sequence is: A -> B -> C -> D -> A -> B.

With a cooling interval of 1, you can repeat a task after just one other task.

**Example 3:**

**Input:** tasks = ["A","A","A", "B","B","B"], n = 3

**Output:** 10

**Explanation:** A possible sequence is: A -> B -> idle -> idle -> A -> B -> idle -> idle -> A -> B.

There are only two types of tasks, A and B, which need to be separated by 3 intervals. This leads to idling twice between repetitions of these tasks.

**Constraints:**

- `1 <= tasks.length <= 10^4`

- `tasks[i]` is an uppercase English letter.

- `0 <= n <= 100`

**Patterns:** `merge-intervals`

## Java Solution

```java
package heap;

public class TaskScheduler {
    public int leastInterval(char[] tasks, int n) {
        int[] taskCounts = new int[26];
        for (char task : tasks) {
            taskCounts[task - 'A']++;
        }

        int maxCount = 0;
        int maxCountTasks = 0;
        for (int count : taskCounts) {
            if (count > maxCount) {
                maxCount = count;
                maxCountTasks = 1;
            } else if (count == maxCount) {
                maxCountTasks++;
            }
        }

        int partCount = maxCount - 1;
        int partLength = n - (maxCountTasks - 1);
        int emptySlots = partCount * partLength;
        int availableTasks = tasks.length - (maxCount * maxCountTasks);
        int idles = Math.max(0, emptySlots - availableTasks);

        return tasks.length + idles;
    }
}
```

## Explanation

### Problem Analysis
We need the minimum number of time slots needed to execute all tasks when identical tasks must be separated by at least `n` intervals. The hard part is accounting for forced idle slots without explicitly simulating every schedule.

This is a common interview problem because it looks like scheduling, but the real solution comes from counting frequencies and reasoning about the most constrained tasks.

### Approach
The code uses a greedy counting formula. It finds the task frequency that appears the most times, treats those occurrences as the backbone of the schedule, and then calculates how many gaps must exist between them.

Instead of building a full timeline, the algorithm computes how many of those gaps can be filled by other tasks and how many must remain idle. That is much simpler and more efficient than simulating with a heap.

### Pattern Used
Greedy with Frequency Counting.

### Key Insight
The tasks with the maximum frequency determine the minimum possible schedule length, because every other task must fit into the gaps created around them.

### Code Walkthrough
`leastInterval(char[] tasks, int n)` starts by counting frequencies:

- `int[] taskCounts = new int[26];` stores counts for `'A'` through `'Z'`.
- The loop `for (char task : tasks)` increments `taskCounts[task - 'A']`.

Next, the code finds the highest frequency and how many tasks share it:

- `maxCount` stores the largest frequency seen so far.
- `maxCountTasks` stores how many distinct task labels occur exactly `maxCount` times.
- If a new larger `count` is found, `maxCount` is replaced and `maxCountTasks` resets to `1`.
- If `count == maxCount`, another task joins that top-frequency group, so `maxCountTasks++`.

The formula section computes the required structure:

- `partCount = maxCount - 1` is the number of full gaps between the most frequent occurrences.
- `partLength = n - (maxCountTasks - 1)` is how many idle-capable positions remain in each gap after placing other max-frequency tasks alongside them.
- `emptySlots = partCount * partLength` is the total number of open positions that still need filling.
- `availableTasks = tasks.length - (maxCount * maxCountTasks)` counts all tasks not belonging to the top-frequency group.
- `idles = Math.max(0, emptySlots - availableTasks)` is the number of gaps that other tasks cannot fill.

Finally:

- `return tasks.length + idles;`
- Every task consumes one interval, and only unavoidable idle slots are added.

### Example Walkthrough
Use Example 1: `tasks = ["A","A","A","B","B","B"]`, `n = 2`.

Frequency counts:

- `A -> 3`
- `B -> 3`
- So `maxCount = 3` and `maxCountTasks = 2`.

Apply the formula:

- `partCount = 3 - 1 = 2`
- `partLength = 2 - (2 - 1) = 1`
- `emptySlots = 2 * 1 = 2`
- `availableTasks = 6 - (3 * 2) = 0`
- `idles = max(0, 2 - 0) = 2`

Answer:

- `tasks.length + idles = 6 + 2 = 8`

That matches a valid schedule such as `A, B, idle, A, B, idle, A, B`.

### Key Variables Explained
- `taskCounts`: frequency table for all 26 uppercase task types.
- `maxCount`: the highest frequency among all tasks.
- `maxCountTasks`: how many task types are tied at that highest frequency.
- `partCount`: number of separators between repeated occurrences of the most frequent tasks.
- `partLength`: remaining capacity in each separator block after accounting for ties at the top.
- `emptySlots`: total positions that still need other tasks or idle intervals.
- `availableTasks`: tasks that can be used to fill those positions.
- `idles`: unavoidable idle intervals left after filling as much as possible.

### Why This Works
Any task with frequency `maxCount` must appear `maxCount` times, creating `maxCount - 1` cooling gaps between consecutive copies. Those gaps are the bottleneck of the schedule. If multiple tasks share the same maximum frequency, they occupy part of each gap structure together, which is why `partLength` subtracts `maxCountTasks - 1`.

Once that backbone is fixed, every remaining task can only reduce empty space. If there are not enough remaining tasks to fill all empty slots, the difference must be idle time. Otherwise, no idle intervals are needed, and the answer is just the number of tasks.

### Trick Used
The main trick is converting the scheduling problem into a gap-counting formula based on `maxCount` and `maxCountTasks`, avoiding explicit timeline simulation.

### Edge Cases Handled
- `n = 0`: then `partLength` becomes `0` or less, `idles` becomes `0`, and the answer is simply `tasks.length`.
- Multiple tasks tied for highest frequency: handled by `maxCountTasks`.
- Enough other tasks to fill every gap: `Math.max(0, emptySlots - availableTasks)` prevents negative idle counts.
- Only one task type repeated many times: the formula correctly adds the required idle slots.

### Complexity Analysis
- **Time Complexity:** `O(tasks.length + 26)` because the code makes one pass to count tasks and one fixed-size pass over the 26 counters. This simplifies to `O(n)` where `n = tasks.length`.
- **Space Complexity:** `O(26)`, which is `O(1)`, because `taskCounts` has constant size and the remaining variables are scalars.
