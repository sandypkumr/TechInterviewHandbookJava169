Given an array of `points` where `points[i] = [xi, yi]` represents a point on the **X-Y** plane and an integer `k`, return the `k` closest points to the origin `(0, 0)`.

The distance between two points on the **X-Y** plane is the Euclidean distance (i.e., `&radic;(x1 - x2)^2 + (y1 - y2)^2`).

You may return the answer in **any order**. The answer is **guaranteed** to be **unique** (except for the order that it is in).

**Example 1:**

```
Input: points = [[1,3],[-2,2]], k = 1
Output: [[-2,2]]
Explanation:
The distance between (1, 3) and the origin is sqrt(10).
The distance between (-2, 2) and the origin is sqrt(8).
Since sqrt(8) < sqrt(10), (-2, 2) is closer to the origin.
We only want the closest k = 1 points from the origin, so the answer is just [[-2,2]].
```

**Example 2:**

```
Input: points = [[3,3],[5,-1],[-2,4]], k = 2
Output: [[3,3],[-2,4]]
Explanation: The answer [[-2,4],[3,3]] would also be accepted.
```

**Constraints:**

- `1 <= k <= points.length <= 10^4`

- `-10^4 <= xi, yi <= 10^4`

**Patterns:** `heap`

## Java Solution

```java
package heap;

import java.util.PriorityQueue;

public class KClosestPointsToOrigin {
    public int[][] kClosest(int[][] points, int k) {
        int[][] result = new int[k][2];
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>(
                (a, b) -> Integer.compare(b[0] * b[0] + b[1] * b[1], a[0] * a[0] + a[1] * a[1])
        );

        for (int[] point : points) {
            maxHeap.offer(point);
            if (maxHeap.size() > k) {
                maxHeap.poll();
            }
        }

        for (int i = 0; i < k; i++) {
            result[i] = maxHeap.poll();
        }

        return result;
    }
}
```

## Explanation

### Problem Analysis
We need the `k` points with the smallest distance from the origin.
A full sort would work, but it does more work than necessary because we only care about the best `k`, not the complete ranking of all points.
This is a standard interview problem for recognizing when a bounded heap is the right top-`k` tool.

### Approach
The code keeps a max-heap of at most `k` points.
For each point, it adds the point to the heap.
If the heap grows beyond size `k`, it removes the farthest point currently in the heap.
That means the heap always contains the best `k` candidates seen so far.
At the end, polling the heap gives exactly the `k` closest points.
This is more efficient than sorting all `n` points when `k` is much smaller than `n`.

### Pattern Used
Heap / Priority Queue.

### Key Insight
By making the heap a max-heap on distance, the worst point among the current `k` candidates is always on top and can be discarded immediately.

### Code Walkthrough
The method `kClosest(int[][] points, int k)` starts by creating `int[][] result = new int[k][2]` for the answer.

Then it builds `PriorityQueue<int[]> maxHeap` with a comparator:
`Integer.compare(b[0] * b[0] + b[1] * b[1], a[0] * a[0] + a[1] * a[1])`.
Because it compares `b` before `a`, the point with the larger squared distance is treated as higher priority, so this behaves like a max-heap.
The code uses squared distance, which is enough for comparison and avoids unnecessary square roots.

The loop `for (int[] point : points)` processes every point.
- `maxHeap.offer(point)` inserts the current point.
- If `maxHeap.size() > k`, then `maxHeap.poll()` removes the farthest point among the stored candidates.
After each iteration, the heap contains at most `k` closest points seen so far.

After the scan, a second loop runs from `i = 0` to `k - 1`.
Each iteration assigns `result[i] = maxHeap.poll()`.
The problem allows any order, so the code does not need to sort the final `k` points.
Finally, it returns `result`.

### Example Walkthrough
Use Example 1: `points = [[1,3],[-2,2]]`, `k = 1`.

Start with an empty `maxHeap`.

Process `[1,3]`:
- Squared distance is `1^2 + 3^2 = 10`.
- Offer it into the heap.
- Heap size is `1`, which is not greater than `k`.

Process `[-2,2]`:
- Squared distance is `(-2)^2 + 2^2 = 8`.
- Offer it into the heap.
- Heap size becomes `2`, so poll once.
- Because the heap is a max-heap by distance, `[1,3]` with distance `10` is removed.
- Heap now keeps only `[-2,2]`.

Build the result:
- `result[0] = maxHeap.poll()` gives `[-2,2]`.
- Return `[[-2,2]]`, which matches the example.

For Example 2, the same process keeps the two points with squared distances `18` and `20`, and discards `[5,-1]` with squared distance `26`.

### Key Variables Explained
- `points`: all input points.
- `k`: how many closest points must remain.
- `result`: output array of size `k`.
- `maxHeap`: bounded priority queue storing the current best `k` candidates.
- `point`: current point being processed in the scan.

### Why This Works
The invariant is that after processing any prefix of `points`, `maxHeap` contains the `k` closest points from that prefix, or all points from that prefix if fewer than `k` have been seen.
When a new point arrives, it is inserted tentatively.
If that makes the heap too large, removing the farthest point is always safe because that point cannot belong to the final closest `k` once there are already `k` better or equal candidates.
By the end of the loop, the heap therefore contains exactly the global `k` closest points.

### Trick Used
Using squared distance (`x*x + y*y`) instead of Euclidean distance, since square roots are unnecessary for comparisons.

### Edge Cases Handled
- `k == 1`: the heap reduces to tracking only the single closest point.
- `k == points.length`: the heap never removes anything, so all points are returned.
- Negative coordinates: squaring handles them correctly when computing distance.
- Output order requirement: the problem allows any order, so polling directly into `result` is valid.

### Complexity Analysis
- Time Complexity: `O(n log k)` because the first loop processes all `n = points.length` points, each heap insertion/removal costs `O(log k)`, and the final `k` polls cost `O(k log k)`; this is dominated by `O(n log k)` for the stated constraints.
- Space Complexity: `O(k)` because `maxHeap` stores at most `k` points, while `result` is the required output.
