Given an array of strings `words` and an integer `k`, return _the _`k`_ most frequent strings_.

Return the answer **sorted** by **the frequency** from highest to lowest. Sort the words with the same frequency by their **lexicographical order**.

**Example 1:**

```
Input: words = ["i","love","leetcode","i","love","coding"], k = 2
Output: ["i","love"]
Explanation: "i" and "love" are the two most frequent words.
Note that "i" comes before "love" due to a lower alphabetical order.
```

**Example 2:**

```
Input: words = ["the","day","is","sunny","the","the","the","sunny","is","is"], k = 4
Output: ["the","is","sunny","day"]
Explanation: "the", "is", "sunny" and "day" are the four most frequent words, with the number of occurrence being 4, 3, 2 and 1 respectively.
```

**Constraints:**

- `1 <= words.length <= 500`

- `1 <= words[i].length <= 10`

- `words[i]` consists of lowercase English letters.

- `k` is in the range `[1, The number of unique words[i]]`

**Follow-up:** Could you solve it in `O(n log(k))` time and `O(n)` extra space?

**Patterns:** `heap`

## Java Solution

```java
package heap;

import java.util.*;

public class TopKFrequentWords {
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Integer> freqMap = new HashMap<>();
        for (String word : words) {
            freqMap.put(word, freqMap.getOrDefault(word, 0) + 1);
        }

        PriorityQueue<String> heap = new PriorityQueue<>(
                (w1, w2) -> {
                    int freqCompare = freqMap.get(w1) - freqMap.get(w2);
                    if (freqCompare == 0) {
                        return w2.compareTo(w1);
                    }
                    return freqCompare;
                }
        );

        for (String word : freqMap.keySet()) {
            heap.offer(word);
            if (heap.size() > k) {
                heap.poll();
            }
        }

        List<String> result = new ArrayList<>();
        while (!heap.isEmpty()) {
            result.add(heap.poll());
        }
        Collections.reverse(result);
        return result;
    }
}
```

## Explanation

### Problem Analysis
We need the `k` most frequent words, ordered first by descending frequency and then by ascending lexicographical order for ties. The challenge is keeping the best `k` candidates efficiently without sorting every unique word at the end.

This is a standard interview problem because it combines counting, custom ordering, and a bounded heap for top-`k` selection.

### Approach
The code first counts each word with a hash map. Then it uses a min-heap of size at most `k` to keep only the current top `k` words.

The heap is designed so that the "least desirable" candidate sits at the top: lower frequency is worse, and for equal frequency, lexicographically larger is worse. That way, when the heap grows beyond `k`, polling removes exactly the word we no longer want.

### Pattern Used
Heap / Priority Queue with Hash Map counting.

### Key Insight
If the heap always ejects the worst candidate among the current top words, then after processing all unique words, the heap contains exactly the desired `k` answers.

### Code Walkthrough
`topKFrequent(String[] words, int k)` begins with frequency counting:

- `Map<String, Integer> freqMap = new HashMap<>();`
- For each `word`, the code runs `freqMap.put(word, freqMap.getOrDefault(word, 0) + 1);`.

Then it creates the heap:

- `PriorityQueue<String> heap = new PriorityQueue<>(...)`
- The comparator uses `freqMap.get(w1) - freqMap.get(w2)` so lower frequency has higher removal priority.
- If frequencies tie, it returns `w2.compareTo(w1)`.
- That reversed lexicographical comparison makes lexicographically larger words come out first, which is exactly what we want to discard in a tie.

Next, the code iterates over all unique words:

- `heap.offer(word)` inserts the current word.
- If `heap.size() > k`, `heap.poll()` removes the weakest candidate.
- Because of the comparator, the heap never holds more than the best `k` words seen so far.

Finally, the result is built:

- `List<String> result = new ArrayList<>();`
- While the heap is not empty, `result.add(heap.poll())` collects words from worst-to-best among the retained set.
- `Collections.reverse(result)` flips that order so the final list is best-to-worst, matching the problem requirement.
- The method returns `result`.

### Example Walkthrough
Use Example 1: `words = ["i","love","leetcode","i","love","coding"]`, `k = 2`.

Frequency map after counting:

- `i -> 2`
- `love -> 2`
- `leetcode -> 1`
- `coding -> 1`

Process unique words through the heap:

- Insert `i` -> heap contains `[i]`.
- Insert `love` -> heap contains `i` and `love`.
  - Since both have frequency `2`, the comparator treats the lexicographically larger word as worse.
- Insert `leetcode` -> heap size becomes `3`, so poll removes `leetcode` because frequency `1` is smallest.
- Insert `coding` -> heap size becomes `3` again, so poll removes `coding`.

Now the heap contains `i` and `love`.

Building the answer:

- Polling gives the weaker of the two retained words first according to heap order.
- `result` is collected in reverse priority order, then `Collections.reverse(result)` turns it into `["i", "love"]`.

### Key Variables Explained
- `freqMap`: maps each word to its occurrence count.
- `heap`: a min-heap that stores at most `k` candidate words.
- Heap comparator: defines which word is considered worse and should be removed first.
- `word`: the current unique word being evaluated for top-`k` membership.
- `result`: final output list built from the heap contents.

### Why This Works
After counting, every word's priority is fully determined by `(frequency descending, lexicographical ascending)`. The heap comparator intentionally stores the opposite notion at the root: the lowest frequency, or on ties the lexicographically largest word, is easiest to remove.

That means after each insertion, if the heap exceeds size `k`, removing the root preserves the best `k` candidates seen so far. By induction over all unique words, the heap at the end contains exactly the correct top `k` words.

### Trick Used
The important trick is the reversed tie-breaker `w2.compareTo(w1)` inside the min-heap comparator, so lexicographically larger tied words get evicted before smaller ones.

### Edge Cases Handled
- `k = 1`: the heap still works and keeps only the single best word.
- Multiple words with the same frequency: the custom comparator enforces lexicographical ordering.
- All words unique: the heap retains the lexicographically smallest words among equal-frequency candidates only when frequency rules allow it.
- Repeated words many times: `freqMap.getOrDefault(word, 0) + 1` counts them correctly.

### Complexity Analysis
Let `n` be `words.length` and `m` be the number of unique words.

- **Time Complexity:** `O(n + m log k + k)` because counting all words is `O(n)`, each of the `m` unique words may be inserted and possibly removed from the heap in `O(log k)`, and the final extraction/reverse step costs `O(k)`.
- **Space Complexity:** `O(m + k)`. `freqMap` stores all unique words, and the heap stores at most `k` of them. Since `m <= n`, this is commonly summarized as `O(n)`.
