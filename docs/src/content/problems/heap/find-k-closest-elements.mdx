Given a **sorted** integer array `arr`, two integers `k` and `x`, return the `k` closest integers to `x` in the array. The result should also be sorted in ascending order.

An integer `a` is closer to `x` than an integer `b` if:

- `|a - x|
**Input:** arr = [1,2,3,4,5], k = 4, x = 3

**Output:** [1,2,3,4]

**Example 2:**

**Input:** arr = [1,1,2,3,4,5], k = 4, x = -1

**Output:** [1,1,2,3]

**Constraints:**

- `1 <= k <= arr.length`

- `1 <= arr.length <= 10^4`

- `arr` is sorted in **ascending** order.

- `-10^4 <= arr[i], x <= 10^4`

**Patterns:** `sliding-window`

## Java Solution

```java
package heap;

import java.util.Arrays;
import java.util.List;

public class FindKClosestElements {
    public List<Integer> findClosestElements(int[] arr, int k, int x) {
        int left = 0;
        int right = arr.length - k;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (x - arr[mid] > arr[mid + k] - x) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }

        return Arrays.stream(arr, left, left + k).boxed().toList();
    }
}
```

## Explanation

### Approach

**Find K Closest Elements** has a monotonic property: we can always determine whether the answer lies in the left or right half of the remaining search space. Binary search exploits this by halving the space at every step, achieving O(log n) instead of O(n) linear scan.

Picture looking up a word in a dictionary: you open to the middle, decide whether your word is in the left or right half, and discard the other half entirely. After at most log₂(n) steps you've found your word — or confirmed it isn't there.

### Code Walkthrough

The solution is implemented in `findClosestElements(int[] arr, int k, int x)`:

1. Define left and right boundaries covering all possible answers.
2. Compute mid = left + (right - left) / 2 (avoids integer overflow).
3. Evaluate the predicate at mid to decide which half to discard.
4. Narrow the range: move left = mid + 1 or right = mid - 1.
5. Repeat until left &gt; right; the answer is typically left (or right + 1).

&gt; **Note:** This solution also uses the **two pointers moving toward each other** technique.

### Complexity Analysis

- **Time Complexity: `O(log(n-k)+k)`** — see the analysis for full details.
- **Space Complexity: `O(1)`** — only a fixed number of extra variables are used; no data structures that scale with input.
