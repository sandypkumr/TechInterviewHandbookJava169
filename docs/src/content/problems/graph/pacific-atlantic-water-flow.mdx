There is an `m x n` rectangular island that borders both the **Pacific Ocean** and **Atlantic Ocean**. The **Pacific Ocean** touches the island's left and top edges, and the **Atlantic Ocean** touches the island's right and bottom edges.

The island is partitioned into a grid of square cells. You are given an `m x n` integer matrix `heights` where `heights[r][c]` represents the **height above sea level** of the cell at coordinate `(r, c)`.

The island receives a lot of rain, and the rain water can flow to neighboring cells directly north, south, east, and west if the neighboring cell's height is **less than or equal to** the current cell's height. Water can flow from any cell adjacent to an ocean into the ocean.

Return _a **2D list** of grid coordinates _`result`_ where _`result[i] = [ri, ci]`_ denotes that rain water can flow from cell _`(ri, ci)`_ to **both** the Pacific and Atlantic oceans_.

**Example 1:**

```
Input: heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]
Output: [[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
Explanation: The following cells can flow to the Pacific and Atlantic oceans, as shown below:
[0,4]: [0,4] -> Pacific Ocean
       [0,4] -> Atlantic Ocean
[1,3]: [1,3] -> [0,3] -> Pacific Ocean
       [1,3] -> [1,4] -> Atlantic Ocean
[1,4]: [1,4] -> [1,3] -> [0,3] -> Pacific Ocean
       [1,4] -> Atlantic Ocean
[2,2]: [2,2] -> [1,2] -> [0,2] -> Pacific Ocean
       [2,2] -> [2,3] -> [2,4] -> Atlantic Ocean
[3,0]: [3,0] -> Pacific Ocean
       [3,0] -> [4,0] -> Atlantic Ocean
[3,1]: [3,1] -> [3,0] -> Pacific Ocean
       [3,1] -> [4,1] -> Atlantic Ocean
[4,0]: [4,0] -> Pacific Ocean
       [4,0] -> Atlantic Ocean
Note that there are other possible paths for these cells to flow to the Pacific and Atlantic oceans.
```

**Example 2:**

```
Input: heights = [[1]]
Output: [[0,0]]
Explanation: The water can flow from the only cell to the Pacific and Atlantic oceans.
```

**Constraints:**

- `m == heights.length`

- `n == heights[r].length`

- `1 <= m, n <= 200`

- `0 <= heights[r][c] <= 10^5`

**Patterns:** `sliding-window`, `dfs`

## Java Solution

```java
package graph;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class PacificAtlanticWaterFlow {
    public List<List<Integer>> pacificAtlantic(int[][] heights) {
        List<List<Integer>> result = new ArrayList<>();

        int rows = heights.length;
        int cols = heights[0].length;

        boolean[][] pacific = new boolean[rows][cols];
        boolean[][] atlantic = new boolean[rows][cols];

        for (int c = 0; c < cols; c++) {
            dfs(heights, 0, c, pacific, heights[0][c]);
            dfs(heights, rows - 1, c, atlantic, heights[rows - 1][c]);
        }
        for (int r = 0; r < rows; r++) {
            dfs(heights, r, 0, pacific, heights[r][0]);
            dfs(heights, r, cols - 1, atlantic, heights[r][cols - 1]);
        }

        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (pacific[r][c] && atlantic[r][c]) {
                    result.add(Arrays.asList(r, c));
                }
            }
        }

        return result;
    }

    private void dfs(int[][] heights, int r, int c, boolean[][] visited, int prevHeight) {
        int rows = heights.length;
        int cols = heights[0].length;

        if (r < 0 || r >= rows || c < 0 || c >= cols || visited[r][c] || heights[r][c] < prevHeight) {
            return;
        }
        visited[r][c] = true;
        dfs(heights, r + 1, c, visited, heights[r][c]);
        dfs(heights, r - 1, c, visited, heights[r][c]);
        dfs(heights, r, c + 1, visited, heights[r][c]);
        dfs(heights, r, c - 1, visited, heights[r][c]);
    }
}
```

## Explanation

### Problem Analysis
The problem asks for all cells from which water can reach both oceans, with flow allowed only from higher or equal height to lower or equal height. It is a favorite interview problem because the forward simulation from every cell looks expensive, but the right graph reversal makes the solution much cleaner.

### Approach
Instead of starting from every cell and trying to flow outward to each ocean, this code does the reverse. It starts DFS from the Pacific border and marks every cell that can be reached by moving to neighbors with height greater than or equal to the previous height; then it does the same from the Atlantic border.

A cell belongs in the answer only if it is reachable in both reverse searches. This avoids repeating work from each interior cell and turns the problem into two boundary-to-interior traversals.

### Pattern Used
Depth-First Search (DFS)

### Key Insight
Reverse the direction of water flow: if water can flow downhill from cell `A` to ocean `O`, then a DFS starting at `O` can reach `A` by only moving uphill or flat.

### Code Walkthrough
In `pacificAtlantic(int[][] heights)`:
- `result` stores the final coordinate pairs.
- `rows` and `cols` store the matrix dimensions.
- `pacific` and `atlantic` are boolean grids marking cells reachable from each ocean in the reversed traversal.

The first boundary loop:
- Iterates through each column `c`.
- Calls `dfs(heights, 0, c, pacific, heights[0][c])` for the top edge.
- Calls `dfs(heights, rows - 1, c, atlantic, heights[rows - 1][c])` for the bottom edge.

The second boundary loop:
- Iterates through each row `r`.
- Calls `dfs(heights, r, 0, pacific, heights[r][0])` for the left edge.
- Calls `dfs(heights, r, cols - 1, atlantic, heights[r][cols - 1])` for the right edge.

After both ocean traversals:
- The nested loops check every cell.
- If `pacific[r][c] && atlantic[r][c]`, that cell can reach both oceans.
- `result.add(Arrays.asList(r, c))` appends the coordinate pair.

In `dfs(int[][] heights, int r, int c, boolean[][] visited, int prevHeight)`:
- `rows` and `cols` are read from `heights`.
- The base case returns when the coordinates are out of bounds, the cell was already visited, or `heights[r][c] < prevHeight`.
- That last condition enforces the reverse-flow rule: from an ocean-side search, we may only move to equal or higher cells.
- If valid, `visited[r][c] = true` marks the cell.
- DFS then explores down, up, right, and left, passing `heights[r][c]` as the new `prevHeight`.

### Example Walkthrough
Use Example 1:
- `heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]`

Pacific DFS starts from the top row and left column:
- Cells like `(0,0)`, `(0,1)`, `(1,0)`, `(3,0)`, and `(4,0)` are immediately marked in `pacific` because they touch the Pacific.
- From those borders, DFS keeps moving only into cells whose height is not smaller than the previous one.

Atlantic DFS starts from the bottom row and right column:
- Cells like `(0,4)`, `(1,4)`, `(3,4)`, `(4,4)`, and `(4,0)` become candidates in `atlantic` through the same reverse rule.

Now check intersections:
- `(0,4)` is marked by both traversals, so it is added.
- `(1,3)` can be reached from the Pacific side through increasing heights and from the Atlantic side through the right edge, so it is added.
- `(1,4)`, `(2,2)`, `(3,0)`, `(3,1)`, and `(4,0)` are also true in both matrices.

The final `result` is:
- `[[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]`

### Key Variables Explained
- `result`: list of coordinates that can reach both oceans.
- `rows`, `cols`: grid dimensions.
- `pacific`: marks cells reachable from the Pacific border in reverse traversal.
- `atlantic`: marks cells reachable from the Atlantic border in reverse traversal.
- `visited`: whichever one of those two boolean grids the current DFS is filling.
- `prevHeight`: the previous cell height used to enforce nondecreasing movement in reverse.
- `r`, `c`: current row and column.

### Why This Works
For any cell, water can flow to an ocean by moving to equal or lower neighboring heights. Reversing that idea means an ocean-origin DFS can move from a cell to neighbors of equal or greater height and exactly capture all cells that could have drained into that ocean.

Because the code computes this reachability separately for the Pacific and Atlantic, the intersection `pacific[r][c] && atlantic[r][c]` is precisely the set of cells that can reach both oceans.

### Trick Used
Running the search backward from the ocean borders instead of forward from every cell.

### Edge Cases Handled
- Single-cell grid: the lone cell is reached from both ocean borders and is returned.
- Border cells: they are naturally included by the initial DFS calls from ocean edges.
- Repeated visits from multiple border starts: `visited[r][c]` prevents duplicate recursion.
- Downhill-only restriction: `heights[r][c] < prevHeight` blocks invalid reverse moves.

### Complexity Analysis
- Time Complexity: `O(m * n)` because each cell can be marked at most once in `pacific` and at most once in `atlantic`, and the final intersection scan is another full grid pass.
- Space Complexity: `O(m * n)` for the two boolean matrices, plus recursion stack space up to `O(m * n)` in the worst case.
