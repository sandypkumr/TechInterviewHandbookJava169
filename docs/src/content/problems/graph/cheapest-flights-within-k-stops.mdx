There are `n` cities connected by some number of flights. You are given an array `flights` where `flights[i] = [fromi, toi, pricei]` indicates that there is a flight from city `fromi` to city `toi` with cost `pricei`.

You are also given three integers `src`, `dst`, and `k`, return _**the cheapest price** from _`src`_ to _`dst`_ with at most _`k`_ stops. _If there is no such route, return_ _`-1`.

**Example 1:**

```
Input: n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1
Output: 700
Explanation:
The graph is shown above.
The optimal path with at most 1 stop from city 0 to 3 is marked in red and has cost 100 + 600 = 700.
Note that the path through cities [0,1,2,3] is cheaper but is invalid because it uses 2 stops.
```

**Example 2:**

```
Output: 200
Explanation:
The graph is shown above.
The optimal path with at most 1 stop from city 0 to 2 is marked in red and has cost 100 + 100 = 200.
```

**Example 3:**

```
Input: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 0
Output: 500
Explanation:
The graph is shown above.
The optimal path with no stops from city 0 to 2 is marked in red and has cost 500.
```

**Constraints:**

- `2 <= n <= 100`

- `0 <= flights.length <= (n * (n - 1) / 2)`

- `flights[i].length == 3`

- `0 <= fromi, toi < n`

- `fromi != toi`

- `1 <= pricei <= 10^4`

- There will not be any multiple flights between two cities.

- `0 <= src, dst, k < n`

- `src != dst`

**Patterns:** `dynamic-programming`

## Java Solution

```java
package graph;

public class CheapestFlightsWithinKStops {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        int[][] dp = new int[k + 2][n];
        for (int i = 0; i <= k + 1; i++) {
            for (int j = 0; j < n; j++) {
                dp[i][j] = Integer.MAX_VALUE;
            }
        }
        dp[0][src] = 0;

        for (int i = 1; i <= k + 1; i++) {
            dp[i][src] = 0;
            for (int[] flight : flights) {
                int u = flight[0];
                int v = flight[1];
                int w = flight[2];
                if (dp[i - 1][u] != Integer.MAX_VALUE) {
                    dp[i][v] = Math.min(dp[i][v], dp[i - 1][u] + w);
                }
            }
        }

        return dp[k + 1][dst] == Integer.MAX_VALUE ? -1 : dp[k + 1][dst];
    }
}
```

## Explanation

### Problem Analysis

This problem asks for the minimum cost path from `src` to `dst`, but only among routes that use at most `k` stops. That stop limit makes it different from a standard shortest-path problem, because the cheapest overall route may be invalid if it uses too many intermediate cities.

This is a common interview question because it tests whether you can model a path constraint correctly instead of reaching for plain Dijkstra or plain BFS automatically.

### Approach

The code uses dynamic programming in a Bellman-Ford style. Instead of storing one best cost per city overall, it stores the best cost per city after a limited number of flights.

In plain English:
- `dp[i][city]` means the cheapest cost to reach `city` using at most `i` flights.
- Since `k` stops means at most `k + 1` flights, the code builds rows `0` through `k + 1`.
- Each new row is computed only from the previous row, so one relaxation round adds at most one more flight.

This is chosen over brute force because enumerating every route up to `k` stops can explode combinatorially, while this approach systematically reuses previous best costs.

### Pattern Used

Dynamic Programming with Bellman-Ford style edge relaxation.

### Key Insight

The key idea is that the stop limit can be enforced by relaxing all flights exactly `k + 1` times and only extending paths from `dp[i - 1]`, never from the row currently being built.

### Code Walkthrough

The method starts by creating `int[][] dp = new int[k + 2][n]`.
- There are `k + 2` rows because row `0` represents using `0` flights, and row `k + 1` represents the maximum allowed number of flights.
- Every entry is initialized to `Integer.MAX_VALUE` to mean “currently unreachable.”

Then `dp[0][src] = 0` sets the base case.
- With zero flights taken, only the source city is reachable.

The outer loop `for (int i = 1; i <= k + 1; i++)` builds the answer one flight count at a time.
- `dp[i][src] = 0` keeps the source reachable with cost `0` in every row.

Inside that, the code scans every `flight`.
- `u = flight[0]` is the departure city.
- `v = flight[1]` is the arrival city.
- `w = flight[2]` is the ticket price.

The condition `if (dp[i - 1][u] != Integer.MAX_VALUE)` checks whether city `u` was reachable in the previous row.
- If it was, then taking one more flight from `u` to `v` gives a candidate cost `dp[i - 1][u] + w`.
- `dp[i][v] = Math.min(dp[i][v], dp[i - 1][u] + w)` keeps the cheapest such candidate.

Finally, `dp[k + 1][dst]` is inspected.
- If it is still `Integer.MAX_VALUE`, no valid route exists, so the method returns `-1`.
- Otherwise, it returns the stored minimum price.

### Example Walkthrough

Use Example 1:
- `n = 4`
- `flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]]`
- `src = 0`, `dst = 3`, `k = 1`

Since `k = 1`, the algorithm allows at most `2` flights, so it fills rows `0`, `1`, and `2`.

Start:
- `dp[0] = [0, INF, INF, INF]`

After `i = 1`:
- From city `0`, flight `0 -> 1` gives cost `100`
- No other flight can be used because their start cities are still unreachable in `dp[0]`
- `dp[1] = [0, 100, INF, INF]`

After `i = 2`:
- `0 -> 1` still gives `100`
- `1 -> 2` gives `200` because `dp[1][1] = 100`
- `1 -> 3` gives `700` because `100 + 600 = 700`
- `2 -> 3` cannot help yet because `dp[1][2]` is still `INF`
- `dp[2] = [0, 100, 200, 700]`

So `dp[k + 1][dst] = dp[2][3] = 700`, which matches the expected answer.

Notice why the cheaper route `0 -> 1 -> 2 -> 3` is rejected:
- It needs `3` flights, which means `2` stops.
- The code never builds a row for `3` flights, so that route is naturally excluded.

### Key Variables Explained

- `dp`: DP table where each row represents an allowed flight count and each column represents a city.
- `i`: current relaxation round, which corresponds to allowing up to `i` flights.
- `flight`: the current directed edge being considered.
- `u`, `v`, `w`: source city, destination city, and price of the current flight.
- `src`: starting city whose cost is always `0`.
- `dst`: destination city whose final DP entry is returned.
- `k`: stop limit, which determines that only `k + 1` flight layers are allowed.

### Why This Works

The invariant is: after finishing row `i`, `dp[i][city]` stores the cheapest cost to reach `city` using at most `i` flights.

That invariant holds because:
- The base row `dp[0]` is correct: only `src` is reachable with zero flights.
- To build row `i`, the code tries every possible last flight `u -> v` and combines it with the best valid way to reach `u` in row `i - 1`.
- Because it only reads from `dp[i - 1]`, it never accidentally uses more than one new flight in a single round.

By the time row `k + 1` is complete, every valid route with at most `k` stops has been considered, and the minimum cost among them is stored at `dp[k + 1][dst]`.

### Trick Used

The main trick is using a separate previous DP row concept (`dp[i - 1]`) while building `dp[i]`, which enforces the stop limit without needing path reconstruction or backtracking.

### Edge Cases Handled

- Unreachable destination: if `dp[k + 1][dst]` stays `Integer.MAX_VALUE`, the code returns `-1`.
- `k = 0`: only one flight is allowed, so only direct flights from `src` can contribute.
- Empty `flights`: no updates happen, so the method correctly returns `-1` unless `src == dst` (which the constraints rule out).
- Reusing the source across rows: `dp[i][src] = 0` keeps the base city valid in every layer.

### Complexity Analysis

- Time Complexity: `O((k + 2) * n + (k + 1) * flights.length)`.
  - Initializing the DP table takes `O((k + 2) * n)`.
  - The nested loops relax every flight for each `i` from `1` to `k + 1`, which takes `O((k + 1) * flights.length)`.
- Space Complexity: `O((k + 2) * n)` for the `dp` table.
