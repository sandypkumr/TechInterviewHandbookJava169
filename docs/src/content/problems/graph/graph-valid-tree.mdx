You are given a graph represented as an integer n (the number of nodes, labeled from 0 to n-1) and a list of edges
where each edge is a pair of nodes [u, v] that connects two nodes in the graph.

Write a function to determine if the graph is a valid tree.

A valid tree must satisfy the following conditions:

It is connected (there is a path between any two nodes).
It contains no cycles.


**Example 1:**

**Input: n = 5, edges = [[0,1],[0,2],[0,3],[1,4]]**

**Output: true**


**Example 2:**

**Input: n = 5, edges = [[0,1],[1,2],[2,3],[1,3],[1,4]]**

**Output: false**

**Patterns:** `union-find`

## Java Solution

```java
package graph;

/**
 * You are given a graph represented as an integer n (the number of nodes, labeled from 0 to n-1) and a list of edges
 * where each edge is a pair of nodes [u, v] that connects two nodes in the graph.
 *
 * Write a function to determine if the graph is a valid tree.
 *
 * A valid tree must satisfy the following conditions:
 *
 * It is connected (there is a path between any two nodes).
 * It contains no cycles.
 *
 * Example 1:
 * Input: n = 5, edges = [[0,1],[0,2],[0,3],[1,4]]
 * Output: true
 *
 * Example 2:
 * Input: n = 5, edges = [[0,1],[1,2],[2,3],[1,3],[1,4]]
 * Output: false
 */
public class GraphValidTree {
    public boolean validTree(int n, int[][] edges) {
        if (edges.length != n - 1) {
            return false;
        }

        int[] parent = new int[n];
        int[] rank = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
            rank[i] = 1;
        }

        for (int[] edge : edges) {
            if (!union(edge[0], edge[1], parent, rank)) {
                return false;
            }
        }

        return true;
    }

    private int find(int node, int[] parent) {
        if (parent[node] != node) {
            parent[node] = find(parent[node], parent);
        }
        return parent[node];
    }

    private boolean union(int u, int v, int[] parent, int[] rank) {
        int rootU = find(u, parent);
        int rootV = find(v, parent);

        if (rootU == rootV) {
            return false;
        }

        if (rank[rootU] > rank[rootV]) {
            parent[rootV] = rootU;
        } else if (rank[rootU] < rank[rootV]) {
            parent[rootU] = rootV;
        } else {
            parent[rootV] = rootU;
            rank[rootU]++;
        }

        return true;
    }
}
```

## Explanation

### Problem Analysis

This problem asks whether an undirected graph is a valid tree. A tree must satisfy two properties at the same time: it must be fully connected, and it must contain no cycle.

This is a classic interview question because it checks whether you know the structural rule that a tree with `n` nodes must have exactly `n - 1` edges, and whether you can combine that with efficient cycle detection.

### Approach

The code uses Union-Find (Disjoint Set Union).

The strategy is:
- First reject any graph whose edge count is not exactly `n - 1`.
- Then process each edge with `union`.
- If two endpoints already belong to the same component, adding that edge creates a cycle, so return `false`.
- If all unions succeed, the graph is a tree.

This is more efficient than repeatedly searching the graph from scratch after every edge.

### Pattern Used

Union-Find (Disjoint Set Union) with path compression and union by rank.

### Key Insight

Once `edges.length == n - 1` is enforced, detecting any cycle is enough to reject the graph, and if no cycle appears, connectivity is guaranteed automatically.

### Code Walkthrough

The method begins with:
- `if (edges.length != n - 1) { return false; }`

This is an important shortcut.
- Too few edges means the graph cannot be connected.
- Too many edges means the graph must contain a cycle.

Next, the code initializes two arrays of size `n`.
- `parent[i] = i` means every node starts as its own component root.
- `rank[i] = 1` stores a rough tree height or size indicator for balanced unions.

Then the loop `for (int[] edge : edges)` processes each undirected edge.
- `union(edge[0], edge[1], parent, rank)` attempts to merge the two endpoint components.
- If `union(...)` returns `false`, the endpoints were already connected, so the method returns `false` immediately.

The helper `find(int node, int[] parent)` locates the representative root.
- If `parent[node] != node`, the method recursively finds the top root.
- `parent[node] = find(parent[node], parent);` applies path compression so future finds are faster.

The helper `union(int u, int v, int[] parent, int[] rank)` does the merge.
- `rootU = find(u, parent)` and `rootV = find(v, parent)` locate both roots.
- If `rootU == rootV`, the two nodes are already in the same component, so adding this edge would form a cycle.

Otherwise, the code attaches the lower-rank root under the higher-rank root.
- If `rank[rootU] > rank[rootV]`, make `rootU` the parent.
- If `rank[rootU] < rank[rootV]`, make `rootV` the parent.
- If the ranks are equal, attach `rootV` under `rootU` and increment `rank[rootU]`.

If every edge is processed without failure, `validTree(...)` returns `true`.

### Example Walkthrough

Use Example 1:
- `n = 5`
- `edges = [[0,1],[0,2],[0,3],[1,4]]`

First check:
- `edges.length = 4`
- `n - 1 = 4`
- So the graph passes the edge-count requirement.

Initial state:
- `parent = [0,1,2,3,4]`
- `rank = [1,1,1,1,1]`

Process `[0,1]`:
- `find(0) = 0`, `find(1) = 1`
- Different roots, so union succeeds
- One root becomes parent of the other

Process `[0,2]`:
- `find(0)` returns the component root of `0`
- `find(2) = 2`
- Different roots, so union succeeds

Process `[0,3]`:
- Again, `3` is merged into the main component

Process `[1,4]`:
- `find(1)` compresses to the main root
- `find(4) = 4`
- Union succeeds

No union ever fails, so no cycle is found. Because the graph also has exactly `n - 1` edges, the method returns `true`.

Example 2 fails even earlier:
- `n = 5`, so a tree would need exactly `4` edges
- The input has `5` edges
- The method returns `false` immediately

### Key Variables Explained

- `parent`: parent-pointer array representing the current disjoint-set forest.
- `rank`: balancing information used to keep Union-Find trees shallow.
- `edge`: one undirected connection from the input.
- `rootU`, `rootV`: representatives of the two endpoint components inside `union(...)`.
- `find(...)`: returns the root representative, with path compression.
- `union(...)`: merges two components and reports whether that merge was valid.

### Why This Works

The solution relies on two tree facts:
- A valid tree on `n` nodes must have exactly `n - 1` edges.
- An undirected graph with `n - 1` edges is a tree if and only if it has no cycle.

The code enforces the first fact immediately with `edges.length != n - 1`.
Then `union(...)` enforces the second fact:
- If an edge connects two nodes already in the same component, a cycle exists.
- If every edge connects two different components, the graph stays acyclic.

Since the edge count is exactly `n - 1`, acyclicity implies connectivity here, so returning `true` is correct.

### Trick Used

The key trick is combining the `edges.length != n - 1` shortcut with Union-Find optimizations: path compression in `find(...)` and union by rank in `union(...)`.

### Edge Cases Handled

- Too few edges: rejected immediately by `edges.length != n - 1`.
- Too many edges: also rejected immediately by the same check.
- Cycle introduced during processing: `rootU == rootV` makes `union(...)` return `false`.
- Repeated finds on deep components: path compression keeps later operations efficient.

### Complexity Analysis

- Time Complexity: `O(n + edges.length * α(n))`.
  - Initializing `parent` and `rank` takes `O(n)`.
  - Each call to `union(...)` performs `find(...)` operations that are effectively amortized near-constant time because of path compression and union by rank.
- Space Complexity: `O(n)` for the `parent` and `rank` arrays.
