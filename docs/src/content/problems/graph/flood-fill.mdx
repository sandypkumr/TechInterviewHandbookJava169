You are given an image represented by an `m x n` grid of integers `image`, where `image[i][j]` represents the pixel value of the image. You are also given three integers `sr`, `sc`, and `color`. Your task is to perform a **flood fill** on the image starting from the pixel `image[sr][sc]`.

To perform a **flood fill**:

- Begin with the starting pixel and change its color to `color`.

- Perform the same process for each pixel that is **directly adjacent** (pixels that share a side with the original pixel, either horizontally or vertically) and shares the **same color** as the starting pixel.

- Keep **repeating** this process by checking neighboring pixels of the _updated_ pixels and modifying their color if it matches the original color of the starting pixel.

- The process **stops** when there are **no more** adjacent pixels of the original color to update.

Return the **modified** image after performing the flood fill.

**Example 1:**

**Input:** image = [[1,1,1],[1,1,0],[1,0,1]], sr = 1, sc = 1, color = 2

**Output:** [[2,2,2],[2,2,0],[2,0,1]]

**Explanation:**

From the center of the image with position `(sr, sc) = (1, 1)` (i.e., the red pixel), all pixels connected by a path of the same color as the starting pixel (i.e., the blue pixels) are colored with the new color.

Note the bottom corner is **not** colored 2, because it is not horizontally or vertically connected to the starting pixel.

**Example 2:**

**Input:** image = [[0,0,0],[0,0,0]], sr = 0, sc = 0, color = 0

**Output:** [[0,0,0],[0,0,0]]

**Explanation:**

The starting pixel is already colored with 0, which is the same as the target color. Therefore, no changes are made to the image.

**Constraints:**

- `m == image.length`

- `n == image[i].length`

- `1 <= m, n <= 50`

- `0 <= image[i][j], color < 2^16`

- `0 <= sr < m`

- `0 <= sc < n`

## Java Solution

```java
package graph;

public class FloodFill {
    public int[][] floodFill(int[][] image, int sr, int sc, int newColor) {
        int originalColor = image[sr][sc];
        if (originalColor == newColor) {
            return image;
        }
        fill(image, sr, sc, originalColor, newColor);
        return image;
    }

    private void fill(int[][] image, int r, int c, int originalColor, int newColor) {
        if (r < 0 || r >= image.length || c < 0 || c >= image[0].length || image[r][c] != originalColor) {
            return;
        }
        image[r][c] = newColor; // Change the color
        // Recursively fill in all four directions
        fill(image, r + 1, c, originalColor, newColor); // Down
        fill(image, r - 1, c, originalColor, newColor); // Up
        fill(image, r, c + 1, originalColor, newColor); // Right
        fill(image, r, c - 1, originalColor, newColor); // Left
    }
}
```

## Explanation

### Problem Analysis

This problem asks you to recolor the entire connected region that starts at `(sr, sc)` and shares the same original value as that starting pixel. The connection rule is strictly four-directional, so diagonal cells do not belong to the same region.

It is a standard interview problem because it tests whether you recognize a grid traversal as a graph traversal problem.

### Approach

The solution uses recursive DFS.

The idea is:
- Read the starting color into `originalColor`.
- If the starting pixel already has `newColor`, return immediately to avoid unnecessary recursion.
- Otherwise, recursively expand in four directions from `(sr, sc)`.
- Only continue recursion when a cell is inside bounds and still has `originalColor`.

This is better than scanning the whole grid blindly because it only explores the connected component that actually needs to change.

### Pattern Used

Depth-First Search (DFS) on a grid.

### Key Insight

Recoloring a cell as soon as it is visited doubles as the “visited” mark, so the code does not need a separate boolean matrix.

### Code Walkthrough

The public method `floodFill(int[][] image, int sr, int sc, int newColor)` starts by reading `int originalColor = image[sr][sc];`.

Then it checks `if (originalColor == newColor) { return image; }`.
- This is important because once a cell is recolored, the recursion uses color differences to stop revisiting.
- If the old and new colors are the same, recursion would be pointless.

Next, the code calls `fill(image, sr, sc, originalColor, newColor);` and finally returns the modified `image`.

The helper `fill(...)` does the real DFS.
- Its first `if` statement is the guard clause.
- It returns immediately when:
  - `r < 0` or `r >= image.length`
  - `c < 0` or `c >= image[0].length`
  - `image[r][c] != originalColor`

If the cell is valid and still has the target region's old color:
- `image[r][c] = newColor;` recolors it.

Then the method recursively explores four neighbors:
- `fill(image, r + 1, c, originalColor, newColor);` for down
- `fill(image, r - 1, c, originalColor, newColor);` for up
- `fill(image, r, c + 1, originalColor, newColor);` for right
- `fill(image, r, c - 1, originalColor, newColor);` for left

### Example Walkthrough

Use Example 1:
- `image = [[1,1,1],[1,1,0],[1,0,1]]`
- `sr = 1`, `sc = 1`, `color = 2`

Start:
- `originalColor = image[1][1] = 1`
- Since `originalColor != newColor`, DFS begins at `(1, 1)`

Visit `(1, 1)`:
- Change `image[1][1]` from `1` to `2`

Recursive expansion from `(1, 1)` reaches:
- `(2, 1)` -> value is `0`, so stop
- `(0, 1)` -> value is `1`, recolor to `2`
- `(1, 2)` -> value is `0`, so stop
- `(1, 0)` -> value is `1`, recolor to `2`

Continue from `(0, 1)`:
- `(0, 0)` becomes `2`
- `(0, 2)` becomes `2`

Continue from `(1, 0)`:
- `(2, 0)` becomes `2`

Cells that remain unchanged:
- `(1, 2)` is `0`
- `(2, 1)` is `0`
- `(2, 2)` is `1`

Final image:
- `[[2,2,2],[2,2,0],[2,0,1]]`

That matches the expected output, and the bottom-right `1` stays unchanged because it is not four-directionally connected to the starting cell.

### Key Variables Explained

- `image`: the input grid being modified in place.
- `sr`, `sc`: row and column of the starting pixel.
- `originalColor`: the color that defines the connected region to replace.
- `newColor`: the replacement color.
- `r`, `c`: the current cell coordinates inside the recursive helper.
- `fill(...)`: the DFS helper that expands through the connected component.

### Why This Works

The DFS visits exactly the cells that belong to the required region.

That is true because:
- The recursion only continues from cells whose value is still `originalColor`.
- Every visited valid cell is immediately changed to `newColor`, so it will not be processed again.
- The four recursive calls ensure every four-directionally connected neighbor is explored.

Therefore, all and only the reachable cells with the starting color are recolored.

### Trick Used

The trick is using the in-place assignment `image[r][c] = newColor` as both the update and the visited marker.

### Edge Cases Handled

- Starting color already equals `newColor`: the early return avoids unnecessary recursion and infinite revisits.
- Grid boundaries: the first condition in `fill(...)` stops recursion outside the image.
- Different-colored neighbors: `image[r][c] != originalColor` prevents unrelated cells from being recolored.

### Complexity Analysis

- Time Complexity: `O(m * n)` in the worst case.
  - If the whole image is one connected region of `originalColor`, every cell is visited once.
- Space Complexity: `O(m * n)` in the worst case due to recursion stack depth.
  - The code does not allocate a separate visited matrix.
  - In the worst-case snake-like or full-region traversal, recursive calls can stack up across many cells.
