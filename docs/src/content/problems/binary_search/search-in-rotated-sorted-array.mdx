There is an integer array `nums` sorted in ascending order (with **distinct** values).

Prior to being passed to your function, `nums` is **possibly left rotated** at an unknown index `k` (`1 <= k < nums.length`) such that the resulting array is `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]` (**0-indexed**). For example, `[0,1,2,4,5,6,7]` might be left rotated by `3` indices and become `[4,5,6,7,0,1,2]`.

Given the array `nums` **after** the possible rotation and an integer `target`, return _the index of _`target`_ if it is in _`nums`_, or _`-1`_ if it is not in _`nums`.

You must write an algorithm with `O(log n)` runtime complexity.

**Example 1:**

```
Input: nums = [4,5,6,7,0,1,2], target = 0
Output: 4
```

**Example 2:**

```
Input: nums = [4,5,6,7,0,1,2], target = 3
Output: -1
```

**Example 3:**

```
Input: nums = [1], target = 0
Output: -1
```

**Constraints:**

- `1 <= nums.length <= 5000`
- `-10^4 <= nums[i] <= 10^4`
- All values of `nums` are **unique**.
- `nums` is an ascending array that is possibly rotated.
- `-10^4 <= target <= 10^4`

**Patterns:** `binary-search`

## Java Solution

```java
package binary_search;

public class SearchInRotatedSortedArray {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid; // Target found
            }

            // Determine which side is sorted
            if (nums[left] <= nums[mid]) { // Left side is sorted
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1; // Search in the left half
                } else {
                    left = mid + 1; // Search in the right half
                }
            } else { // Right side is sorted
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1; // Search in the right half
                } else {
                    right = mid - 1; // Search in the left half
                }
            }
        }

        return -1; // Target not found
    }
}
```

## Explanation

### Problem Analysis

The array started out sorted, but rotation breaks the global order.

That means a normal binary search cannot simply compare `target` with `nums[mid]` and always know which side to discard.

The important detail is that the array still comes from one sorted sequence with distinct values. So in any current search range, at least one half is guaranteed to still be sorted.

That is the property this solution uses to preserve `O(log n)` time.

### Approach

The code performs a **modified binary search**.

On each iteration:

1. Compute `mid`.
2. If `nums[mid]` is the target, return `mid`.
3. Figure out which half is sorted.
4. Check whether the target falls inside that sorted half.
5. Keep that half if it can contain the target; otherwise search the other half.

So the method still discards about half of the remaining range every time.

### Pattern Used

This solution uses **modified binary search on a rotated sorted array**.

It does not first find the pivot, and it does not use any extra data structure. The binary search itself handles the rotation.

### Key Insight

For every search window `[left, right]`, one of these halves must be sorted:

- `nums[left...mid]`
- `nums[mid...right]`

The code checks `nums[left] <= nums[mid]` to decide whether the left half is sorted.

- If that condition is true, the left half is sorted.
- Otherwise, the right half must be sorted.

Once the sorted half is known, the code can safely test whether `target` is inside its value range.

### Code Walkthrough

```java
public int search(int[] nums, int target) {
    int left = 0;
    int right = nums.length - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) {
            return mid;
        }

        if (nums[left] <= nums[mid]) {
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return -1;
}
```

How the method works:

1. `left` starts at `0` and `right` starts at `nums.length - 1`.
2. The loop runs while there is still a valid search range: `left <= right`.
3. `mid = left + (right - left) / 2` finds the middle safely.
4. If `nums[mid] == target`, the answer is found immediately.
5. `nums[left] <= nums[mid]` means the left half is sorted.
6. In that case, `nums[left] <= target && target < nums[mid]` checks whether the target belongs in the left half.
   - If yes, move `right` to `mid - 1`.
   - If no, move `left` to `mid + 1`.
7. Otherwise, the right half is sorted.
8. Then `nums[mid] < target && target <= nums[right]` checks whether the target belongs in the right half.
   - If yes, move `left` to `mid + 1`.
   - If no, move `right` to `mid - 1`.
9. If the loop finishes, the target is not present, so return `-1`.

### Example Walkthrough

For `nums = [4,5,6,7,0,1,2]` and `target = 0`:

| `left` | `mid` | `right` | `nums[left]` | `nums[mid]` | `nums[right]` | Decision |
|-------:|------:|--------:|-------------:|------------:|--------------:|----------|
| 0 | 3 | 6 | 4 | 7 | 2 | Left half is sorted. `0` is not in `[4, 7)`, so move `left` to `4`. |
| 4 | 5 | 6 | 0 | 1 | 2 | Left half is sorted. `0` is in `[0, 1)`, so move `right` to `4`. |
| 4 | 4 | 4 | 0 | 0 | 0 | `nums[mid] == target`, so return `4`. |

This walkthrough matches the exact comparisons used in the code.

### Key Variables Explained

- **`left`**: the start index of the current search range.
- **`right`**: the end index of the current search range.
- **`mid`**: the middle index used to split the current range.
- **`nums[left]`**: helps detect whether the left half is sorted.
- **`nums[mid]`**: used both for the direct equality check and for deciding which half can be discarded.
- **`nums[right]`**: used when the code reasons about the right sorted half.
- **`target`**: the value we want to find.

### Why This Works

The algorithm maintains this invariant:

- if the target exists, it must lie somewhere inside `[left, right]`

On each step, the code identifies one sorted half. Because that half is sorted, its boundary values are enough to tell whether the target can be inside it.

- If the target falls within that sorted half's range, the algorithm keeps that half.
- Otherwise, it discards that half and searches the other side.

So the code never throws away a region that could still contain the answer.

Since one half is eliminated every iteration, the range shrinks logarithmically until the target is found or the interval becomes empty.

### Trick Used

There is no extra trick beyond the main rotated-array observation.

The useful idea is that the code does **not** separately locate the pivot. Instead, it decides which half is sorted during each binary-search step and uses that information immediately.

That keeps the solution short and directly aligned with the required `O(log n)` runtime.

### Edge Cases Handled

1. **Single-element array** like `[1]`
   - the loop runs once
   - it returns `0` if the element matches `target`, otherwise `-1`

2. **Array not rotated** like `[1,2,3,4,5]`
   - the left half is repeatedly recognized as sorted
   - the logic still behaves like regular binary search

3. **Target not present** like `[4,5,6,7,0,1,2]`, `target = 3`
   - the search range keeps shrinking
   - the method eventually returns `-1`

4. **Target near the rotation point** like `[4,5,6,7,0,1,2]`, `target = 0`
   - no special pivot handling is needed
   - the sorted-half checks still guide the search correctly

5. **Rotation near the beginning or end** like `[5,1,2,3,4]` or `[2,3,4,5,1]`
   - one half is still sorted on every iteration
   - the same comparisons continue to work

### Complexity Analysis

- **Time Complexity: `O(log n)`** — each loop iteration discards half of the remaining search interval.
- **Space Complexity: `O(1)`** — the implementation uses only a few index variables and no extra data structures.
