Given an array of integers `nums` which is sorted in ascending order, and an integer `target`, write a function to search `target` in `nums`. If `target` exists, then return its index. Otherwise, return `-1`.

You must write an algorithm with `O(log n)` runtime complexity.

**Example 1:**

```
Input: nums = [-1,0,3,5,9,12], target = 9
Output: 4
Explanation: 9 exists in nums and its index is 4
```

**Example 2:**

```
Input: nums = [-1,0,3,5,9,12], target = 2
Output: -1
Explanation: 2 does not exist in nums so return -1
```

**Constraints:**

- `1 <= nums.length <= 10^4`

- `-10^4 < nums[i], target < 10^4`

- All the integers in `nums` are **unique**.

- `nums` is sorted in ascending order.

**Patterns:** `sliding-window`, `binary-search`

## Java Solution

```java
package binary_search;

public class BinarySearch {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid; // Target found
            } else if (nums[mid] < target) {
                left = mid + 1; // Search in the right half
            } else {
                right = mid - 1; // Search in the left half
            }
        }

        return -1; // Target not found
    }
}
```

## Explanation

### Problem Analysis

The input array `nums` is already sorted in ascending order, and we must return the index of `target` or `-1` if it is absent.  
Because the array is sorted, comparing `target` with a middle element tells us which half can be discarded.  
This is one of the most common interview problems because it checks whether you can exploit sorted order to beat linear search.

### Approach

The method keeps a search window between `left` and `right`.  
On each iteration, it computes `mid`, compares `nums[mid]` with `target`, and throws away the half that cannot contain the answer.

Why this approach?

- A linear scan would be simple but takes `O(n)` time.
- The sorted property lets us shrink the candidate range by half every step.
- That gives the required `O(log n)` runtime.

### Pattern Used

Binary Search.

### Key Insight

Once `nums[mid]` is known, the sorted order guarantees that either the entire left half or the entire right half is impossible and can be discarded immediately.

### Code Walkthrough

The method begins with:

- `int left = 0;`
- `int right = nums.length - 1;`

These pointers represent the current inclusive search range.

The main loop is:

- `while (left <= right)`

As long as the range is valid, we keep searching.

Inside the loop:

- `int mid = left + (right - left) / 2;`
- This avoids overflow and picks the middle index of the current range.

Then the code checks three cases:

- If `nums[mid] == target`, it immediately returns `mid`.
- If `nums[mid] < target`, the target can only be to the right, so `left = mid + 1`.
- Otherwise, the target must be to the left, so `right = mid - 1`.

If the loop finishes without returning:

- `return -1;`
- That means the search range became empty and `target` was never found.

### Example Walkthrough

Use **Example 1**: `nums = [-1,0,3,5,9,12]`, `target = 9`.

Initial state:

- `left = 0`, `right = 5`

First iteration:

- `mid = 0 + (5 - 0) / 2 = 2`
- `nums[mid] = 3`
- Since `3 < 9`, move rightward: `left = 3`

Second iteration:

- `left = 3`, `right = 5`
- `mid = 3 + (5 - 3) / 2 = 4`
- `nums[mid] = 9`
- Match found, so return `4`

That matches the expected output.

### Key Variables Explained

- `nums`: the sorted input array.
- `target`: value we are searching for.
- `left`: left boundary of the current search interval.
- `right`: right boundary of the current search interval.
- `mid`: middle index used to decide which half to keep.

### Why This Works

The loop maintains the invariant that if `target` exists, it must lie within the inclusive range `[left, right]`.  
Each comparison removes only values that are provably too small or too large because `nums` is sorted.  
When `nums[mid] < target`, everything at or left of `mid` is too small; when `nums[mid] > target`, everything at or right of `mid` is too large.  
So the algorithm never discards the true answer, and if the range becomes empty, the target is not present.

### Trick Used

Overflow-safe midpoint calculation: `left + (right - left) / 2`.

### Edge Cases Handled

- Single-element array: the loop still checks index `0` correctly.
- Target smaller than all values: repeated `right = mid - 1` eventually empties the range.
- Target larger than all values: repeated `left = mid + 1` eventually empties the range.
- Target absent between existing values: the loop ends naturally and returns `-1`.

### Complexity Analysis

- **Time Complexity: `O(log n)`** — each loop iteration cuts the remaining search interval roughly in half.
- **Space Complexity: `O(1)`** — only `left`, `right`, and `mid` are used in addition to the input.
