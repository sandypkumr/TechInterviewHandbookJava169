Suppose an array of length `n` sorted in ascending order is **rotated** between `1` and `n` times. For example, the array `nums = [0,1,2,4,5,6,7]` might become:

- `[4,5,6,7,0,1,2]` if it was rotated `4` times.

- `[0,1,2,4,5,6,7]` if it was rotated `7` times.

Notice that **rotating** an array `[a[0], a[1], a[2], ..., a[n-1]]` 1 time results in the array `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`.

Given the sorted rotated array `nums` of **unique** elements, return _the minimum element of this array_.

You must write an algorithm that runs in `O(log n) time`.

**Example 1:**

```
Input: nums = [3,4,5,1,2]
Output: 1
Explanation: The original array was [1,2,3,4,5] rotated 3 times.
```

**Example 2:**

```
Input: nums = [4,5,6,7,0,1,2]
Output: 0
Explanation: The original array was [0,1,2,4,5,6,7] and it was rotated 4 times.
```

**Example 3:**

```
Input: nums = [11,13,15,17]
Output: 11
Explanation: The original array was [11,13,15,17] and it was rotated 4 times.
```

**Constraints:**

- `n == nums.length`

- `1 <= n <= 5000`

- `-5000 <= nums[i] <= 5000`

- All the integers of `nums` are **unique**.

- `nums` is sorted and rotated between `1` and `n` times.

**Patterns:** `sliding-window`

## Java Solution

```java
package binary_search;

public class FindMinimumInRotatedSortedArray {
    public int findMin(int[] nums) {
        int left = 0;
        int right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            // Decide which half to continue searching
            if (nums[mid] < nums[right]) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }

        return nums[left]; // The minimum element
    }
}
```

## Explanation

### Problem Analysis

The array was originally sorted, then rotated, so it now contains two sorted segments with the minimum element at the rotation point.  
We need to return that minimum in `O(log n)` time, which rules out a simple linear scan.  
This is a standard interview variation of binary search because the array is not fully sorted, but it still has enough structure to discard half the search space each step.

### Approach

The code compares `nums[mid]` with `nums[right]` to determine which side contains the minimum.  
If `nums[mid] < nums[right]`, then the right half is sorted and the minimum is at `mid` or to its left.  
Otherwise, the rotation point must be to the right of `mid`, so we move `left` forward.

Why this approach?

- A linear scan would find the minimum in `O(n)`.
- The rotated sorted structure lets us identify the unsorted side, which is where the minimum lives.
- That preserves the required `O(log n)` runtime.

### Pattern Used

Binary Search.

### Key Insight

In a rotated sorted array of unique values, the minimum always lies in the half that breaks sorted order, and `nums[mid]` versus `nums[right]` tells us which half that is.

### Code Walkthrough

The method starts with:

- `int left = 0;`
- `int right = nums.length - 1;`

These pointers bound the current search interval for the minimum.

The loop condition is:

- `while (left < right)`

We stop when both pointers converge on the minimum index.

Inside the loop:

- `int mid = left + (right - left) / 2;`

Then the code checks:

- If `nums[mid] < nums[right]`, the segment from `mid` to `right` is sorted, so the minimum cannot be to the right of `mid`. The code sets `right = mid`.
- Otherwise, `nums[mid]` is in the left rotated portion, so the minimum must be strictly after `mid`. The code sets `left = mid + 1`.

At the end:

- `return nums[left];`

Since `left == right`, that index is the minimum element.

### Example Walkthrough

Use **Example 1**: `nums = [3,4,5,1,2]`.

Initial state:

- `left = 0`, `right = 4`

First iteration:

- `mid = 0 + (4 - 0) / 2 = 2`
- `nums[mid] = 5`, `nums[right] = 2`
- `5 < 2` is false, so set `left = mid + 1 = 3`

Second iteration:

- `left = 3`, `right = 4`
- `mid = 3 + (4 - 3) / 2 = 3`
- `nums[mid] = 1`, `nums[right] = 2`
- `1 < 2` is true, so set `right = mid = 3`

Now:

- `left = 3`, `right = 3`

Loop stops, and `nums[left] = nums[3] = 1`, which is the answer.

### Key Variables Explained

- `nums`: rotated sorted input array.
- `left`: left boundary of the current candidate range for the minimum.
- `right`: right boundary of the current candidate range.
- `mid`: middle index used to inspect which side is properly sorted.

### Why This Works

The algorithm maintains the invariant that the minimum element always lies within `[left, right]`.  
When `nums[mid] < nums[right]`, the right side is sorted in increasing order, so its smallest element is `nums[mid]`; the true minimum cannot be beyond `mid`, so keeping `[left, mid]` is safe.  
When that condition is false, the rotation point lies to the right of `mid`, so the minimum must be in `[mid + 1, right]`.  
Each update keeps the minimum inside the search range until only one index remains.

### Trick Used

Using `nums[right]` as the comparison anchor to detect whether `mid` is in the sorted right portion or the rotated left portion.

### Edge Cases Handled

- Already sorted array like `[11,13,15,17]`: the `nums[mid] < nums[right]` branch keeps shrinking toward index `0`.
- Array of length `1`: `left` and `right` start equal, so the loop never runs and the only element is returned.
- Rotation near the ends: the pointer updates still converge correctly because the minimum stays inside `[left, right]`.

### Complexity Analysis

- **Time Complexity: `O(log n)`** — each iteration halves the candidate interval by moving either `left` or `right`.
- **Space Complexity: `O(1)`** — only a few integer pointers are used.
