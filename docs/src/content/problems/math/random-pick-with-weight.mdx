You are given a **0-indexed** array of positive integers `w` where `w[i]` describes the **weight** of the `i^th` index.

You need to implement the function `pickIndex()`, which **randomly** picks an index in the range `[0, w.length - 1]` (**inclusive**) and returns it. The **probability** of picking an index `i` is `w[i] / sum(w)`.

- For example, if `w = [1, 3]`, the probability of picking index `0` is `1 / (1 + 3) = 0.25` (i.e., `25%`), and the probability of picking index `1` is `3 / (1 + 3) = 0.75` (i.e., `75%`).

**Example 1:**

```
Input
["Solution","pickIndex"]
[[[1]],[]]
Output
[null,0]

Explanation
Solution solution = new Solution([1]);
solution.pickIndex(); // return 0. The only option is to return 0 since there is only one element in w.
```

**Example 2:**

```
Input
["Solution","pickIndex","pickIndex","pickIndex","pickIndex","pickIndex"]
[[[1,3]],[],[],[],[],[]]
Output
[null,1,1,1,1,0]

Explanation
Solution solution = new Solution([1, 3]);
solution.pickIndex(); // return 1. It is returning the second element (index = 1) that has a probability of 3/4.
solution.pickIndex(); // return 1
solution.pickIndex(); // return 1
solution.pickIndex(); // return 1
solution.pickIndex(); // return 0. It is returning the first element (index = 0) that has a probability of 1/4.

Since this is a randomization problem, multiple answers are allowed.
All of the following outputs can be considered correct:
[null,1,1,1,1,0]
[null,1,1,1,1,1]
[null,1,1,1,0,0]
[null,1,1,1,0,1]
[null,1,0,1,0,0]
......
and so on.
```

**Constraints:**

- `1 <= w.length <= 10^4`

- `1 <= w[i] <= 10^5`

- `pickIndex` will be called at most `10^4` times.

**Patterns:** `sliding-window`, `prefix-sum`

## Java Solution

```java
package math;

import java.util.Random;

public class RandomPickWithWeight {
    private int[] prefix;
    private int total;
    private Random rand;

    public RandomPickWithWeight(int[] w) {
        prefix = new int[w.length];
        rand = new Random();

        prefix[0] = w[0];
        for (int i = 1; i < w.length; i++) {
            prefix[i] = prefix[i - 1] + w[i];
        }
        total = prefix[w.length - 1];
    }

    public int pickIndex() {
        int target = rand.nextInt(total) + 1;

        int left = 0, right = prefix.length - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (target <= prefix[mid]) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return left;
    }
}
```

## Explanation

### Problem Analysis
This problem asks for weighted random sampling: index `i` must be returned with probability `w[i] / sum(w)`. The challenge is not just generating randomness, but mapping each index to exactly the right portion of the total probability space.

It is a common interview question because it combines preprocessing, probability intuition, prefix sums, and binary search into one clean design.

### Approach
The constructor converts the weight array into a prefix-sum array. After that transformation, each index owns a continuous numeric interval inside `1` to `total`.

Then `pickIndex()` generates one random integer in that range and uses binary search to find the first prefix value that is greater than or equal to it. That index is exactly the weighted answer.

### Pattern Used
Prefix Sum + Binary Search.

### Key Insight
If `prefix[i]` stores the cumulative weight up to index `i`, then picking a random number in `[1, total]` and locating its first covering prefix automatically gives the correct weighted probability.

### Code Walkthrough
The class stores three fields:
- `prefix` for cumulative weights
- `total` for the sum of all weights
- `rand` for random number generation

Inside `RandomPickWithWeight(int[] w)`, the code creates `prefix = new int[w.length];` and initializes `rand = new Random();`.

It sets `prefix[0] = w[0];`, then fills the rest with:
- `prefix[i] = prefix[i - 1] + w[i];`

So if `w = [1, 3, 2]`, `prefix` becomes `[1, 4, 6]`. Finally, `total = prefix[w.length - 1];` stores the full weight sum.

In `pickIndex()`, `int target = rand.nextInt(total) + 1;` generates a random integer from `1` through `total`. The `+ 1` matters because the intervals are treated as 1-based inclusive ranges.

The binary search uses `left = 0` and `right = prefix.length - 1`. While `left < right`:
- `mid` is computed safely as `left + (right - left) / 2`
- if `target <= prefix[mid]`, the answer is at `mid` or earlier, so `right = mid`
- otherwise the answer must be later, so `left = mid + 1`

When the loop ends, `left` is the first index whose prefix sum covers `target`, and that index is returned.

### Example Walkthrough
For **Example 1**, `w = [1]`:
- The constructor builds `prefix = [1]` and `total = 1`
- `pickIndex()` computes `target = rand.nextInt(1) + 1`, so `target` is always `1`
- Binary search starts and ends at index `0`
- The method always returns `0`, matching the example

For **Example 2**, `w = [1, 3]`:
- The constructor builds `prefix = [1, 4]` and `total = 4`
- That means index `0` owns target `1`, and index `1` owns targets `2`, `3`, and `4`
- If `target = 1`, binary search returns `0`
- If `target = 2`, `3`, or `4`, binary search returns `1`
- So index `1` is chosen three times as often as index `0`, which matches the required `1/4` vs `3/4` probability split shown in the example

### Key Variables Explained
- `prefix`: cumulative weight array; each position marks the end of that index's interval.
- `total`: total weight sum and the upper bound for random target generation.
- `rand`: Java's random number generator.
- `target`: the randomly selected position inside the weighted range.
- `left`, `right`, `mid`: binary search pointers used to locate the correct interval.

### Why This Works
Each index `i` corresponds to exactly `w[i]` integer targets inside the range `1...total`. Because `target` is chosen uniformly from that full range, the chance of landing inside index `i`'s interval is exactly `w[i] / total`.

The binary search is correct because `prefix` is sorted in increasing order, so the first prefix sum that reaches `target` uniquely identifies the interval containing it.

### Trick Used
The main trick is turning weights into prefix intervals and using a 1-based `target = rand.nextInt(total) + 1` so boundary cases map cleanly to the first valid prefix.

### Edge Cases Handled
- **Single-element input**: `prefix.length` is `1`, so `pickIndex()` immediately returns `0`.
- **Boundary targets**: when `target` is exactly equal to some `prefix[mid]`, the `<=` check keeps that index as a valid answer.
- **Large differences in weights**: cumulative sums still preserve the correct interval sizes for each index.

### Complexity Analysis
- **Time Complexity: `O(n)` to build, `O(log n)` per `pickIndex()`** — the constructor fills `prefix` once, and each call to `pickIndex()` performs binary search over `prefix`.
- **Space Complexity: `O(n)`** — the `prefix` array stores one cumulative value per input weight.
